### 참고(고치지 않아도 됨)
1. 안전 안내에 교과서·실험관찰의 "실험이 끝나면 사용한 물질은 선생님의 안내에 따라 정해진 곳에 버립니다"가 없다(`lesson-config.js:46`). 시뮬레이션이라 빠져도 되지만 한 구절 덧붙일 수 있다.
2. 실험관찰 22쪽 "실험하기 전: 밀가루, 탄산수소 나트륨, 식초의 특징을 각각 관찰해 봅니다"는 앱에 없다. 기록 칸이 없는 활동이라 7분 예산상 빼도 무방.
3. 관찰 카드의 '본 모습' 글(예: "고무풍선이 조금씩 커지면서 둥글게 부풀고 있어요.")이 보기 중 하나와 거의 같은 뜻이라 보기 고르기가 쉽다. 개정 1("값은 화면에 바로 보이고 기록하기로 저장")과 색만으로 전달하지 않기 원칙에 맞는 설계라 그대로 둬도 된다.
4. 탄산수소 나트륨 · 삼각 플라스크 안 보기에 "밀가루가 가라앉는다"가 함께 나온다(보기 목록이 살펴볼 것 기준). 실험관찰 문구를 그대로 쓰기 위한 것이라 문제는 아니다.
5. 새로고침하면 기록·장면(섞은 상태)은 복원되지만 고른 조건(가루·살펴볼 것)은 비어 있다. 다시 고르면 "👀 살펴보기"로 이어진다. 공통 틀 동작.
6. 4칸을 다 기록한 직후의 알림("모든 실험을 기록했어요!")이 바로 '다음 단계'를 누르면 분석 화면(375px)에서 몇 초간 분석 2 문항 위를 가린다. 저절로 사라진다.

## 확인한 것 vs 못 한 것

### 확인한 것
환경: 자기 전용 headless Chrome(CDP 포트 9461, 스크래치 프로필, 뷰포트마다 새 프로필), 자기 정적 서버(127.0.0.1:8761, `public/` 제공, 404 없음). 공유 브라우저·다른 탭·개발 서버 설정은 건드리지 않았다. 가짜 로그인 세션 + 페이지 안 가짜 fetch로 Supabase 요청을 메모리에서 응답했고 `*.supabase.co`는 `--host-resolver-rules`로 막아 **실 DB 요청 0건**. `localStorage.clear()` 쓰지 않음. 끝나고 서버·Chrome 모두 종료.
* **전체 흐름 끝까지(예상 → 4칸 → 분석 2문항 → 결론 → 마치기)** 6가지: 1024×768 3D, 768×1024 3D, 768×1024 3D 다크, 375×812 3D 다크(모바일·터치 에뮬), 1024×768 2D, 375×812 2D 다크. 모두 가로 스크롤 0, **콘솔 오류·경고·예외 0**.
* 기록 값·분석 표·`detail.records`·`detail.qa` 표가 앱 config 문구와 글자까지 같음(위 정확성 표).
* 완료 payload(`app_results`): `completed: true`, `duration_seconds`, `details`에 predict·hintsOpened·records·analysis(tries 포함)·conclusion·curiosity·**`qa` 6항목**(predict/q1 text, experiment/records table, analyze/q1·q2 choice, conclude/conclusion text+submitted, curiosity text). 궁금한 점을 비워도 마쳐짐.
* 규칙: 예상 질문 1개(10글자 미만이면 실험하기로 못 넘어감, 알림 확인), 힌트 3개 순서대로 열림, 분석 보기 고르기 2개(오답 → spec 피드백, 정답 피드백 겹침 없음), 발전 질문 없음, 결론 제출 뒤에만 모범 답안, 4칸 미만이면 분석으로 못 넘어감(“지금 1/4칸” 알림). 값 타이핑 없음(보기 고르기 → 확인하기 → 기록하기). 수치 측정 없는 관찰형이라 반올림·소수 규칙은 해당 없음.
* 관찰 오답: "🔍 방금 본 모습과 다른 것 같아요…" + 기록하기 꺼짐 + "🔁 다시 섞어 보기" 버튼.
* 실행 방식: 처음 섞기 "▶ 고무풍선을 세워 섞기", 같은 가루의 다른 칸 "👀 … 살펴보기"(+ "이미 섞었어요" 안내), 같은 칸 "🔁 다시 섞어 보기", 기록 뒤 같은 가루의 남은 칸 자동 선택, "🧽 실험대 처음처럼 되돌리기" 뒤 다시 "▶ 섞기"로 돌아옴.
* 새로고침 복원: 실험 단계·기록 1/4·예상 글·섞은 장면 복원.
* 앞 단계 이동(실험 → 예상 → 실험), 3D↔2D 6번 전환: 캔버스 0↔1개, 3D 안내 오버레이 0↔1개, 2D 틀 1↔0개(쌓이지 않음 = WebGL 해제).
* 3D 마우스 드래그: 페이지 스크롤·조건 선택이 바뀌지 않음. 조작 버튼은 `<button>`+`aria-pressed`, 2D 플라스크 버튼 `aria-label`·`aria-pressed`, 관찰 보기 `role=group`.
* 로그인 없음: "🔒 로그인이 필요해요" 가림막만 보임(스크린숏), `sci6…` 키 0개. 다른 문서에서 세션 키 삭제(로그아웃 흉내) → 이 앱의 `sci6…` 키 9개 → 0개로 삭제됨.
* 저장 키 `sci622sim1:v1`, `app_progress` GET/POST/PATCH 요청 발생.
* 학생 입력 `<b>굵게</b>` → 글자 그대로 표시(`<b>` 요소 0개). 앱 코드에 `innerHTML` 없음(공통 틀도 없음).
* 색만으로 정보 전달 안 함: 3D 이름표(밀가루/탄산수소 나트륨/식초), 분석 표 아이콘+글자, 관찰 카드 글.
* 공통 틀 사본: `diff -r scripts/templates/science-sim public/apps/sci-6-2-2-1/science-sim` 차이 없음, `class1-record.js` 정본과 같음, `config.js` 본보기(6-2-1-2)와 같음(anon key만).
* three.js·supabase-js CDN은 본보기와 같은 URL+SRI.

### 못 한 것
* 실제 iPad·휴대폰 터치(3D 한 손가락 드래그·두 손가락 확대, 버튼 누름 느낌), 실제 GPU 성능(헤드리스는 소프트웨어 렌더링). 키보드만으로 끝까지 진행은 따로 해 보지 않았다(모두 `<button>`/`<input>`이라 가능할 것으로 봄).
* 실제 로그인·실제 `app_progress`/`app_results` 저장(RLS), 두 학생 계정 전환, 블로그에서의 실제 로그아웃.
* "↺ 처음부터 다시 하기"(공통 틀 기능, 누르지 않음), `prefers-reduced-motion` 환경.
* 관리자 "학생 응답" 화면 표시(`src/data/app-responses/` 매핑은 Embed 단계).
* 실제 학생 소요 시간(위 표는 추정).
