## 2. 동작 요약

* **예상하기**: 탐구형 질문 1개(최소 10자, 직접 타이핑) + 힌트 3개(한 단계씩, 답을 말하지 않음).
* **실험하기**: 달 바(실험관찰 순서 3월 → 2월, 계절별 3달씩 묶고 계절 이름·아이콘·색을 함께 표시)에서 달을 누르면
  그 달 21일 태양의 하루 길을 **약 2초 빨리 감기(모형)**로 보여 준다(배지 "⏩ 빨리 감기(모형) · ○월 21일 하루(낮 ○시간 ○분)를 약 2초로").
  태양이 남중하면 남중 고도가, 해가 지면 낮의 길이가 값 패널과 하늘 모형 위 작은 표에 나타나고 → **📝 기록하기**(타이핑 없음). 12칸 모두 기록해야 다음 단계.
  기록한 달의 길은 흐린 선 + "○월" 이름표로 남는다(**👣 지난 경로: 보임/숨김** 토글). 언제든 다시 누르거나 다시 기록할 수 있다.
  3D: 투명 하늘 반구, 지평선(해가 떠 있는 동안 노랗게 빛남), 고도 30°·60° 보조선, 동서남북, 가운데 태양 고도 측정기(받침판+막대기, 그림자 = 막대 ÷ tan 고도),
  남중 순간에 정남쪽 자오선 위 "남중 고도 ○○.○°" 각 표시. 드래그 회전·두 손가락 확대, 더블탭 처음 방향.
  2D(`?no3d=1`·WebGL 없음·3D 실패): 남쪽 하늘을 바라본 그림(가로 = 방위 북동~북서, 세로 = 고도 0~90°)에 같은 식으로 그린 길.
* **기록·분석하기**: 12행 표(계절·월·남중 고도(°)·낮의 길이) + 꺾은선그래프 2개(남중 고도 0~90°, 낮의 길이 8~16시간; 계절 띠에 이름 표기) +
  오개념 안내 "달이 바뀔 때 갑자기 바뀌지 않고 날마다 조금씩 계속 달라져요"(137쪽), 지역 차이 안내(137쪽 길잡이 5) + 보기 고르기 2개.
* **정리하기**: 결론 1개 → 제출 후 모범 답안(137쪽) 비교, 궁금한 점 한 줄(선택), 학습 마치기.
* 로그인 필수·진행 저장(`app_progress`)·로그아웃 삭제·완료 저장(`app_results`, `detail.qa`)은 공통 틀(`SciSim.createStore`/`Lesson`) 그대로.

### 과학 모형
* 태양의 길 = 서울(위도 37.57°, 화면에는 쓰지 않음)에서 본 적위가 일정한 하루 길. 적위는 표의 남중 고도에서 거꾸로 구해(δ = 고도 − (90° − φ)),
  **그린 길의 가장 높은 곳 = 표의 남중 고도**(정확히 일치, 3월은 정동에서 떠서 정서로 짐). 뜨고 지는 지점도 같은 식에서 나오므로 낮이 긴 달일수록 길이 넓고 길다.
* 그린 길의 뜨고 지는 시각 폭은 기하 계산이라 표의 낮의 길이(대기 굴절 등 포함)와 몇 분 다를 수 있다 → 화면의 수치는 모두 표 값이고, 그림은 "모형"으로 밝힘.
* 계절 변화의 원인(자전축·공전·23.5° 등)과 "절기"는 화면에 없다(자동 검사: 화면 글에 '자전축·23.5·기울어·공전·지도서·절기' 0건).

## 3. spec과 다른 점 / Build 판단

1. **공통 틀 `Experiment`를 쓰지 않고 실험 화면을 앱 전용 코드로 만들었다.** 개정 1의 흐름(달을 누르면 바로 재생 → 값 패널 → 기록하기)은
   Experiment의 "조건 고르기 → 실행 버튼 → 관찰 카드 → 확인 → 기록"과 맞지 않는다(달마다 4번 누름). 같은 CSS 틀(`.ss-exp-layout`, `.ss-exp-view`, 진행 막대)과
   `Sim3D`·`RecordStore`·`Experiment.scrollIntoView`만 쓰고, 3D↔2D 전환·늦은 3D 버리기(mount token)·WebGL 해제·컨텍스트 잃음 → 2D는 Experiment와 같은 방식으로 앱 안에 구현했다. 공통 틀 변경 요청 없음.
2. **분석 q1 보기**는 본문대로 3·6·9·12월(정답 6월). **q2 질문**은 q1 정답을 미리 보여 주지 않도록 "(6월)"을 빼고 "태양의 남중 고도가 가장 높았던 달의 낮의 길이는 내가 기록한 열두 달 중 어땠나요?"로 바꿨다.
3. **안전 한 줄**: 137쪽 문구("정해진 주제 이외 조사 금지")는 이 앱에 조사 화면이 없어 맞지 않아, "실제 하늘에서 태양을 관찰할 때는 태양을 맨눈으로 직접 보지 않아요."로 바꿨다.
4. **달 바 배치**: 가로 태블릿 오른쪽 칸·휴대폰은 계절 2개씩 두 줄(버튼 폭 ≥ 44px 유지), 세로 태블릿은 12달 한 줄. 달 바와 값 패널을 한 카드에 넣어 세로 태블릿에서도 하늘 모형·달 바·값·기록 버튼이 한 화면에 들어오게 했다.
5. 슬라이더류 조작은 없다(달 바는 버튼). 키보드: Tab + 방향키(←/→/↑/↓, Home/End)로 달 사이 이동, Enter/Space로 선택.
6. 재생 중에는 달 바·2D 전환·지난 경로 토글을 잠근다(`aria-disabled`, 누르면 무시). 기록하기는 그 달의 하루 길을 끝까지 본 뒤에만 켜진다(새로고침 뒤에도 유지).
7. `prefers-reduced-motion`이면 재생 없이 결과(길 전체 + 남중 표시)를 바로 보여 준다.
8. detail: `{ predict, hintsOpened, source:{area,year,day}, records:[{month,season,altitude,dayMinutes,dayLabel}×12], analysis:{q1,q2:{choice,correct,tries}}, conclusion, curiosity, qa }`.
   `qa` = predict.q1(text) · experiment.records(table 12행) · analyze.q1/q2(choice) · conclude.conclusion(text) · conclude.curiosity(text).
   → 관리자 응답 매핑 `src/data/app-responses/sci-6-2-1-3.ts`는 이번 범위 밖이라 만들지 않았다(Embed 단계에서 필요하면 추가).
