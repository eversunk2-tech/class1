## 3. 문제

### 🔴 문제 1 (높음) — 전기 회로 (라)의 배선이 교과서 카드와 다르다

* **위치**: `data/lesson-config.js:88-96`(`wire: { a: "loosePlus", c: "looseMinus" }`, `why`, `seen`), `app.js:202-203`(`P.loosePlus`/`P.looseMinus`), `app.js:215-219`(`sagFor`), `app.js:617-619`(2D `D2PATH.a.loosePlus`/`c.looseMinus`)
* **현상**: 앱은 (라)를 "전구·스위치는 이어져 있지만 **전선 끝의 집게가 전지에 물려 있지 않다**"로 그리고 설명한다. 그러나 실험관찰 75쪽(= 지도서 268쪽)의 (라) 카드는 **검정 집게가 전지의 (-)극 단자에 분명히 물려 있고**, 전구→스위치로 이어진 전선의 반대쪽(스위치의 다른 단자)이 비어 있는 모습이다. 즉 실제 (라)는 "**전지의 (-)극에만 연결된** 회로"다. 지도서 264쪽 정리도 "전구에 불이 켜지지 않는 전기 회로는 전기 부품의 연결이 끊어져 있거나 **전지의 (+)극 또는 (-)극에만 연결되어 있습니다**"라고 적어, (가)=(+)극에만·(다)=(+)극에만(전선 2개)·(라)=(-)극에만 이라는 읽기와 맞는다.
* **왜 문제인가**: 수업에서 학생은 실험관찰 75쪽 카드를 오려 실물로 회로를 만든다. 앱에서 본 (라)와 손에 든 (라)가 다르면 "집게를 안 물린 것이 (라)"라는 잘못된 기억이 남는다. 결과(안 켜짐)는 같지만, 이 차시의 학습 목표가 "왜 안 켜지는지 배선을 비교해 설명하기"이므로 배선 자체가 학습 내용이다.
* **재현**: 실험하기 → "전기 회로 (라)" 선택 → 3D/2D 장면과 관찰 카드 문구 확인. 비교 대상: `실험관찰-6-2.pdf` 75쪽(PDF 75쪽) (라) 사진, 또는 지도서 PDF 15쪽 오른쪽 아래.
* **수정 제안**(코드는 고치지 않음):
  1. `lesson-config.js` (라)를 `wire: { a: "minus", c: null }`로 바꾸고, 빨강/검정 구분을 위해 3D `setWiring`에서 (라)일 때 `wireA` 색을 검정으로 쓰는 옵션(예: `wireColor: "black"`)을 `circuits`에 추가한다.
  2. 문구 교체 — `why`: "전선이 전지의 (-)극에만 연결되어 있어요. 스위치와 전지 사이에는 전선이 없어요." / `seen`: "전구에 불이 켜지지 않았어요. 전선이 전지의 (-)극에만 연결되어 있고, 스위치와 전지 사이에는 전선이 없어요."
  3. (가)의 `why`도 "전선이 전지의 (+)극에만 연결되어 있어요. 스위치와 전지 사이에는 전선이 없어요."로 다듬으면 (가)/(라) 대비가 "(+)극에만 / (-)극에만"으로 분명해지고 지도서 264쪽 정리와 이어진다.
  4. 2D는 `D2PATH.a.minus`(전구 왼쪽 단자 → (-)극 단자 290,50)를 새로 넣고 `loosePlus`/`looseMinus` 경로와 `.d2-clip` 2개는 쓰지 않게 한다.
  5. `spec.md` 1절의 (라) 판독 내용도 함께 고쳐야 한다(다음 Build·Review가 같은 오류를 되풀이하지 않도록).
* **덧붙임**: 지금 3D에서도 (라)의 "떠 있는 집게"는 전지 단자 바로 옆 높이에 붙어 있어(`P.loosePlus = [-1.75, 1.15, -1.25]`) 기본 시점에서는 **물려 있는 것처럼 보인다**(첨부 확인용 화면 캡처 기준). 위 수정이 이 문제까지 함께 없앤다.

### 🟠 문제 2 (중간) — 실행이 끝나면 3D 카메라가 전구로 확대돼 배선이 화면 밖으로 나간다

* **위치**: `app.js:558` — `await v.focus([-2.8, 1.1, 1.7], 0.6, 520);` (run 마지막)
* **현상**: "▶ 스위치 닫기"를 누르면 실행이 끝난 뒤 카메라가 전구 쪽으로 크게 확대된다. 1024×768에서 **스위치가 완전히 화면 밖으로 사라지고** 전지 일부만 보인다. 이 상태로 관찰 카드의 보기를 고르고 기록하므로, 학생이 "어디가 끊겼는지"를 화면에서 직접 확인하지 못한 채 넘어가기 쉽다. 특히 (다)·(라)는 배선 차이가 관찰 목표인데 그 부분이 보이지 않는다.
* **재현**: 실험하기 → (다) 또는 (라) 선택 → 실행 → 3D 화면. "🎥 처음 방향으로"를 눌러야 전체 회로가 다시 보인다.
* **수정 제안**: 확대 목표를 전구 단독이 아니라 **회로 전체가 들어오는 거리**로 바꾸거나(예: `v.focus([0, 0.7, -0.1], 0.8, 520)`), 불이 켜진 (나)·금속 막대일 때만 전구로 확대하고 안 켜진 칸은 전체 시점을 유지한다. 또는 확대 뒤 1초쯤 지나 `v.flyHome()`으로 되돌린다.

### 🟡 문제 3 (낮음) — 분석 정답 피드백 문구가 겹친다

* **위치**: `data/lesson-config.js:135`, `:151` (`correct`가 "맞아요!"로 시작)
* **현상**: 공통 틀이 앞에 "⭕ 맞았어요!"를 붙여 화면에 "⭕ 맞았어요! 맞아요! 불이 켜진 회로는 …"로 나온다(실제 확인).
* **수정 제안**: `correct`에서 앞의 "맞아요!"를 빼고 "불이 켜진 회로는 …"으로 시작한다.

### 🟡 문제 4 (낮음) — 2D에서 막대는 실행한 뒤에만 그려지는데 안내 문구는 "연결한 모습"이라고 한다

* **위치**: `app.js:721-723`(`rod2.style.display = done ? "" : "none";`), `app.js:756`(캡션 "…를 연결한 모습이에요. 실행 버튼을 눌러 보세요.")
* **현상**: 2D에서 막대를 고르면 스위치 자리가 **비어 있는데** 캡션은 "플라스틱 막대를 연결한 모습이에요"라고 안내한다. 3D에서는 막대가 공중에 떠 있게 그려져 "아직 끼우지 않음"이 보이지만 2D에는 그 표현이 없다.
* **수정 제안**: 2D에서도 실행 전 막대를 흐리게(점선·반투명) 그리거나, 캡션을 "…를 끼우기 전이에요. 실행 버튼을 눌러 보세요."로 바꾼다.

### 🟡 문제 5 (낮음) — 실험 2에서 스위치 받침이 그대로 남아 있다

* **위치**: `app.js:463-478`(`showRod`) — 레버와 "스위치" 글자만 숨기고 받침·단자는 남긴다
* **현상**: 실험관찰 37쪽(지도서 264쪽 그림 설명)은 "**스위치를 제거하고** 그 자리에 막대를 연결한 모습"이다. 앱은 스위치 받침 위에 막대를 올린 모습이라 "스위치에 막대를 얹었다"로 읽힐 수 있다.
* **수정 제안**: 실험 2에서 받침을 숨기고 집게 달린 전선 두 개 사이에 막대만 놓거나, 라벨을 "전선 사이에 끼운 막대"로 보완한다. (모형 표시가 있으므로 급하지는 않다.)

### 🟡 문제 6 (낮음) — 관찰 오답 횟수가 항상 0으로 저장된다

* **위치**: `app.js:839` — `answer: { …, tries: 0 }`
* **현상**: 관찰 보기를 여러 번 틀려도 `detail.qa`의 관찰 항목은 `tries: 0`으로 저장돼, 관리자 "학생 응답"에서 학생이 몇 번 만에 맞혔는지 알 수 없다. build-report 7절에도 적혀 있다(공통 틀이 칸별 오답 횟수를 돌려주지 않음).
* **수정 제안**: 공통 틀 `Experiment`에 칸별 `tries`를 돌려주는 API를 더한 뒤 반영한다(정본 수정이므로 별도 작업으로).

### 참고 사항

* `detail.qa`의 id가 spec §8과 다르다(`q1`/`q2`←`quiz_q1`/`quiz_q2`, `curiosity`←`curiosity1`, `conclusion`←`conclude1`). 관리자 화면은 `detail.qa`를 그대로 읽으므로(`docs/admin/responses-spec.md` §3.3) **동작에는 영향이 없고** 새 앱은 `src/data/app-responses/` 매핑 파일도 필요 없다. spec 표기만 현실과 다르다.
* 지도서 263쪽 오개념(전구 끼우개 아랫면 연결)은 spec 10절에서 "이번 앱에는 넣지 않음"으로 승인된 사항이라 문제로 보지 않았다.

## 5. 소요 시간

기계 시간(애니메이션·화면 전환만, 스크립트가 넣은 대기 제외한 실측):

| 구간 | 기계 시간 |
|---|---|
| 실험 준비(3D 첫 로드 포함) | 약 2.0초 |
| 칸 1개 실행 애니메이션 | 약 2.4~2.7초 (첫 칸 2.7초) |
| 실험 7칸 합계(고르기·실행·확인·기록 자동) | 약 24초 |
| 분석 표 그리기 + 2문항 | 약 1.8초 |
| 정리 + 마치기(결과 저장) | 약 1.9초 |
| **합계** | **약 30초** |

학생 시간 추정(화면에 읽을 글 **1,379자**를 실측해 초6 묵독 속도로 환산 + 타이핑 2회 + 조작):

| 단계 | 보통 학생 | 느린 학생 |
|---|---|---|
| 예상하기(도입·질문 읽기 + 한 문장 타이핑, 힌트 포함) | 65초 | 110초 |
| 실험 전에 알아 두기(423자) | 60초 | 95초 |
| 실험 1 (4칸 × 약 22초) | 90초 | 140초 |
| 실험 2 (3칸 × 약 17초) | 50초 | 75초 |
| 기록·분석(표 확인 + 2문항) | 60초 | 95초 |
| 정리하기(결론 타이핑 + 모범 답안 비교) | 60초 | 95초 |
| 궁금한 점(선택) | 10초 | 20초 |
| **합계** | **약 5분 55초** | **약 10분 30초** |

* 보통 학생은 **7분 기준 안**에 들어온다.
* 느린 학생은 기준을 넘길 수 있다. 가장 큰 덩어리는 "실험 전에 알아 두기"(423자, 문단 4 + 안전 4줄)와 (가)·(다)·(라)의 두 겹 설명(`seen`과 `why`가 거의 같은 말을 두 번 한다 — 예: (라) "전선 끝의 집게가 전지에 물려 있지 않아요"가 관찰 문장과 🔎 문장에 모두 들어 있다). **`why`를 없애고 `seen` 한 줄로 합치면 약 60~80초 줄어든다.** (2단원 탐구 5도 비슷한 이유로 8~9분이 걸렸고 사용자가 그대로 두기로 했으므로, 줄일지는 사용자 판단 사항으로 남긴다.)
* 실제 학생 소요 시간은 재지 못했다(위는 글자 수·조작 수 기반 추정).

## 6. 확인한 것 / 확인하지 못한 것

**확인한 것**
* 전체 흐름 끝까지 진행(7칸 기록 → 분석 2문항 오답·정답 → 결론 → 마치기 → `app_results` 저장 payload 확인), 콘솔 오류 0
* 기록 값이 spec·교과서와 같은지: (가)·(다)·(라) 안 켜짐 / (나) 켜짐, 플라스틱·고무 안 켜짐 / 금속 켜짐 — 표·저장 기록 모두 일치
* 교재 대조: 지도서 262~264·268쪽, 실험관찰 36~37·75쪽(회로 카드 원본 사진을 고배율로 판독)
* 로그인 가림막 / 비로그인 시 `sci6…` 전부 삭제 / 다른 학생으로 바뀔 때 앞 사람 기록 삭제 / `app_progress` 저장·복원(로컬을 비운 "다른 기기" 시나리오 포함)
* 단계 잠금·게이트 문구, 앞 단계 이동, 같은 칸 다시 실행·다시 기록, 실험대 되돌리기, 새로고침(가짜 충돌 없음)
* `?no3d=1` 2D 대체 화면의 배선 경로(`d` 속성)까지 하나씩 대조, 3D↔2D 5회 연속 전환에서 WebGL 컨텍스트 해제
* 1024×768 / 768×1024 / 375×812 가로 스크롤 0, 다크모드 대비, `innerHTML` 미사용, aria 속성, 터치 영역 52px
* 공통 틀 사본 = 정본(`diff -r` 차이 0)

**확인하지 못한 것**
* **실제 iPad·태블릿 터치**(3D 한 손가락 드래그 회전, 두 손가락 확대, 두 번 탭 초기화). headless Chrome(SwiftShader)에서만 확인했다.
* **실제 Supabase DB·로그인**. 지침대로 실 DB에 쓰지 않고 `Class1Record`를 가짜 객체로 바꿔 확인했다(진행 저장·이어서 하기·완료 저장의 *앱 쪽 연결*은 확인했지만 RLS·실제 행 저장은 확인하지 못했다).
* **블로그에서 로그아웃**했을 때의 `sci6…` 삭제(다른 탭 storage 이벤트 경로). 이 탭 안 `signed_out` 경로와 비로그인 진입 경로만 확인했다.
* **실제 학생 소요 시간**(5절은 추정).
* `npm run build`·lint는 돌리지 않았다(이 앱은 `public/` 정적 파일만 더한다).

**뒷정리**: 띄운 정적 서버(8991)와 headless Chrome(9333)은 모두 종료했다. 임시 파일은 스크래치 폴더에만 두었다.
