## 1. 고친 것

### 🔴 문제 1 (높음) — 전기 회로 (라)의 배선 — **고침**

실험관찰 75쪽 / 지도서 264·268쪽대로 **검정 전선 집게가 전지의 (-)극에 물려 있고, 스위치 쪽 단자 하나가 비어 있는** 모습으로 바꿨다.

| 위치 | 바뀐 내용 |
|---|---|
| `data/lesson-config.js` (라) | `wire: { a: "loosePlus", c: "looseMinus" }` → **`wire: { a: "minus", c: null, color: "black" }`** |
| `data/lesson-config.js` (라) `seen` | "…전선 끝의 집게가 전지에 물려 있지 않아요" → **"전구에 불이 켜지지 않았어요. 전선이 전지의 (-)극에만 연결되어 있어요."** |
| `data/lesson-config.js` (가) `seen` | **"…전선이 전지의 (+)극에만 연결되어 있어요."**(리뷰 제안대로 (가)/(라) 대비를 "(+)극에만 / (-)극에만"으로 맞춤 — 지도서 264쪽 정리와 같은 표현) |

| `app.js` 3D | `P.loosePlus`/`P.looseMinus`와 `sagFor()` 삭제, `setWiring()`이 `wire.color === "black"`이면 전구 쪽 전선을 검정으로 그린다 |
| `app.js` 2D | `D2PATH.a.minus`(전구 왼쪽 단자 → 위로 돌아 (-)극) 추가, `loosePlus`/`looseMinus` 경로와 `.d2-clip` 사각형 2개 삭제, 검정/빨강은 `d2-red` 클래스 토글로 |

* (나)·(다)는 그대로 두었고 (가)는 배선을 바꾸지 않고 문구만 다듬었다.
* 덤: (라)의 긴 전선이 3D·2D의 "전지" 글자를 지나가서, 3D는 전지 라벨을 (+)극·(-)극 사이 위쪽으로, 2D는 전지 아래로 옮겼다.
* **spec.md 1절의 (라) 판독 설명도 고쳐야 한다** — 내 수정 범위 밖이라 건드리지 않았다(다음 Build·Review가 같은 오류를 되풀이하지 않도록 Claude가 고쳐 주기 바람).

### 🟠 문제 2 (중간) — 실행 뒤 카메라가 전구로 확대돼 배선이 안 보임 — **고침**

`app.js` `run()` 마지막을 바꿨다.

* **안 켜진 칸**: 전구로 확대하지 않고 **회로 전체가 보이는 시점**으로 맞춘다(`v.focus([0, 0.7, -0.1], 0.95, 480)`).
* **켜진 칸((나)·금속 막대)**: 전구를 0.46초 가까이 보여 주고 0.6초 머문 뒤 **다시 회로 전체 시점으로 되돌아온다**.
* 비율 0.95는 처음 맞춤 거리(회로 전체가 들어오는 거리)의 95%라, 전지·전구·스위치가 모두 화면 안에 남는다. 학생이 돌려 둔 방향은 그대로 유지한다(`flyHome`이 아니라 `focus`).

### 🟡 문제 3 — 정답 피드백 중복 — **고침**
`quiz[].correct`에서 앞의 "맞아요!"를 뺐다. 화면: "⭕ 맞았어요! 불이 켜진 회로는 …"(실제 확인).

### 🟡 문제 4 — 2D 막대 표시 시점과 문구 불일치 — **고침**
2D에서도 실행 전에 막대를 **흐리게·점선(`.d2-rod.is-pending`)** 으로 그려 "아직 끼우기 전"이 보이게 하고, 안내 문구를 **"○○ 막대를 아직 끼우기 전이에요. 실행 버튼을 눌러 보세요."** 로 바꿨다(회로 카드는 "…를 연결한 모습이에요. 스위치를 닫아 보세요.").

### 🟡 문제 5 — 실험 2에 스위치 받침이 남아 있음 — **고침**
교과서(실험관찰 37쪽)처럼 **스위치를 떼어 낸다**. 3D는 받침·단자 기둥·레버·"스위치" 글자를 모두 숨기고 전선 집게 두 개 사이에 막대만 놓는다(막대 높이 0.5 → 0.44로 낮춰 집게에 닿게). 2D도 스위치 받침과 레버를 숨기고 막대만 그린다.

### 🟡 문제 6 — 관찰 오답 횟수가 항상 0 — **고침(공통 틀을 고치지 않고)**
공통 틀이 `observe().check(observed, ctx)`에 넘겨 주는 **`ctx.tries`**(그 카드에서 틀린 횟수)를 앱이 받아 기록에 담도록 했다.
`makeRecord`에 `tries`를 넣고 `detail.qa`의 관찰 항목·`detail.records`가 그 값을 쓴다. 확인: 일부러 한 번 틀린 뒤 맞히면 `records[0].tries === 1`, `detail.qa`의 `circuit_ga`가 `tries: 1`로 저장된다.

## 4. 다시 확인한 것

* **전체 흐름 끝까지** 새로 2번: 예상 → 실험 7칸 → 분석 2문항 → 결론 → 궁금한 점 → 학습 마치기 → 결과 저장(`completed: true`, `details` 4,224자, `detail.qa` 13개). **콘솔 오류 0건.**
* **(라) 배선**: 3D·2D 모두 "검정 전선 1개가 (-)극에만 물려 있고 스위치 쪽 단자 하나가 빔". (가)는 빨강 전선이 (+)극에만. 두 카드가 색·극으로 분명히 구분된다(화면 캡처로 확인).
* **(나)·(다)** 배선은 고치기 전과 같음(캡처 대조).
* **관찰 카드**: 한 줄로 합쳐진 문장이 나오고(`👀 전구에 불이 켜지지 않았어요. 전선이 전지의 (+)극에만 연결되어 있어요.`), 본 것과 다른 보기를 고르면 기록이 막힌다.
* **오답 횟수**: 한 번 틀린 뒤 맞히면 `tries: 1`이 기록·저장된다.
* **정답 피드백**: "⭕ 맞았어요! 불이 켜진 회로는 …"(중복 없음), 오답 피드백(`wrongBy`)도 그대로 동작.
* **실험 2**: 3D·2D 모두 스위치 받침이 사라지고 전선 사이에 막대만 놓인다. 2D는 실행 전 막대가 점선·반투명이고 안내가 "아직 끼우기 전이에요".
* **새로고침 복원**: 2칸 기록 뒤 새로고침 → 실험하기 단계·2/4·예상 글 복원, 가짜 충돌 창 없음.
* **`?no3d=1` 2D 대체**, **3D↔2D 4회 연속 전환**(캔버스 항상 1개, 오류 0).
* **화면 크기**: 375×812·768×1024·1024×768에서 `scrollWidth == clientWidth`(가로 스크롤 0), 결과 표도 표 안 가로 스크롤 없음. **다크모드** 정상((라) 배선·라벨 대비 유지).
* **공통 틀**: `diff -r scripts/templates/science-sim public/apps/sci-6-2-3-1/science-sim` 차이 0, `class1-record.js` 차이 0.

## 5. 확인하지 못한 것

* **실행 직후 카메라의 최종 화면을 그대로 찍은 캡처**. 이 환경에서는 headless 브라우저가 가상 시간으로 돌아 실행 애니메이션이 끝나기 전에 사진이 찍히고, 공유 브라우저 탭은 `document.hidden`이 항상 참이라 애니메이션이 건너뛰어진다. 대신 **실행 도중(같은 방향·비율 0.86) 캡처에서 전지·전구·스위치가 모두 화면 안에 있음을 확인**했고, 최종 비율 0.95는 그보다 더 넓은 화면이다(회로가 차지하는 범위 6.9×4.1 < 화면 범위 9.3×7.4).
* **실제 iPad·태블릿 터치**, **실제 Supabase DB·로그인**, **블로그 로그아웃 경로**, **실제 학생 소요 시간** — 리뷰와 같은 이유로 확인하지 못했다.
* `npm run build`·lint는 돌리지 않았다(이 앱은 `public/` 정적 파일만 더한다).

**뒷정리**: 띄운 정적 서버와 headless Chrome은 종료했고, 내 브라우저 탭도 닫았다. 스크래치 폴더 `scratchpad/build-sci-6-2-3-1/`는 삭제 명령이 권한 거부되어 남아 있다(앱 폴더 밖이라 저장소에는 영향 없음).
