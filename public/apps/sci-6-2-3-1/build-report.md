## 2. 구성

* **단계**: 예상하기 → 실험하기 → 기록·분석하기 → 정리하기(결론 + 궁금한 점 한 줄 + 학습 마치기). 4단계.
* **실험하기**: 조건 1개("무엇으로 실험할지") × 보기 7개, 단계 2개.
  * 실험 1 = 전기 회로 (가)·(나)·(다)·(라) 4칸. 실험 2 = 플라스틱·고무·금속 막대 3칸(실험 1을 모두 기록해야 열림 — 공통 틀의 단계 잠금 그대로).
  * 보기를 고르면 3D에 그 배선이 바로 보이고, 실행 버튼(`▶ 스위치 닫기 · 전기 회로 (가)` / `▶ 금속 막대 연결하기`)을 누르면 스위치가 닫히거나 막대가 내려오고 결과가 나온다.
  * 관찰 카드에 본 모습이 글로 보이고, 학생은 **보기 2개 중 고르기 → 확인하기 → 기록하기**(타이핑 없음). 7칸 모두 기록해야 다음 단계로 간다.
* **배선(3D·2D 공통)** — spec 1절 판독 결과 그대로.
  * (가) 전구↔전지(+) 전선, 전구↔스위치 전선은 있고 **스위치↔전지(-) 전선이 없음**
  * (나) (+)극 → 전구 → 스위치 → (-)극까지 모두 이어짐 → **불이 켜짐**
  * (다) 전지에 물린 전선 두 개가 **모두 (+)극**에 있음((-)극에 아무것도 없음)
  * (라) 전구·스위치는 이어져 있으나 **전선 끝 집게가 전지에 물려 있지 않음**(공중에 떠 있게 그림)
  * 실험 2는 (나)와 같은 배선 + 스위치 자리에 막대(주황=플라스틱, 검정=고무, 은색=금속). 금속만 켜짐.
* **모형 표시**: 3D 화면 왼쪽 위 공통 틀 배지 "모형", 오른쪽 위 앱 배지 "🏷 화살표는 모형", 화면 아래 설명("전기가 흐르는 모습은 눈에 보이지 않지만, 흐르는 길을 알기 쉽게 화살표 모형으로 나타냈어요").
* **안전 안내**(실험 전에 알아 두기): 전구 파손 주의 / 젖은 손 금지 / **전지의 (+)극과 (-)극을 전선으로 바로 잇지 않기** / 콘센트·가정용 전기 금지.
* **용어**: 교과서 표기(전기 회로·전지·전구·전선·스위치·전기가 흐르는 물질)만 썼다. 중학교 용어와 "전류", 다음 차시 내용(전지 두 개 연결 등), "지도서"라는 말은 화면에 없다. 출처는 "교과서·실험관찰"로 적었다.
* **`detail.qa`**: spec 8절 목록 그대로 13개 — predict1 / circuit_ga·na·da·ra / material_plastic·rubber·metal / records(표) / q1·q2 / conclusion / curiosity. 저장된 `details` 크기 약 4.3KB(한도 16,000자 안).

## 5. 확인한 것

브라우저는 다른 에이전트와 공유되므로 **내 탭 하나**와 **내 전용 headless Chrome + 내 전용 정적 서버(포트 8971·8972·8973, 끝내고 종료)**만 썼고, `localStorage.clear()`를 쓰지 않았다(`sci623sim1…`과 내 시험용 키만 지움).

* **전체 흐름 끝까지**: 예상 → 실험 7칸 → 분석 2문항 → 결론 → 궁금한 점 → 학습 마치기 → 결과 저장(가짜 DB에 `completed: true`, `details.qa` 13개). 콘솔 오류 **0건**.
* **기록 값이 spec과 같은지**: (가)·(다)·(라) 안 켜짐, (나) 켜짐 / 플라스틱·고무 안 켜짐, 금속 켜짐 — 결과 표와 저장된 기록 모두 일치.
* **단계 잠금**: 실험 2 보기는 "🔒 실험 1을 마치면 열려요"로 잠기고, 실험 1을 4칸 기록하면 열림. 분석·정리 단계 잠금 문구도 정상.
* **오답 피드백**: 분석 1번에서 "전지가 두 개" → "전지 개수가 아니라 연결 방법을 다시 살펴보세요", "스위치가 열려 있다" → "…스위치를 닫았을 때만 비교했어요" (다음 차시 내용 언급 없음). 관찰 보기를 잘못 고르면 확인하기에서 막히고 기록되지 않는다.
* **새로고침 복원**: 2칸 기록 뒤 새로고침 → 실험하기 단계·2/4·예상 글 그대로 복원, **가짜 충돌 창 뜨지 않음**. (참고: 서버 기록을 일부러 다르게 만든 경우에는 "⚠️ 기록이 두 가지예요" 창이 정상적으로 떴다 — 진짜 충돌 판단은 살아 있음.)
* **앞 단계 이동 · 다시 하기**: 분석 → 이전 단계 → 실험으로 돌아가 (나)를 다시 실행·다시 기록 가능. "처음부터 다시 하기"는 로컬 기록과 (가짜) DB 행을 모두 지우고 예상하기부터 다시 시작.
* **실험대 되돌리기**: 화면만 처음 상태로, 기록은 유지(4/4 그대로).
* **`?no3d=1` 2D 대체**: SVG 회로도로 같은 정보 제공((가)~(라) 배선 차이, 집게가 떨어진 모습, 켜짐/안 켜짐, 막대). 3D↔2D **5번 연속 전환** — 캔버스는 항상 1개, 콘솔 오류 0(WebGL 컨텍스트 정상 해제).
* **로그인 필수**: 세션이 없으면 "🔒 로그인이 필요해요" 가림막 + 로그인 링크만 보인다.
* **화면 크기**: 1024×768(태블릿 가로), 768×1024(태블릿 세로), 620×1000, 375×812(휴대폰)에서 **가로 스크롤 0**(`scrollWidth == clientWidth`), 결과 표도 표 안 가로 스크롤 없음.
* **다크모드**: 머리말·카드·3D 배경·실험대 색이 모두 바뀌고 글자 대비 유지.
* **색만으로 구분하지 않음**: 결과 표·관찰 카드·미니 표 모두 아이콘(💡/⚫/✓)과 글자를 함께 쓴다. 3D에는 "전지 / +극 / -극 / 전구 / 스위치 / 막대" 글자 라벨을 붙였다.

## 6. 확인하지 못한 것

* **실제 iPad·휴대폰 터치**(3D 드래그 회전, 두 손가락 확대). headless Chrome(SwiftShader)과 브라우저 탭에서만 확인했다.
* **실제 Supabase DB**(진행 상황 저장·이어서 하기·완료 결과). 지침대로 실 DB에 쓰지 않고 가짜 응답으로만 확인했다.
* **두 학생 계정 번갈아 쓰기**(기록 주인 바뀜 → 로컬 삭제)와 **블로그 로그아웃 시 `sci6…` 삭제**. 블로그 화면이 필요해 확인하지 못했다.
* **실제 학생 소요 시간**(4절은 추정치).
* `npm run build`는 돌리지 않았다(다른 앱을 동시에 만드는 중이라 빌드를 건드리지 않았다. 이 앱은 `public/` 정적 파일만 더해서 빌드에 영향을 주지 않는다).

**뒷정리**: 띄운 서버(8971·8972·8973)와 headless Chrome은 모두 종료했고, 내 브라우저 탭도 닫았다. 스크래치 폴더 `scratchpad/build-sci-6-2-3-1/`(시험용 앱 사본·가짜 Supabase·스크린숏)는 **삭제 명령이 권한 거부되어 남아 있다** — 앱 폴더 밖이라 저장소에는 영향이 없다.

## 7. 공통 틀에 바랄 점 (고치지 않고 적어 둠)

* `.ss-matrix`의 `min-width: 620px`는 열이 2개뿐인 표에서는 좁은 화면 가로 스크롤을 만든다. 지금은 앱 CSS에서 덮었지만, 정본에서 열 수에 따라 정해지면 더 좋겠다.
* 관찰 카드의 오답 횟수(`tries`)를 앱이 읽을 방법이 없어 `detail.qa`의 관찰 항목은 `tries: 0`으로 넣었다. `exp`가 칸별 오답 횟수를 돌려주면 그대로 담을 수 있다.
