## 2. spec과 다른 점과 구현 결정

1. **분석 4(단위가 다른 속력)**: spec 보기 "② 5 m/s가 더 빠르다"는 과학적으로 **참**이다(10 km/h ≈ 2.8 m/s, 지도서 223쪽). 그런데 spec은 이 보기를 오답으로 채점한다. 그래서 문항을 바꿨다. 이제 "10 km/h가 숫자가 크니까 더 빠르다"는 민재의 말을 평가하게 한다. 정답은 "단위가 다르므로 숫자만 보고 바로 비교할 수 없고, 단위를 같게 맞춰야 비교할 수 있다"이다. 정답 피드백에서는 지도서대로 "단위를 맞추면 5 m/s가 더 빠르다"를 알려 준다. 환산 계산은 요구하지 않는다.
2. **분석 3(평균 속력)**: 앱 장면은 등속 모형이라, 장면 안에서는 "매 초 27.0 cm씩" 가는 것이 사실이 된다. 그래서 오답 보기를 "1초마다 재어 보니 매 초 정확히 27.0 cm씩 이동했다는 뜻"(측정 방법에 대한 오개념, 222쪽)으로 다듬었다. "전체 거리가 27.0 cm라는 뜻"이라는 오답 보기를 하나 더 넣어 3지선다로 만들었다. 정답 피드백은 "모형이라 일정하지만 실제 태엽 자동차는 빠르기가 달라질 수 있다"고 밝힌다.
3. **값 확인 방식(오차 없음, 확정 결정)**: 읽은 값(거리 또는 시간)과 속력 입력칸은 지도서 값과 같아야 기록된다(`min = max`). 값이 다르면 기록 버튼이 잠긴다. 대신 답을 알려 주지 않는 안내를 보여 준다("확대 그림에서 앞부분 눈금을 다시 읽어 보세요", "초시계 숫자를 다시 읽어 보세요", "나누는 순서를 확인해 보세요").
4. **계산기**: 읽은 값이 맞으면 식(예: `100 ÷ 4.2`)이 자동으로 들어간다. 학생은 `=`를 눌러 계산기 표시(23.80952381)를 보고, 반올림 안내와 함께 23.8이 속력 칸에 들어간다. 교통수단 카드에는 식이 미리 들어가지 않는다(열린 질문 3 추천안). 학생이 숫자와 ÷를 직접 누르고, 반올림 값이 0.1 이내면 자동으로 기록된다. 거꾸로 나누면 따로 안내한다.
5. **관찰 카드 순서**: 공통 틀은 body(그림) → 입력칸 순서로 만든다. 앱 코드에서 순서를 "읽은 값 → 계산기 → 속력 → 기록하기"로 옮겼다(DOM 이동만 했고 공통 틀은 그대로).
6. **3D 장면**: 차선 4개(1단계 빨강·파랑, 2단계 초록·노랑)마다 cm 줄자(1 cm 눈금, 10 cm 숫자)를 두었다. 출발선(0 cm)은 모든 차선에, 결승선(100 cm, 보라색)은 2단계 차선에만 있다. 자동차는 상자 모형이고 태엽 열쇠가 달리는 동안 돈다. 이름표가 붙어 있어 색만으로 구분하지 않는다. 1단계는 5.0초에 멈추고 "📸 5초가 된 순간의 모습"을 보여 준 뒤 앞부분으로 다가간다. 2단계는 앞부분이 100 cm에 닿는 순간 초시계가 멈추고, 자동차는 0.6초 더 달린 뒤 선다. 모두 **실제 시간**(빨리 감기 없음)이고, 모형 안내에 이를 밝혔다. 다른 자동차를 고르면 지난 초시계 표시를 치운다.
7. **2D 대체**: 위에서 본 차선 4개, 줄자, 출발선, 결승선, 같은 초시계 HUD. 휴대폰에서는 20 cm마다 숫자를 쓴다.
8. **분석 추가 요소**: 자동차 표 아래에 속력 식 목록을 두었다. "cm/s와 km/h를 쓴 까닭 생각해 보기" 안내도 넣었다(222쪽 지도 길잡이, 답은 주지 않음). 막대그래프만 쓴다(spec 7-4). 분석 단계를 넘어가려면 교통수단 5가지를 모두 구하고 퀴즈 4개를 확인해야 한다.
9. **퀴즈 오답 피드백**: q1에 초록·노랑 보기용, q2에 기차 보기용 `wrongBy`를 더했다. 어느 것도 정답을 직접 말하지 않는다.
10. **궁금한 점**: 지도서 224~225쪽 보충 자료(노트·마하, 스피드 건·GPS 앱)를 "📚 더 알아보기" 카드로 소개한다. 공통 틀의 `examples`는 "이런 식으로 적어도 좋아요" 문구로 나오기 때문에 쓰지 않았다.
11. 예상하기에는 221쪽 전제("같은 출발선에 놓고 비교할 수 없음")를 도입 문장으로 넣었다. 예상하기 화면에는 "속력"과 "나누기"라는 말이 없다(머리말의 차시 제목은 예외).

## 3. 확인한 것

공유 Browser 패널 탭은 숨겨진 상태(`document.hidden = true`)라 애니메이션이 바로 끝났다. 그래서 대부분의 검증은 자체 헤드리스 Chrome 153(CDP, 포트 9471, SwiftShader WebGL)으로 했다. 대상은 `http://localhost:3000/class1/apps/sci-6-1-2-5/index.html`이다.
- **전체 흐름**을 1024×768 라이트, 768×1024 다크, 375×812 모바일(터치 에뮬레이션), `?no3d=1`(768×1024)에서 끝까지 진행했다. 순서: 예상 게이트 → 힌트 3개 → 2단계 잠금 알림 → 자동차 4대(틀린 값 안내, 기록 잠금, 맞는 값이면 계산기 식, `=` → 27.0 / 24.4 / 23.8 / 17.2) → 분석 표·막대 → 교통수단(거꾸로 나누기, 식 미완성, 틀린 값 안내 → 20 / 72.5 / 150 / 34.5 / 900) → 퀴즈 4개(오답 피드백 뒤 정답) → 정리 3개(모범 답안, `<img onerror>` 입력 시 img 0개) → 궁금한 점 → 마치기.
- **실제 시간**: 초록색 자동차는 출발 뒤 4.2초에 초시계가 멈췄다(0.4초 간격으로 표본을 뽑아 확인). 빨간색은 5초 동안 달렸다.
- **세로 화면·휴대폰**: 달리는 동안 3D 화면(127~577px / 166~466px)과 초시계가 화면 안에 있었다. 스크린숏으로도 확인했다.
- **가로 스크롤**: 모든 크기의 모든 단계에서 `scrollWidth`가 뷰포트 너비와 같았다.
- **새로고침 복원**: 단계, 궁금한 점 입력, 기록(미니 표 ✓✓✓✓), 3D 장면이 되살아났다. 앞 단계(실험하기)로 이동해도 동작했다.
- **3D↔2D**: 6번 왕복한 뒤 캔버스 1개. `?no3d=1`에서는 캔버스 0개였다.
- **저장**: `Class1Record.save`를 가짜로 바꿔 확인했다. detail 키는 predict, records, transports, analysis, conclusion, extension, curiosity이고 크기는 약 1.1천 자다. 비로그인 안내 문구가 나온다. 실 DB 요청은 없다.
- **콘솔 오류·경고**: 앱 기준 0건. `node --check app.js` 통과. `innerHTML` 사용 없음.

## 4. 못 한 것 / 참고

- 실제 태블릿 터치(핀치·드래그), iOS Safari, 로그인 상태의 실제 저장은 확인하지 못했다. `npm run build`와 Embed(`science-curriculum.ts` 연결)도 하지 않았다.
- 휴대폰 폭에서는 3D 글자 라벨과 줄자 숫자가 작다. 1단원 앱과 같은 제한이다. 눈금 읽기는 관찰 카드의 확대 그림으로 한다.
- 작업하는 동안 다른 에이전트가 공통 틀 정본(`experiment.js`, `sim3d.js`, `style-common.css`)을 커밋하지 않은 채 고쳤다(visible 옵션, busyLabel, Countdown 등 추가). 이 앱의 `science-sim/`은 그 전 HEAD 판 복사본이다. 새 기능은 쓰지 않으므로 다시 복사하지 않았다.
- **틀 반영 제안**: (a) `lockMessage`의 조사 오류: "1단계(2칸)를 모두 기록하면"은 "2칸을"이어야 한다(작업 트리 정본에서는 이미 고쳐짐). (b) 수치 입력 필드에 "정답 값 + 틀렸을 때 안내 문구" 옵션을 넣고, 관찰 카드 안에서 body를 입력칸 사이에 둘 수 있는 자리(`afterField`)를 만든다. 지금은 앱 코드에서 DOM을 옮긴다. (c) 계산기 위젯(÷ = C ⌫)을 공통 컴포넌트로 만든다. 속력 차시에 계속 쓰인다.
- **검증 환경 주의**: 처음 띄운 헤드리스 Chrome(포트 9337)에 다른 에이전트도 붙어 있었다. 그 뒤 포트 9471 전용 Chrome으로 옮겼다. 9337 Chrome은 다른 에이전트가 아직 쓰고 있어 종료하지 않았다. 초기 스크립트 한 번이 그 브라우저의 첫 탭(다른 앱 페이지였을 수 있음)을 이 앱 주소로 이동시켰을 가능성이 있다. 공유 Browser 패널에서는 이 앱의 키(`sci612sim5:*`)만 지웠고 자기 탭을 닫았다. 9471 Chrome은 종료했다. 스크래치 폴더 `scratchpad/t5`(테스트 스크립트, 스크린숏, 프로필)는 `rm` 권한이 거부되어 남아 있다.
