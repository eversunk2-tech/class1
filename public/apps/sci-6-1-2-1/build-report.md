## 2. 구현 요약

- 조건 ① 장면(교실 안 → 바닷가 → 공원, 앞 장면 모두 기록해야 열림) ② 물체(고른 장면의 물체만 보임). 26칸.
- **📷 사진 찍기**: 사진 1 찍기 → 초시계로 **실제 5초** 카운트다운(⏱ + 5·4·3·2·1 + 진행 고리, "실제 시간 5초") 동안 `moved: true` 물체만 움직임 → 사진 2. 두 사진 모두 고른 물체에 점선 원과 이름 표시. 사진 1에서 물체가 있던 곳을 두 사진에서 똑같이 잘라 크게 본 사진도 보여 준다.
- 움직임은 장면 시간 t초의 함수(닫힌 타원 길)라서 순간 이동이 없다. 장면 시간은 저장돼 새로고침 뒤에도 이어진다. 시곗바늘: 5초에 초침 30˚, 분침 0.5˚, 시침 1/24˚(10시 10분 0초에서 시작).
- 움직이는 물체와 가만히 있는 물체는 같은 색 원칙(사람은 모두 회색 계열, 얼굴 없음)을 쓴다. 2D 이름표도 모든 물체에 똑같이 붙인다. 결과 표는 ⏸/🏃 아이콘과 글자로 보여 준다.
- 분석: 실험관찰 23쪽 형식 요약 표(장면 × 같은/다른 위치) + 장면별 자세히 보기(지도서와 다르게 기록한 칸 → "🔁 다시 살펴볼까요?", 누르면 그 물체를 골라 실험하기로 감) + 퀴즈 4(q2 "빠르게" 오답 피드백은 `wrongBy`로).
- 안전 약속(가치·태도 목표): 실험하기 패널에 5개 확인 표시 카드. 결과에 `safetyChecked`로 남긴다.
- 다루지 않는 말(처음/나중 위치, 좌표평면, 기준점, 이동 거리, 걸린 시간, 속력)은 화면에 없다(grep 확인). `innerHTML` 안 씀.

## 3. spec과 다른 점

1. **사진 2의 시점**: spec §3.2는 "그 순간의 카메라 시점". 학생이 5초 동안 화면을 돌리면 가만히 있는 물체도 사진 속 자리가 달라져 비교가 틀려지므로, 사진 2는 **사진 1과 같은 시점**(삼각대처럼)에서 찍는다. 기다리는 동안에는 자유롭게 돌려 볼 수 있다. 고른 물체가 화면 밖이면 처음 방향으로 돌아와서 사진 1을 찍는다.
2. **조건이 2개**(장면 + 물체): spec §5 예시는 factor 1개였으나, 틀의 단계 잠금·진행률을 그대로 쓰려고 장면을 조건으로 두었다. 기록 형식은 `{ scene, object, result, recordedAt }`(+ 키용 `objId`, 틀이 붙이는 `phase`).
3. **미니 표 대신 "기록한 물체 한눈에 보기"**: 장면마다 물체 수가 달라(7·11·8) 틀의 행×열 미니 표를 못 써서 앱에서 칩 목록으로 그렸다.
4. 분석 q3 문장을 "놀이터에 굴러가는 공, 축구 골대, 미끄럼틀, 나무가 있어요. 이 가운데 운동하는 물체는 무엇인가요?"로 바꿨다(보기·정답 같음). 정답 피드백 앞의 "맞아요!"는 틀이 "⭕ 맞았어요!"를 붙여서 뺐다.
5. 장면 출처 표기: 교실 안은 학생이 보는 쪽수로 "교과서 38쪽 교실 관찰 활동"이라 썼다(spec 표의 근거는 지도서 188·194쪽).
6. 사람·작은 물체는 넓은 장면에서도 보이도록 1.3배 키웠다(모형 안내에 포함). 움직이는 물체가 5초 동안 가는 거리는 모형이다(spec 열린 질문 3).

## 5. 확인한 것 (개발 서버 `localhost:3000/class1/apps/sci-6-1-2-1/`, 내 탭만 씀)

- 1024×768: 예상하기(5글자 미만 막힘) → 교실 안 7 → 바닷가 11 → 공원 8 기록(26칸, 실제 5초 × 26). 장면을 마치면 다음 장면이 열리고 첫 물체가 골라짐. 화분·개를 일부러 틀리게 기록 → 분석에 "다시 살펴보면 좋은 물체 2개" → 🔁 누르면 실험하기에서 그 물체가 골라짐.
- 사진: 3D는 560px JPEG 2장 + 확대 2장. 시곗바늘 확대에서 초침 30˚ 차이, 비행기·갈매기는 사진 2 확대에 없음(다른 위치), 등대는 같은 자리.
- 퀴즈 4개(오답·`wrongBy`·정답 피드백), 정리 3개 모범 답안, 궁금한 점, 마치기 → 가짜 저장 detail(predict, records 26, analysis, conclusion, extension, curiosity, safetyChecked), 약 2.5천 자.
- 768×1024 세로 + 다크모드: 실행하면 3D가 머리말 바로 아래(127px)로 스크롤되고 카운트다운·움직임이 화면 안에서 보임. 사진 카드 정상.
- 375×812: 모든 단계에서 `scrollWidth = 375`, 화면 밖으로 나가는 요소 없음. 휴대폰 3D에서 카운트다운 표시.
- `?no3d=1`: 2D 그림(교실·바닷가·공원), 5초 움직임, SVG 사진 1·2 + 확대. 3D 버튼 비활성 안내.
- 3D↔2D 13회 전환 → 캔버스 1개, `isContextLost() = false`.
- 새로고침 복원: 단계·예상·기록·선택(장면·물체)·장면 시간·보기 방식. "처음부터 다시 하기"는 이 앱 키만 지움.
- 콘솔 오류 0. 끝난 뒤 내 앱 localStorage 키만 지우고 탭을 닫았다. 스크래치 파일·임시 서버는 지웠다.

## 6. 못 한 것 / 알려진 제한

- 실제 터치 기기의 핀치·드래그는 확인하지 못했다. 공유 브라우저 창에서 백그라운드일 때는 3D 트윈이 바로 끝나서(틀의 기존 동작) 움직임은 앞 탭일 때만 눈으로 확인했다. 초시계는 백그라운드에서도 실제 5초였다.

- spec 힌트 3(팔만 흔든 친구 vs 걸어간 친구)과 발전 질문 2(팔을 흔드는 준비 자세)는 소재가 비슷하다. 둘 다 승인된 spec 문장 그대로 두었다. Review 단계에서 볼 만하다.
