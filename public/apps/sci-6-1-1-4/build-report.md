## 2. spec과 다른 점 / 구현 결정

1. **조건 축이 2개**: 공통 틀의 `phases.cells`는 조건 값으로 단계를 구분하므로 spec §5 예시(조건 `drops` 하나)로는 A·B 칸이 겹친다. 조건 ① "시작 용액"(첫째 줄 묽은 염산 / 넷째 줄 묽은 수산화 나트륨 용액, B는 A 6칸 기록 후 열림) + ② "넣는 방울 수"로 만들었다. 기록 형식은 spec 그대로 `{phase, drops, colorFamily, recordedAt}`.
2. **칸 색(모형)**: spec은 "0→25방울 선형 보간"이었으나, 지도서 144쪽 **실험관찰 결과 예시 그림**(A: 붉은색·진분홍·자홍·초록·연두·연두빛 노랑 / B: 노랑·연두·초록·자홍·진분홍·붉은색)을 직접 확인해 이를 본떴다. 모든 색은 145쪽 "붉은 양배추 용액의 색깔 변화표"(산성이 강함 ↔ 염기성이 강함) 그러데이션 위의 자리로 정한다. 0방울 끝값은 spec 헥스(`#d23a57`, `#e7c52c`)와 똑같다. 방울을 넣는 동안 색은 이 경로를 따라 방울 수마다 바뀐다. 중간 칸 색 이름은 화면에 쓰지 않는다.
3. **정오 판정**: spec대로 0방울·25방울 칸만 판정한다(A0 붉은색 / A25 푸른색이나 노란색 / B0 푸른색이나 노란색 / B25 붉은색 계열). 틀리면 표에 "🔁 다시 실험해 볼까요?"가 나온다. 중간 칸은 판정하지 않는다.
4. **색만으로 전달하지 않기**: 관찰 카드의 "🎨 색 구별이 어려우면" 버튼을 누르면 색깔 변화표 위에 처음·넣은 뒤 자리를 ▲ 글자 표시로 보여 준다. 결과 표는 색 칩 + 고른 계열 글자로 나타낸다.
5. **분석 단계 추가 자료**: 결과 표 아래에 "색깔 변화표와 비교하기"(145쪽 5단계, 실험관찰 13쪽)와 A·B 줄 방울 수별 색 흐름(→)을 넣었다. spec §3.3의 화살표 아이디어를 구현한 것이다.
6. **3D 배치**: 기구(묽은 염산·묽은 수산화 나트륨 용액 점적병, 붉은 양배추 용액, 색연필 통)를 홈판 뒤쪽에 한 줄로 두었다(spec: 왼쪽·오른쪽). 이렇게 해야 세로 화면에서도 장면이 화면 안에 들어온다. 첫째 줄이 앞쪽이다. 둘째·셋째 줄은 흐리게 표시하고 "쓰지 않음" 라벨을 붙였다. 방울 수는 화면 위 숫자 카운터로 세고, 떨어지는 방울은 최대 5~6개만 그린다.
7. **예상 정리 보충**: 140쪽 지도 길잡이 5의 "진하기가 같은 두 용액을 섞으면 더 많이 넣은 용액의 성질"을 결론 비교 도움말에 넣었다.
8. 퀴즈 보기 순서를 바꿔 정답 위치를 섞었다. 보기별 피드백(`wrongBy`)에서 "곧바로 뒤바뀐다" 오개념을 다룬다.

## 3. 확인한 것 (`python3 -m http.server`로 띄운 정적 서버, `index.html`)

- 1024×768 가로: 예상하기(5글자 미만이면 다음 단계로 못 감 확인) → 실험 A 6칸(A25를 일부러 틀리게 기록) → B 잠금 알림 → B 6칸 → 분석 표에서 A25 플래그 확인 → 🔁 누르면 실험하기로 가서 그 칸이 골라짐 → 다시 기록하면 플래그 사라짐 → 퀴즈 4문항(오답 피드백·wrongBy 확인) → 정리 3문항 모범 답안 → 궁금한 점 → 마치기.
- 3D 실제 시간: 첫 칸(줄 준비 포함, 25방울) 약 11초, 준비된 줄에서는 2.5~6초. 방울 카운터와 색 변화도 확인했다.
- 768×1024 세로 + 다크모드: 실행하면 3D가 머리말 바로 아래(127px)에 오고 애니메이션이 화면 안에서 진행된다. 가로 스크롤 없음.
- 375×812: 모든 단계에서 `scrollWidth = 375`, 화면 밖으로 나가는 요소 없음(표·2D 홈판은 자체 스크롤). 휴대폰 3D에서 실행·카운터 동작.
- `?no3d=1`: 2D 홈판으로 실험·기록·방울 카운터 동작, 3D 버튼 비활성 안내.
- 3D↔2D 20회 왕복 → 캔버스 1개, `isContextLost()=false`.
- 새로고침 복원: 단계·예상·기록·퀴즈·정리·궁금한 점·홈판(3D 장면 다시 그림).
- "처음부터 다시 하기" → 임시 저장 초기화.
- 저장: `Class1Record.save`를 가짜로 바꿔 확인했다. detail 키(predict, records 12, analysis, conclusion, extension, curiosity)와 약 1.5천 자 크기, 성공 문구, `not_logged_in`일 때 로그인 안내가 맞게 나온다. 실 DB 요청은 없다.
- 콘솔 오류 0, 자원 404 0. 화면 문구에 중성·pH·중화·몰 농도 없음. `innerHTML` 사용 없음(학생 입력은 textContent).
