## 만든 것(요약)
- **예상하기**: spec 질문 1개를 직접 입력(5글자 이상). 힌트 2개는 한 단계씩 열리며, 답("각이 클수록 밝다")을 말하지 않음.
- **실험하기**:
  - 3D 장면(모형): 어두운 교실 책상 위에 화면이 위를 향한 스마트 기기가 있고, 센서와 빨판 막대(5 cm)가 있다. LED 손전등은 센서에서 **늘 20 cm** 떨어져 있다. 반투명 빛줄기, 빛 자국 타원(넓이 ∝ 1/sin, 밝기 ∝ sin), 막대 그림자, 각도 호와 "○°" 표시, "20.0 cm (늘 같음)" 표시가 있다. 드래그로 돌리고, 두 번 탭하면 처음 방향으로 돌아간다. 오른쪽 위의 "📱 조도 측정 앱(모형)" 화면에 빛의 세기가 바로 나온다.
  - **각도 슬라이더**: `<input type=range>`, 10°~90°, 1° 단위. 손잡이는 44px이고 `aria-valuetext`로 "45도, 빛의 세기 707, 그림자 길이 5.0 cm"처럼 읽힌다. 터치 드래그·마우스·키보드(←/→)로 움직인다. 슬라이더 위에 **30°(그림자가 길 때)·80°(그림자가 짧을 때)** 눈금 버튼이 있어 누르면 그 각도로 맞춰진다. 양 끝에는 ◀/▶(1°씩) 버튼이 있다. 끄는 동안의 3D·값 갱신은 `requestAnimationFrame` 한 번으로 묶었다.
  - 3D 캔버스와 슬라이더는 서로 다른 요소라 드래그가 섞이지 않는다. 슬라이더는 `touch-action: pan-y`라 세로로 밀면 페이지가 스크롤된다.
  - 값 패널(각도·빛의 세기·그림자 길이)에 값이 바로 보이고 학생은 **타이핑하지 않는다**. **"📝 ○° 기록하기"**로 저장한다. 필수는 30°·80°이고, 다른 각도는 6개까지 더 기록할 수 있다(넘으면 버튼이 꺼지고 안내가 나옴. 추가 기록은 "✕ 지우기"로 지울 수 있음). 같은 각도를 다시 기록하면 덮어쓴다.
  - 30°·80°를 모두 기록해야 다음 단계로 간다. 막히면 "(기록함 n/2)"을 알려 준다.
- **기록·분석하기**: 기록한 모든 각도의 표(각도·그림자 길이·빛의 세기)와 꺾은선그래프(x축 각도 0~90°, y축 빛의 세기, 각도 순으로 이음, 점 옆에 값)를 그린다. 분석 1(30°와 80° 중 더 밝은 쪽)은 **내 기록으로 채점**하고, 분석 2(관계)는 spec 보기와 오답 피드백 그대로다.
- **정리하기**: 결론 1개(146쪽 평가 문항)를 제출하면 모범 답안과 비교한다. 이어서 궁금한 점(선택 한 줄)과 "학습 마치기"가 나온다. 발전 질문은 없다.
- **공통 틀 연결**: 로그인 필수 가림막, `app_progress` 자동 저장·이어서 하기, 로그아웃 삭제, 완료 저장은 모두 공통 틀 그대로다. 로컬 저장은 모두 `store`로 한다(localStorage 직접 사용 없음). 완료 detail 키는 `predict, records[{angleDeg, shadowCm, reading, required}], analysis, conclusion, curiosity, qa`이고, `qa` = predict/q1(text), experiment/records(table), analyze/q1·q2(choice), conclude/conclusion(text), conclude/curiosity(text)다. 크기는 약 2.3천 자다.

## spec과 다른 점 / 판단한 점
1. **공통 틀 `experiment.js`를 쓰지 않음**: 이 틀은 "조건 버튼 고르기 → 실행 → 관찰 카드 → 기록" 흐름이라 "슬라이더로 실시간 살펴보고 바로 기록"(개정 1)과 맞지 않는다. 그래서 실험 화면은 `app.js`가 만들었다. 공통 CSS 클래스(`ss-exp-layout`, `ss-exp-view`, `ss-view-badge` 등)는 그대로 쓰고, 3D↔2D 전환·늦은 3D 생성 버리기·렌더러 해제·컨텍스트 손실 시 2D 전환은 틀과 같은 방식으로 옮겼다. 공통 틀 파일은 고치지 않았다.
2. 기록은 `RecordStore` 대신 `store`의 `"records"` 배열(각도마다 1개)로 관리한다. `RecordStore`에는 지우기 기능이 없어서다.
3. 본문 §3.2의 "측정하기 → 숫자가 0에서 올라감"과 "확인 입력"은 개정 1(실시간, 타이핑 없음)을 따라 없앴다.
4. 그래프는 개정 1대로 막대그래프 대신 꺾은선그래프다. 분석 1 질문은 "내 기록표에서 30°와 80°를 비교해 보세요. …"로 비교 대상을 밝혔다(보기·채점은 spec과 같음).
5. 모형 안내 문구: "🔧 모형: 빛의 세기는 실제 조도 측정 앱 숫자를 흉내 낸 값이에요. 그림자 길이는 빛이 나란하게 들어온다고 보고 계산했어요." 3D 화면에는 "모형" 배지와 "조도 측정 앱(모형)" 표시가 있다. 3D 그림의 그림자는 빛 자국 밖(책상 위)까지 이어서 그렸다. 실제 LED 손전등도 주변을 흐리게 비추므로 그렇게 단순화했다.
6. 학생 화면에 "지도서"는 나오지 않는다(주석에만 있음). 자전축·공전은 언급하지 않는다.
7. 처음 슬라이더 위치는 45°(기록할 필요 없는 각도)다. 학생이 직접 30°·80°로 옮기게 했다.

## 검증(자기 전용 headless Chrome, CDP 포트 9724~9727, 임시 프로필)
- 개발 서버 `http://localhost:3000/class1/apps/sci-6-2-1-4/index.html`을 썼다. `*.supabase.co` 요청은 모두 가로채 메모리 가짜 응답으로 처리했다(가짜 세션). **실제 DB 요청은 0건**이다. 공유 브라우저 탭은 쓰지 않았고 `localStorage.clear()`도 쓰지 않았다.
- 끝까지 진행한 조합은 태블릿 가로 1024×768(3D), 세로 768×1024(3D), 휴대폰 375×812(다크·터치 3D), `?no3d=1`(2D)이다. 네 경우 모두 결과는 아래와 같다.
  - **콘솔 오류·경고 0**, **가로 스크롤 0**(모든 단계)
  - 3D↔2D 4번 전환 뒤에도 캔버스 1개, 값은 그대로
  - 새로고침하면 실험 단계, 슬라이더 각도(57°), 기록 7개, 조도 값이 복원됨. 마친 뒤 새로고침하면 정리 단계, 완료 카드, 4단계 완료 표시가 복원됨. 앞 단계(실험)로 돌아가면 기록이 그대로 있음
  - 키보드: 45°에서 → → ← ← ←를 누르면 44°. 마우스 끌기 35°→65° 구간이 슬라이더에 반영됨. 휴대폰 터치 끌기 반영됨
  - 30°·80° 눈금 버튼 → 기록하기 → "🎉 30°와 80°를 모두 기록했어요!" 알림. 추가 기록 7번을 시도하면 6개에서 막히고, 1개를 지우면 다시 가능
  - 분석 오답 피드백(30° 고름, "관계없다" 고름)과 정답 피드백 확인. 마치기를 누르면 `app_results` POST(`completed: true`)
  - 비로그인이면 "🔒 로그인이 필요해요" 가림막이 뜸
- 레이아웃:
  - 세로 768×1024: 실험 화면을 머리말 바로 아래로 올리면 슬라이더·값 패널·기록 버튼이 함께 보인다(기록 버튼 아래 끝 953px, 아래 이동 막대 시작 955px). 이를 위해 세로 태블릿의 3D 높이를 `min(36vh, 440px)`로 줄였다.
  - 휴대폰 375에서는 기록 버튼까지 조금 스크롤해야 한다. 휴대폰에서는 3D 이름표 중 "스마트 기기 화면(지표면)"을 숨기고 손전등·거리·각도 이름표를 키웠다.
- 3D 장면을 10°·30°·45°·80°·90°에서 캡처해 확인했다: 각이 작을수록 빛 자국이 넓고 흐리며 그림자가 길고, 각이 클수록 빛 자국이 좁고 진하며 그림자가 짧다. 이름표가 조도 앱 화면과 겹치지 않는다(손전등을 세우면 이름표가 왼쪽으로 감). 2D도 같은 각도에서 확인했다.
