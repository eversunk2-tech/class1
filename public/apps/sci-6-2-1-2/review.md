## 4. 기능·UI 확인

* 시간 바: 마우스로 끌기(9:30 → 11:47), ±3분 안에서 놓으면 눈금에 맞춤(12:32 → 12:30), 터치 끌기(375 모바일 에뮬레이션, 끄는 동안 페이지 스크롤 없음), 키보드 ←/→·PageUp/PageDown·Home/End, 끝값 8:30·15:30을 넘지 않음. 손잡이 44 px, 눈금 버튼 52×48 px(375에서는 두 줄로 엇갈려 겹침 0).
* 3D 드래그와 슬라이더 간섭: 3D 캔버스를 끌면 시각은 그대로이고 시점만 바뀐다. 시간 바를 위아래로 비스듬히 끌어도 3D 시점은 그대로다(화면 해시 비교).
* 3D↔2D 6번 전환: 캔버스 0↔1개(쌓이지 않음), 시계·시간 바 중복 없음. `?no3d=1`은 2D로 시작하고 캔버스 0개.
* 다시 하기·앞 단계: 정리하기 → 실험하기로 돌아가 10:30을 "🔁 다시 기록"함(같은 값으로 덮어씀).
* 화면 크기: 1024×768(장면·시간 바·기록 버튼이 한 화면에 들어옴), 768×1024 3D(한 화면), 768×1024 2D(문제 1), 375×812 다크(가로 스크롤 0, 문제 2). 다크모드에서 2D SVG는 밝은 바탕을 그대로 쓰지만 글자가 잘 보임.
* 콘솔 오류·예외: 앱에서는 0건(내 정적 서버의 favicon 404 1건은 테스트 환경 탓).

실험하기가 8칸으로 늘었지만 한 칸에 10초 안팎이라 시간 부담은 작다. 느린 학생이 7분을 넘는 부분은 예상·결론 서술이라 구조를 바꿀 필요는 크지 않다(이전 앱 6-1-2-5와 같은 수준).

## 6. 확인한 것 vs 못 한 것

**확인함**(자기 전용 headless Chrome, 포트 9362 + 자기 정적 서버 127.0.0.1:8762, Supabase 요청은 CDP로 모두 가로채 메모리 가짜 응답. Supabase 도메인은 `--host-resolver-rules`로 막아 실 DB 요청 0건. 공유 브라우저·다른 탭·개발 서버는 쓰지 않았고, 끝난 뒤 서버·브라우저를 종료함)
* 위 1~5절의 모든 항목: 전체 흐름, 값 일치(8칸 + 421분 전수), 저장·복원·로그아웃 삭제·완료 payload, 3D/2D 장면(스크린숏 1024·768·375, 라이트·다크), 접근성 속성.
* 지도서 120~135쪽 원문 대조, 태양 위치 천문 계산 검산.

**못 함**
* 실제 iPad·태블릿 터치 감도, 실제 GPU에서의 3D 성능·글자 선명도.
* 실제 로그인, 실제 `app_progress`/`app_results` 저장(RLS), 두 학생 계정 전환, "처음부터 다시 하기"(공통 틀 기능).
* 관리자 "학생 응답" 화면 표시(`src/data/app-responses/` 매핑 없음, Embed 단계에서 처리할 일).
* 실제 학생 소요 시간(위 표는 추정).
* 8:30 기온 19.5 °C의 실제 관측값(사용자 확인 필요).
