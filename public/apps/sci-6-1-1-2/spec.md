## 1. 지도서 분석

### 1.1 차시 개요 (지도서 118쪽)
- 학습 목표
  1. 지시약을 이용하여 용액을 산성 용액과 염기성 용액으로 분류할 수 있다.
  2. 붉은 양배추 용액을 이용하여 여러 가지 용액을 산성 용액과 염기성 용액으로 분류할 수 있다.
- 성취기준 `[6과09-01]` 여러 가지 용액에 지시약을 넣었을 때의 변화를 관찰하여 용액을 산성 용액과 염기성 용액으로 분류할 수 있다. (지도서 120, 129쪽)
- 이 차시는 사실상 **두 개의 탐구 활동**으로 구성된다.
  - 탐구 활동 A: 리트머스 시험지 + 페놀프탈레인 용액으로 용액 분류하기 (지도서 118~120, 122~123, 124~125쪽 / 실험관찰 8~9쪽)
  - 탐구 활동 B: 붉은 양배추 용액으로 용액 분류하기 (지도서 121, 126, 128쪽 / 실험관찰 10쪽)
  - 두 활동은 **같은 실험 도움판 ①·같은 24홈판**을 함께 쓰고(지도서 121쪽 "실험 도움판 ①은 두 개의 탐구 활동에서 모두 사용"), 홈판에서 리트머스·페놀프탈레인 넣는 칸과 붉은 양배추 용액 넣는 칸이 구역별로 나뉘어 있다.

### 1.2 준비물 (지도서 118, 108쪽 단원 지도 계획)
- 모둠: 점적병에 담긴 여섯 가지 용액(식초, 레몬즙, 빨랫비누 물, 석회수, 묽은 염산, 묽은 수산화 나트륨 용액), 24홈판, 실험 도움판 ①(실험관찰 71쪽), 푸른색 리트머스 시험지, 붉은색 리트머스 시험지, 페놀프탈레인 용액, 붉은 양배추 용액, 핀셋, 가위
- 개인: 실험복, 보안경, 실험용 장갑
- 안전(지도서 118, 121쪽): 실험복·보안경·실험용 장갑 필수, 유리 기구 주의, 용액이 피부/눈에 닿으면 흐르는 물로 충분히 씻기, 묽은 염산은 냄새를 맡지 않음(자극성), 임의로 맛보거나 냄새 맡지 않음, 실험 후 지정된 곳에 폐기(석회수→무기계, 묽은 염산→산, 묽은 수산화 나트륨 용액→알칼리계 폐수통, 121쪽).

### 1.3 지시약별 정확한 색 변화표 (반드시 이 값만 사용)

**출처: 지도서 118, 120, 122~123, 124, 126, 128쪽 / 교과서·실험관찰 원문 표**

| 용액 | 성질(지도서 표기) | 푸른색 리트머스 시험지 | 붉은색 리트머스 시험지 | 페놀프탈레인 용액 | 붉은 양배추 용액 |
|---|---|---|---|---|---|
| 식초 | 산성 | 붉은색으로 변함 | 변화 없음 | 변화 없음 | 붉은색 |
| 레몬즙 | 산성 | 붉은색으로 변함 | 변화 없음 | 변화 없음 | 붉은색 |
| 묽은 염산 | 산성 | 붉은색으로 변함 | 변화 없음 | 변화 없음 | 붉은색 |
| 빨랫비누 물 | 염기성 | 변화 없음 | 푸른색으로 변함 | 붉은색으로 변함 | 푸른색 |
| 석회수 | 염기성 | 변화 없음 | 푸른색으로 변함 | 붉은색으로 변함 | 푸른색 |
| 묽은 수산화 나트륨 용액 | 염기성 | 변화 없음 | 푸른색으로 변함 | 붉은색으로 변함 | **노란색** |

- 붉은 양배추 용액 결과는 지도서 121, 126, 128쪽에 걸쳐 3번 반복 확인된 값이며, 128쪽 평가 문항의 정답과도 일치한다. **묽은 수산화 나트륨 용액만 노란색**이고 나머지 두 염기성 용액(빨랫비누 물, 석회수)은 푸른색이다 — 앱에서 "염기성 = 무조건 푸른색"으로 단순화하지 않는다.
- 일반 규칙(지도서 121쪽 정리): "붉은 양배추 용액은 산성 용액에서는 **붉은색 계열**, 염기성 용액에서는 **푸른색이나 노란색 계열**로 변한다." 붉은 양배추 용액 색은 농도·만든 시기에 따라 달라질 수 있어(지도서 121, 122, 126쪽) 지도서는 "계열"로 뭉뚱그려 표현한다. 앱에서는 표의 6가지 값(정확한 개별 색)을 기본 판정 기준으로 쓰고, 계열 설명은 보충 텍스트로만 둔다.
- 페놀프탈레인 용액 보충 자료(지도서 123쪽): pH 8~10 정도인 염기성 용액에서 붉은색으로 변하며, 아주 약하거나 아주 강한 염기성 용액에서는 반응하지 않을 수 있다. **단, 지도서 106쪽 "단원 지도상의 유의점"에 pH·중성·중화 개념은 이 단원에서 다루지 않는다고 명시** → 앱 화면에도 pH 수치·중화를 등장시키지 않는다(과학적 배경 지식은 Plan 문서에만 남긴다).
- 안토사이아닌(지도서 127쪽 보충 자료): 붉은 양배추 색소로, 산성에서 자주색·빨간색 등, 염기성에서 파란색·초록색·노란색 등을 띤다는 일반 설명. 앱에서 6가지 용액 밖의 값을 함부로 만들어내지 않는다.

### 1.4 탐구 과정 단계 (지도서 118~121쪽)
1. (도입) 색깔 없고 투명한 용액을 어떻게 분류할지 생각하기 → 지시약 개념 도입.
2. [탐구 A] 실험 도움판 ①에 24홈판을 올리고 6가지 용액을 각 홈에 넣는다.
3. 푸른색·붉은색 리트머스 시험지를 반으로 잘라 핀셋으로 각 홈에 넣고 색 변화 관찰·기록.
4. 페놀프탈레인 용액을 각 홈에 1~2방울 떨어뜨리고 색 변화 관찰·기록.
5. 리트머스·페놀프탈레인 결과로 용액을 산성/염기성으로 분류하고, 두 지시약의 분류 결과가 같음을 확인.
6. [탐구 B] 같은 실험 도움판의 붉은 양배추 용액 칸에 6가지 용액을 넣고, 붉은 양배추 용액을 다섯 방울씩 떨어뜨려 색 변화 관찰·기록.
7. 탐구 A·B 결과를 비교하여 같은 분류 결과가 나옴을 확인.
8. 정리: 지시약을 이용한 분류 방법을 말로 설명, 산성/염기성 용액의 주변 예 이야기하기(지도서 124쪽: 산성 — 묽은 염산·오렌지주스·구연산 용액·콜라·식초·탄산수; 염기성 — 묽은 수산화 나트륨 용액·욕실 청소용 표백제·하수구 세정제·제빵 소다 용액·손 세정제).

### 1.5 지도상 유의점 (지도서 118~123, 126쪽)
- 실험 도움판 ①은 두 탐구에서 공용이므로, 해당 실험에 쓰는 칸에만 용액을 넣도록 안내(121쪽).
- 각 홈에 용액을 넣을 때 다른 홈과 섞이지 않도록 주의(118, 120, 122, 126쪽 반복).
- 리트머스 시험지는 미리 반으로 잘라 둘 수 있음(124쪽).
- 페놀프탈레인은 홈판 가까이에서 떨어뜨려 튀지 않게(120쪽).
- 지시약 색은 용액의 **농도**에 따라 진하기가 다를 수 있어 "비슷한 계열의 색"으로 판단하도록 지도(120, 122, 126쪽) — 앱의 판정은 정확한 표값으로 채점하되, 학생에게 보여주는 색 애니메이션은 "계열"이라는 문구로 힌트를 줄 수 있다.
- 리트머스 2종 + 페놀프탈레인의 분류 결과가 서로 다른 색으로 나타나지만 **분류 결과(산성/염기성 묶음)는 항상 같다**는 것을 이해하도록 지도(120쪽) — 분석 퀴즈에 반영.

### 1.6 오개념
- 지도서 118~129쪽(이 차시) 범위에는 별도의 "오개념" 박스가 없다. (오개념 박스는 앞 차시인 "여러 가지 용액을 분류해 볼까?" 114쪽에 "투명한 용액은 색깔이 없다"로 등장하며 이 차시 범위 밖이다.)
- 이 차시와 관련해 지도서가 명시적으로 경계하는 오해는 "지시약마다 색이 다르게 변하니 결과도 다르다"이다(1.5 참고) → 정리하기 분석 질문에서 다룬다.

### 1.7 평가 (지도서 119, 129쪽)
- 평가 목표: [지식·이해] 지시약을 넣었을 때 색깔 변화를 설명할 수 있다 / [과정·기능] 지시약으로 산성·염기성 용액을 분류할 수 있다 / [가치·태도] 흥미를 갖고 참여하는 태도.
- 지도서 129쪽 평가 기준표(상/중/하)를 참고해 "기록·분석하기" 단계 분석 질문 채점 기준의 톤을 맞춘다(모든 항목을 옳게 → 상, 일부만 → 중, 대부분 틀림 → 하에 해당하는 피드백 문구).
- 실험관찰 128쪽 평가 문항 3개(색깔 표 빈칸 채우기, 레몬즙+붉은양배추 예측과 까닭, 6용액 분류)를 "기록·분석하기"의 분석 퀴즈 소재로 활용할 수 있다(문항 그대로 베끼지 않고 형식만 참고, 보기형으로 각색).

## 2. 앱 종류 판단

**실험 시뮬레이션 앱**으로 만든다.
- 근거: 지도서 118~129쪽 전체가 "실험해요 → 정리해요 → 결론 도출 및 적용"으로 구성된 두 개의 정식 탐구 활동(위 1.4)이며, 실제 교실에서도 점적병·24홈판·리트머스 시험지·페놀프탈레인 용액·붉은 양배추 용액을 사용하는 손 실험이다. "조사하기" 차시가 아니다.

## 3. 화면 설계 (예상하기 → 실험하기 → 기록·분석하기 → 정리하기 → 궁금한 점)

### 3.0 공통 전제
- 6가지 용액(식초, 레몬즙, 빨랫비누 물, 석회수, 묽은 염산, 묽은 수산화 나트륨 용액) × 3가지 지시약(푸른색 리트머스, 붉은색 리트머스, 페놀프탈레인) + 붉은 양배추 용액 비교 실험. 총 24개 "용액×지시약" 조합(6×4)이 있지만, 지도서 구성을 따라 **탐구 A(리트머스 2종 + 페놀프탈레인)를 먼저, 탐구 B(붉은 양배추 용액)를 이어서** 진행한다.
- 색은 1.3의 표 값만 사용한다. UI 문구·툴팁에도 "노란색은 묽은 수산화 나트륨 용액만 해당" 등 표에 없는 임의 색을 만들지 않는다.

### 3.1 예상하기
- 질문 1: "색깔도 없고 투명해서 눈으로 구별할 수 없는 두 용액(예: 석회수, 묽은 염산)을 어떻게 구별할 수 있을까요?" → 서술형 입력.
- 질문 2: "지시약을 여섯 가지 용액에 각각 넣으면 지시약의 색깔이 용액마다 같게 변할까요, 다르게 변할까요? 그렇게 생각한 까닭도 적어 보세요." → 서술형 입력.
- 힌트 버튼(단계적, 답을 직접 주지 않음):
  1. "지도서 앞 차시에서 색깔·투명도로 분류했던 것 기억나나요? 그 방법이 통하지 않는 용액들이 있었죠."
  2. "어떤 물질은 다른 물질을 만나면 색이 변해요. 이런 성질을 가진 물질을 무엇이라고 부를지 생각해 보세요."
  3. (마지막 힌트) "리트머스 시험지를 사용해 본 적 있나요? 색이 변하는 시험지예요."
- 답은 절대 제시하지 않는다. 입력값은 localStorage에 즉시 임시 저장.

### 3.2 실험하기 (3D 장면)
- **장면 구성**: 실험대 위에 24홈판(6용액 × 4지시약 칸 배치, 실험 도움판 ①을 단순화한 모형으로 라벨), 여섯 개의 점적병(라벨: 식초/레몬즙/빨랫비누 물/석회수/묽은 염산/묽은 수산화 나트륨 용액), 리트머스 시험지 통(푸른색/붉은색), 페놀프탈레인 용액병, 붉은 양배추 용액병, 핀셋, 스포이트. three.js로 각 오브젝트를 단순 형태(실린더=점적병, 평판=홈판, 얇은 직사각형=시험지)로 표현하고 "모형" 라벨을 화면에 명시.
- **조작 흐름**:
  1. 용액 선택(6개 중 1개, 버튼 또는 점적병 탭) → 3D에서 점적병이 강조됨.
  2. 지시약 선택(리트머스-파랑/리트머스-빨강/페놀프탈레인/붉은 양배추 용액 중 1개, 탐구 B는 탐구 A를 마친 뒤 잠금 해제) → 해당 지시약 오브젝트 강조.
  3. "떨어뜨리기/적시기" 버튼 → 애니메이션: 시험지는 홈에 담그는 모션, 액체 지시약은 스포이트로 1~2방울 떨어지는 모션 → 홈 안 색이 1.3의 표값으로 서서히 바뀐다(트랜지션 0.6~1초).
  4. "기록" 버튼으로 현재 조합(용액, 지시약, 관찰된 색)을 기록 목록에 저장. 같은 조합을 다시 실험하면 마지막 기록으로 덮어쓴다(같은 셀 중복 방지).
- **관찰 항목**: 용액명, 지시약명, 색 변화 결과(문자열, 표값과 동일 어휘 사용: "붉은색으로 변함" / "변화 없음" / "푸른색으로 변함" / "노란색" / "붉은색" / "푸른색" — 탐구 A는 "~으로 변함/변화 없음" 표현, 탐구 B는 색 이름만 쓰는 지도서 표기를 그대로 따른다).
- **카메라 조작**: three.js `OrbitControls`, 터치 1-드래그 회전, 2-핑거 핀치 확대/축소, 더블탭으로 초기 각도 복귀.
- **기록 데이터 형식(예시)**:
```json
{
  "phase": "A",            // "A" | "B"
  "solution": "식초",
  "indicator": "붉은색리트머스",  // 리트머스파랑 | 리트머스빨강 | 페놀프탈레인 | 붉은양배추
  "result": "변화 없음",
  "recordedAt": 1737350000000
}
```
- 탐구 A는 6용액 × 3지시약 = 18칸, 탐구 B는 6용액 × 1지시약 = 6칸을 모두 기록해야 "기록·분석하기"로 진행 가능(진행률 표시).

### 3.3 기록·분석하기
- **자동 생성 표**: 용액(행) × 지시약(열, 4개) 매트릭스. 학생이 기록한 값을 그대로 채워 넣고, 지도서 표(1.3)와 다르면 "다시 실험해 볼까요?" 안내(정답을 알려주지 않고 재실험 유도) — 정오 판정은 채점용이 아니라 스스로 다시 볼 수 있게 하는 용도.
- 그래프는 이 실험의 성격상(범주형 색 결과) 막대/꺾은선 그래프보다 **표+색상 칩**이 더 적합 → 별도 수치 그래프는 만들지 않고, 표의 각 셀을 실제 관찰색으로 채색한 "색상 매트릭스"를 시각 자료로 쓴다(과학적으로 뜻이 있는 시각화).
- **분석 퀴즈(보기 중 고르기, 지도서 118~129쪽 근거)**:
  1. "페놀프탈레인 용액을 떨어뜨렸을 때 붉은색으로 변하는 용액을 모두 고르세요." → 보기: 식초/레몬즙/빨랫비누 물/석회수/묽은 염산/묽은 수산화 나트륨 용액 (정답: 빨랫비누 물, 석회수, 묽은 수산화 나트륨 용액) — 실험관찰 128쪽 유형 각색.
  2. "붉은 양배추 용액을 레몬즙에 떨어뜨리면 어떤 색 계열로 변할까요?" → 보기: 붉은색 계열 / 푸른색이나 노란색 계열 (정답: 붉은색 계열) — 128쪽 유형.
  3. "리트머스 시험지와 페놀프탈레인 용액은 색이 다르게 변하는데도 분류 결과가 같은 까닭은 무엇일까요?" → 보기: "두 지시약 모두 용액의 산성/염기성이라는 같은 성질에 반응하기 때문" / "우연히 결과가 같게 나온 것" (정답: 전자) — 120쪽 지도 길잡이 근거.
  - 각 문항 정답/오답에 따라 지도서 문구를 바탕으로 한 짧은 피드백 제공(예: 오답 시 "다시 표를 살펴볼까요? 염기성 용액에서 페놀프탈레인은 어떻게 변했나요?").

### 3.4 정리하기
- 결론 질문: "지시약을 이용하면 왜 눈으로 구별하기 어려운 용액도 분류할 수 있을까요? 자신의 말로 정리해 보세요." → 서술형 입력 후 모범 답안 표시: "지시약은 산성 용액과 염기성 용액에서 서로 다른 색깔을 나타내는 물질이기 때문에, 지시약의 색깔 변화를 관찰하면 눈으로 구별하기 어려운 용액도 산성 용액과 염기성 용액으로 분류할 수 있습니다."(지도서 118, 129쪽 근거 요약) → 학생 답과 나란히 비교 표시.
- 발전 질문 1: "우리 주변에서 산성 용액이나 염기성 용액을 이용하는 예를 한 가지씩 적어 보세요." → 모범 답안: 지도서 124쪽 — 산성: 묽은 염산·오렌지주스·구연산 용액·콜라·식초·탄산수 / 염기성: 묽은 수산화 나트륨 용액·욕실 청소용 표백제·하수구 세정제·제빵 소다 용액·손 세정제 중 예시.
- 발전 질문 2: "붉은 양배추 용액처럼 색깔이 변하는 다른 식물(재료)을 알고 있거나 예상해 보세요." → 모범 답안: 지도서 127쪽 보충 자료 — 안토사이아닌은 포도, 비트, 가지 등에도 들어 있어 천연 지시약으로 쓸 수 있다.
- "더 탐구하고 싶은 점(또는 궁금한 점)" 자유 입력란.

### 3.5 단계 이동 / 저장
- 상단에 4단계 진행 표시(예상하기 → 실험하기 → 기록·분석하기 → 정리하기), 언제든 이전 단계로 돌아가 다시 볼 수 있음. "실험하기"는 언제든 다시 실행 가능(리셋 버튼 — 기록은 유지, 3D 장면만 초기화).
- localStorage 임시 저장 키(예): `sci611sim2:v1:predict`, `sci611sim2:v1:records`, `sci611sim2:v1:analysis`, `sci611sim2:v1:conclusion`, `sci611sim2:v1:curiosity`, `sci611sim2:v1:step` — 접두사 `sci611sim2`는 앱 폴더명(`sci-6-1-1-2`)과 대응.

### 5.2 three.js
- CDN: `https://cdn.jsdelivr.net/npm/three@0.169.0/build/three.module.js` + `three/addons/controls/OrbitControls.js`(동일 버전 경로의 `examples/jsm/controls/OrbitControls.js`), ES 모듈 `<script type="module">`로 로드.
- 버전 고정 + SRI: 빌드 시 `curl -s <src> | openssl dgst -sha384 -binary | openssl base64 -A`로 계산해 `integrity` + `crossorigin="anonymous"` 부여(class1-record.js 예시와 동일 방식). OrbitControls는 importmap으로 같은 버전의 three를 가리키게 한다.
- 터치 드래그: `OrbitControls.enableDamping = true`, 1-포인터 드래그=회전, 핀치=줌, `touchAction: none`으로 스크롤 충돌 방지.

### 5.3 성능(태블릿)
- 저폴리곤 프리미티브(box/cylinder/plane)만 사용, 텍스처 최소화(색은 vertex/material color로 애니메이션).
- `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`, 화면 밖일 때 `requestAnimationFrame` 정지(IntersectionObserver 또는 visibilitychange).
- 3D 없이도 표·질문 단계는 동작해야 하므로 WebGL 미지원 기기용 정적 이미지/설명 폴백 고려(공통 틀 과제로 §6에 기록).

### 5.4 접근성
- 모든 버튼 44px 이상 터치 영역, 색만으로 결과를 구분하지 않고 항상 텍스트 라벨 동반("변화 없음" 등), 명도 대비 WCAG AA 이상, 서술형 입력은 `<textarea>` + 라벨.

### 5.5 class1-record.js 연동
- `Class1Record.init({ url, anonKey, appId: "sci-6-1-1-2" })`.
- 정리하기 완료 시 저장:
```js
Class1Record.save({
  completed: true,
  durationSec: elapsedSeconds,
  detail: {
    predict: { q1, q2 },
    records: recordArray,          // 3.2의 기록 데이터 배열
    analysis: { q1Choice, q2Choice, q3Choice, q1Correct, q2Correct, q3Correct },
    conclusion: studentConclusionText,
    extension: { q1: studentAnswer1, q2: studentAnswer2 },
    curiosity: studentCuriosityText,
  },
});
```
- 로그인하지 않아도 처음부터 끝까지 사용 가능(비로그인 시 정리하기 화면에 `renderLoginHint` 사용).

### 5.6 basePath / 상대경로 규칙
- 모든 리소스 참조는 `./`로 시작(예: `./style.css`, `./science-sim/sim3d.js`). CDN만 절대 URL(https://) 허용.
- 블로그 로그인 페이지 링크는 `class1-record.js`의 `loginUrl()`이 제공하는 `../../login/`을 그대로 사용.

## 6. 공통 틀 설계 (`scripts/templates/science-sim/`)

25개 차시 앱이 공유할 정본. 각 앱은 이 폴더 전체를 복사해 폴더 안에서 자체 완결한다(§5.1 구조와 동일).

| 파일 | 역할 |
|---|---|
| `stage-nav.js` | 4단계(+궁금한 점) 진행바, 단계 전환/뒤로 가기 관리. `LessonConfig.stages` 순서를 읽어 렌더링. |
| `predict.js` | 예상하기 화면 공통 UI: 질문 텍스트·입력창 렌더링, 힌트 버튼(단계적 공개), 입력값 persist 연동. |
| `sim3d.js` | three.js 초기화(씬/카메라/조명/OrbitControls), 오브젝트 로더(점적병·홈판·시험지 등 프리미티브 팩토리), 색 트랜지션 애니메이션 헬퍼, 리사이즈/가시성 최적화. 차시별 3D "장면 배치"는 `lesson-config.js`의 `scene` 객체로 주입. |
| `record-store.js` | 기록 버튼 로직, 기록 배열 관리(중복 셀 덮어쓰기), persist 연동, 진행률 계산. |
| `table-chart.js` | 기록 배열 → 표/색상 매트릭스/필요 시 막대그래프 렌더링(차시마다 표 형태가 다르므로 렌더 방식을 `lesson-config.js`에서 선택: `"matrix"` | `"bar"` | `"line"`). |
| `quiz.js` | 보기 중 고르기 분석 퀴즈 컴포넌트(문항 배열을 `lesson-config.js`에서 주입), 정오 피드백 표시. |
| `conclude.js` | 결론 서술 입력 → 모범 답안 비교, 발전 질문 1~2개 반복 렌더링(질문/모범답안 배열을 `lesson-config.js`에서 주입). |
| `curiosity.js` | "더 탐구하고 싶은 점" 입력 UI. |
| `persist.js` | localStorage 임시 저장 공통 유틸(`get/set/clear`, 키 접두사를 `lesson-config.js`의 `storageKey`로 네임스페이스). |
| `style-common.css` | 단계 공통 레이아웃(태블릿 우선, 큰 버튼, 다크모드 없음 — 웹앱은 별도 톤 유지 가능), science-sim 전용 클래스. |

```js
  chart: { type: "matrix", rows: [...], cols: [...] },
  quiz: { questions: [...] },
  conclude: { conclusionPrompt, modelAnswer, extensions: [...] },
};
```
- 실험이 없는 "조사하기" 차시는 이 틀 대신 별도의 **조사 도우미 앱** 형태(3D/기록 없이: 조사 참고 자료 카드, 조사 팁 목록, 조사 활동지 틀(빈칸 입력 + 로컬 저장), 완료 시 class1-record.js로 detail 저장)를 쓴다 — science-sim과는 별도 정본(`scripts/templates/science-guide/`, 필요 시 후속 Plan에서 설계)으로 분리하고, 이번 spec에서는 뼈대만 언급한다.

## 7. Embed 계획

- `src/data/science-curriculum.ts`의 `Lesson` 타입에 선택 필드 추가: `appId?: string;`(주석: `public/apps/{appId}/`와 대응, 없으면 실험/조사 앱 미제공). `6-1` 단원 1의 `id: "3"` 항목에 `appId: "sci-6-1-1-2"` 추가.
- `findLesson` 등 기존 헬퍼는 변경 없음. 화면(`src/app/science/page.tsx` → `ScienceView` 컴포넌트, `src/components/science/science-view.tsx` 추정 경로)에서 `lesson.appId`가 있으면 "실험 시작" 버튼(또는 카드)을 표시하고, `appHref`와 유사하게 `withBasePath(`/apps/${lesson.appId}/`)`로 새 탭 또는 인앱 이동. `src/data/apps.ts`의 `appHref`를 그대로 재사용하려면 과학 앱도 `WebApp`으로 등록하거나, science 전용의 작은 헬퍼(`scienceAppHref(appId)`)를 하나 추가하는 두 방식 중 Build 단계에서 더 적은 변경으로 되는 쪽을 고른다(열린 질문 참고).
- 이 spec에서는 구현하지 않는다 — Embed는 별도 단계에서 실제 컴포넌트를 확인한 뒤 진행한다.

## 8. 열린 질문 (추천안 포함)

1. **Embed 시 과학 앱을 `apps.ts`의 `webApps`(메인 페이지 카드)에도 노출할지?**
   추천: 아니오. 메인 페이지 카드는 독립 웹앱 포트폴리오용이고, 과학 실험 앱은 `science-curriculum.ts`를 통해 차시 화면에서만 접근하는 것이 자연스럽다. 필요하면 나중에 별도로 추가.
2. **웹GL을 지원하지 않는 오래된 태블릿 대비 폴백을 이번 시범 앱에도 넣을지, 공통 틀에서만 다룰지?**
   추천: 시범 앱(`sci-6-1-1-2`)에서 최소한의 폴백(정적 이미지 + "3D를 지원하지 않는 기기입니다" 안내)까지 구현해 공통 틀 `sim3d.js`에 그대로 반영한다. 25개 차시가 함께 쓰므로 처음부터 넣는 편이 안전하다.
3. **탐구 A/B 진행 순서를 강제(A 다 끝나야 B 시작)할지, 자유롭게 왔다갔다 허용할지?**
   추천: 지도서 순서(A→B)를 기본 흐름으로 강제하되, "다시 하기"로 전체 리셋 후 자유 순서 재실험은 허용. 초등학생 인지 부하를 줄이기 위해 첫 진행은 순서를 고정하는 편이 지도서 취지에 맞는다.
4. **붉은 양배추 용액 "계열" 표현을 정오 판정에 어떻게 반영할지** (예: 노란색 대신 "연두색"이라고 답해도 정답 처리할지)?
   추천: 자유 서술형이 아니라 보기 중 고르기(정확한 색 이름 보기)로 설계했으므로 채점은 지도서 표값과 정확히 일치할 때만 정답 처리하고, 3D 애니메이션 색상 자체도 표값 HEX로 고정한다(계열 설명은 텍스트 보충으로만).
5. **`lesson-config.js`를 JS 객체(window 전역)로 둘지, JSON + fetch로 둘지?**
   추천: 정적 export + `file://` 없이 GitHub Pages 서빙이므로 fetch도 가능하지만, 가장 단순하고 캐시 걱정 없는 `<script>` 전역 객체 방식을 1차로 채택(§6.1). 차시가 늘어나 config가 커지면 JSON 전환을 재검토.
6. **`src/components/science/science-view.tsx`의 실제 존재 여부·구조**는 이번 Plan에서 직접 열어보지 않았다(읽기 범위를 spec.md 작성에 필요한 최소로 제한). Build/Embed 담당자가 실제 파일을 확인하고 §7을 구체화해야 한다.
