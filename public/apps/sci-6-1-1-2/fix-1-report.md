## 2. 제안과 다르게 한 것

- **분석 2(레몬즙 + 붉은 양배추)**: "표를 보기 전 예측으로 옮기기" 대신 지도서 123쪽 평가 2번(서술형)을 4지선다로 바꿨다. 표를 봐도 바로 답이 나오지 않고 "산성 용액 판단 → 푸른색 리트머스 변화" 두 단계 추론이 필요하다.
- **분류 근거**: 분류 카드 안에 따로 두지 않고 분석 1(보기 고르기)로 두었다. 분류를 맞힌 직후 바로 이어지고, 공통 `Quiz`의 채점·저장을 그대로 쓴다.
- **'분류를 맞혀야 분석 질문 열림'**: 틀렸을 때 표를 다시 보게 하는 흐름. 2번 넘게 틀리면 도움말이 구체적으로 바뀌어 막히지 않게 했다.
- **D1**: 렌더러 하나 재사용 대신 매번 완전 해제 + `forceContextLoss()`. 3D 장면 구성(차시마다 다름)과 렌더러 수명을 분리하지 않아도 되어 공통 틀이 단순하다.
- **저장 detail 형식**: `analysis`가 `{ q1: { choice:[보기 문구], correct, tries }, … }`(문항 수에 무관한 형식)로 바뀌고 `classify: { groups, correct, tries }`가 추가됐다(spec §5.5 예시의 q1Choice… 평면 형식과 다름).

- 식초 + 페놀프탈레인: 3D 홈이 노란색 그대로, 견본 "노란색, 투명 → 처음 용액의 색과 같음(변화 없음)".
- M2: 태블릿 세로 768×1024에서 실행 버튼까지 스크롤한 상태(3D 위치 -711px) → 누르면 3D가 머리말 바로 아래(127px)로 오고, 애니메이션 6.2초 동안 화면 안에 있음(스크린숏으로 방울 떨어지는 장면 확인).
- D1: 3D↔2D 20회 왕복을 두 번(다른 세션) → 캔버스 1개, WebGL 경고 없음, 컨텍스트 살아 있음(`isContextLost()=false`), 3D 전환 버튼 정상.
- 새로고침 복원(단계·예상·기록·분류·결론·궁금한 점·홈판), `?no3d=1`(2D 24홈, 3D 버튼 비활성 안내, 실험·기록 가능), 휴대폰 375×812 다크모드에서 모든 단계 가로 넘침 없음·다크 색 적용, 태블릿 가로(800×600) 좌우 배치.
- 수치 측정형: 스크래치 시험 페이지(정본 틀 + 가짜 2D 트랙)로 물체 2 × 거리 3 × 3회 = 18 기록, 음수 입력 시 기록 버튼 비활성, 미니 표 회차 표시, 수치 표 + 평균, 꺾은선(2계열·범례·축 제목 "이동 거리(m)", "걸린 시간(초)"), 묶음 막대("속력(m/s)") 좌표 확인. 시험 페이지·서버는 끝난 뒤 삭제·종료.
- 콘솔: 앱 오류 0(앱 자원 실패 없음). `npm run build` 통과, `out/apps/sci-6-1-1-2/science-sim/`에 새 파일 포함.

## 5. 못 한 것 / 알려진 제한

- 작업 후반에 브라우저 창이 숨겨져 있어 **휴대폰·다크모드 화면 스크린숏과 20회 전환 뒤 3D 애니메이션 실제 시간 측정**은 하지 못했다(DOM·계산값·컨텍스트 상태로 대신 확인). 숨겨진 탭에서 실행이 멈추던 문제를 이때 발견해 고쳤다(스크롤 대기를 타이머로).
- 실제 터치 기기의 끌어다 놓기(분류 칩은 `touch-action: none`이라 칩 위에서 시작한 세로 스크롤은 안 된다 — 칩 밖을 밀면 됨), 로그인 실제 저장·RLS(지침상 실 DB 쓰기 금지).
- 저장 detail 최악의 경우(모든 입력칸 1000자, 따옴표·줄바꿈만) 약 15천 자로 16,000자 한도에 가깝다. 넘으면 이제 "글이 너무 길어요" 안내가 나온다.
- 3D 글자 라벨이 휴대폰에서 작은 것은 그대로(기존 제한).
