* 임시 파일은 스크래치 디렉터리에만 두고 끝나면 지운다.

## spec.md에 담을 내용
1. **지도서 분석** (쪽수 근거 포함): 실험 목적, 준비물, 용액 목록, 지시약(리트머스 종이, 페놀프탈레인 용액, BTB 용액 등 지도서에 나온 것)과 각 용액에서의 **정확한 색 변화 표**, 붉은 양배추 지시약 활동 여부와 색, 탐구 과정 단계, 지도상 유의점, 흔한 오개념, 평가 기준.
2. **앱 종류 판단**: 실험 시뮬레이션 앱인 근거.
3. **화면 설계** — 규칙의 4단계 + 궁금한 점:
   * 예상하기: 질문 문구, 입력 칸, 힌트 목록(답을 알려주지 않는 단계적 힌트)
   * 실험하기: 3D 장면 구성(실험대, 비커/시험관, 스포이트, 지시약 병, 리트머스 종이 등), 조작 방법(용액 선택 → 지시약 선택 → 떨어뜨리기/적시기 → 색 변화 애니메이션), 드래그 회전·확대, 측정·관찰 항목, 기록 버튼으로 저장되는 데이터 형식
   * 기록·분석하기: 자동 생성 표(용액 × 지시약), 그래프가 의미 있다면 형태, 분석 질문과 보기, 정답·피드백
   * 정리하기: 결론 질문, 모범 답안, 발전 질문 1~2개와 모범 답안
   * 더 탐구하고 싶은 점
   * 단계 이동/다시 하기, localStorage 임시 저장 키
4. **과학적 정확성 체크리스트**: 앱에 들어갈 모든 사실(색, 분류 결과)을 지도서 쪽수와 함께 나열. 지도서에 없는 값은 쓰지 않거나 "모형"임을 밝힌다.
5. **기술 설계**: 파일 구조, three.js 버전(CDN, 정확한 버전 + SRI 계획), 터치 드래그(OrbitControls), 성능(태블릿), 접근성, `class1-record.js` 연동(`detail` 필드 구조), basePath 상대경로 규칙.
6. **공통 틀 설계**: `scripts/templates/science-sim/`에 둘 파일과 역할(단계 내비게이션, 예상/힌트, 기록 저장소, 표·그래프, 분석 퀴즈, 정리·모범답안 비교, 궁금한 점, 3D 뷰어 초기화, 임시 저장, 결과 전송), 차시별 앱이 채워야 하는 설정(config) 형식 예시. 조사 도우미 앱 형태도 간단히.
7. **Embed 계획**: `src/data/science-curriculum.ts`의 Lesson에 앱 경로 필드 추가 방식과 차시 화면에 "실험 시작" 버튼 표시 방식.
8. **열린 질문**(추천안 포함).
