### 버저 소리 집중 점검(개정 1 요구) — 모두 통과

자동재생 정책을 실제 브라우저와 같게 강제(`--autoplay-policy=document-user-activation-required`, 새 AudioContext가 `suspended`로 시작함을 확인)한 뒤 측정했다.

| 확인 항목 | 결과 |
|---|---|
| 화면에 들어가는 것만으로 소리가 나는가 | ❌ 안 남. **AudioContext가 아예 만들어지지 않는다**(실험 화면 진입 직후 `ctx = 0`) |
| 언제 오디오가 깨어나는가 | 실험 패널 안에서 학생이 **처음 누를 때**(`pointerdown`)만. 키보드(Enter)만 쓰는 학생도 정상 재생됨(별도 시험) |
| 전구·전동기 단계에서 소리 | ❌ 안 남(4칸 실행 뒤에도 oscillator 0개) |
| 전지 한 개 ↔ 두 개 직렬 크기 차이 | ✅ 최대 음량 **0.15 / 0.35**(spec 값 그대로), 주파수 660 / 700Hz, 길이 1.25초 |
| 소리 끄기 | ✅ 누르면 재생 중인 소리를 끊고, 이후 실행에서 oscillator **0개**. '소리 다시 듣기'를 누르면 "지금은 소리가 꺼져 있어요…" 안내만 |
| 끈 상태 기억 | ✅ `sci623sim2:v1:sound = false`로 저장, 새로고침 뒤에도 '🔇 소리 켜기' 상태 유지(문제 4 참고) |

## 4. 소요 시간

기계로 진행한 순수 조작 시간(읽기·타이핑 제외)은 **전체 25~31초**, 칸 하나당 실행 애니메이션 **2.0~2.6초**(2D는 1.5초)였다. 여기에 6학년이 읽고 쓰는 시간을 더한 추정은 다음과 같다.

| 단계 | spec 예상 | 이번 추정(보통) | 느린 학생 |
|---|---|---|---|
| 예상하기(질문 읽기 + 한두 문장 타이핑, 힌트 포함) | 1.0분 | 1.0~1.2분 | 1.6분 |
| 실험 도입(직렬연결 안내 + 안전 5줄 읽기) | 0.5분 | 0.4~0.5분 | 0.8분 |
| 실험 6칸(칸당 조작 3.3초 + 읽고 고르기 12~15초) | 2.5분 | 1.8~2.1분 | 2.8분 |
| 기록·분석(표 확인 + 보기 2문항) | 1.5분 | 1.2~1.5분 | 2.0분 |
| 정리하기(결론 쓰기 + 모범 답안 비교) | 1.0분 | 1.0분 | 1.5분 |
| 궁금한 점(선택) | 0.3분 | 0.2분 | 0.4분 |
| **합계** | **6.8분** | **약 5.6~6.5분** | **약 9분** |

* **7분 기준 안에 든다**(보통 학생). 느린 학생은 약 9분으로 2단원 탐구 5와 비슷한 수준이다.
* '더 탐구해 보고 싶어요' 팝업은 선택이고 읽는 데 약 40~60초가 더 든다. 수업 시간이 빠듯하면 교사가 "다 한 사람만 열어 보기"로 안내하면 된다.
* 실제 학생 시간은 재지 못했다(글자 수·조작 수 기반 추정).

## 5. 확인한 것 vs 확인하지 못한 것

**확인한 것**: 위 표의 모든 항목(전체 흐름 5가지 화면 조건, 소리 8가지 시나리오, 팝업, 3D/2D 전환, 터치 드래그, 새로고침 복원, 로그인 가림막, `detail.qa` 저장 내용, 공통 틀 사본 동일성, 지도서·실험관찰 대조).

**확인하지 못한 것**

* **실제 소리의 크기 느낌** — headless 브라우저에는 소리 장치가 없어 음량 값(0.15/0.35)과 재생 호출·차단만 확인했다. 교실에서 실제로 들어 보고 "작지만 차이는 알 수 있는" 수준인지 **사람이 한 번 들어 봐야 한다**(태블릿 스피커 기준).
* **실제 iPad·태블릿 터치와 실제 GPU 3D** — SwiftShader headless + 터치 에뮬레이션으로만 확인했다(두 손가락 확대/축소는 시험하지 못함).
* **실제 Supabase DB** — 로그인·진행 저장·결과 저장 모두 가짜 응답으로만 확인했다(실 DB 쓰기 금지).
* **로그아웃 시 `sci6…` 로컬 삭제** — 가짜 세션 환경에서 앱의 로그아웃 단추가 끝까지 진행되지 않아(가짜 Supabase 응답 때문으로 보임) 확인하지 못했다. 공통 틀 기능이고 저장 키가 `sci6`으로 시작하는 것은 확인했다.
* **'↺ 처음부터 다시 하기'** — 네이티브 확인창이 떠서 자동 점검이 멈췄다(공통 틀 기능, 동작 자체는 막히지 않음). 사람이 한 번 눌러 보면 좋다.
* **두 학생 계정을 번갈아 쓰는 흐름**(기록 주인 바뀜 삭제) — 공통 틀 기능이라 이번에 따로 시험하지 않았다.
* `npm run build` — 이 앱은 `public/` 아래 정적 파일이라 번들에 들어가지 않으므로 돌리지 않았다(Embed 단계에서 확인 필요).
