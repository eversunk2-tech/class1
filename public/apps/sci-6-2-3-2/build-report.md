## 2. 구성(spec대로)

* **조건**: 부품(전구·전동기·버저) × 전기 회로(전지 한 개 / 전지 두 개 직렬) = **6칸**. 단계 A(전구)→B(전동기)→C(버저) 순서로 열린다.
* **3D 장면**: 실험대에 회로판 2개를 **나란히** 놓고 두 회로에 같은 부품을 하나씩 연결했다. 전지 끼우개의 (＋)(－) 표시, 직렬 회로는 앞 전지 (＋)극과 뒤 전지 (－)극을 잇는 짧은 전선 + "직렬연결" 이름표, 스위치 레버, 빨강(＋쪽)·검정(－쪽) 전선 고리. 버저의 빨간 선은 (＋)극 쪽에 붙였다(교과서 표기).
* **실행**: "▶ 스위치 닫기" → 레버가 닫히고(0.36초) 부품이 반응(1.35초). 전구는 빛·후광 크기, 전동기는 날개 회전 속도(느림 7 rad/s · 빠름 18 rad/s)와 잔상 고리, 버저는 퍼지는 소리 고리로 차이를 보여 준다. **카메라는 움직이지 않는다**(두 회로를 늘 함께 비교하도록).
* **관찰**: 결과 문구가 카드에 보이고(타이핑 없음) 2지선다에서 고른 뒤 '확인하기'→'기록하기'. 본 것과 다른 보기를 고르면 다시 보라는 피드백만 주고 기록을 막는다(정답을 알려 주지 않음).
* **기록·분석**: 3행×2열 매트릭스 표(글자 + 아이콘, 색만으로 전달하지 않음) + 보기 고르기 2문항(`wrongBy` 포함).
* **정리·궁금한 점**: 결론 1개(모범답안 비교), 궁금한 점은 선택(비워도 마칠 수 있음).
* **detail.qa 6개**: predict/q1(text), experiment/records(table, columns `part`·`single`·`series2`), analyze/q1·q2(choice), conclude/conclusion(text), curiosity/curiosity(text) — spec §8과 같다.

### 개정 1 요구 사항

* **버저 소리**: WebAudio 직접(라이브러리 없음). square 660~700Hz + 저역 통과 필터, **음량 전지 한 개 0.15 / 두 개 직렬 0.35**, 1.25초. **학생이 버튼을 누른 뒤에만** 난다(실험 화면 안의 조작에서만 AudioContext를 깨운다 — 전구·전동기 단계에서는 소리를 만들지 않는 것을 확인).
* **소리 끄기/켜기**: 실험 패널의 "🔊 소리 · 더 탐구하기" 카드와 버저 관찰 카드에 단추. 끈 상태는 앱 저장소(`sound` 키)에 기억한다. 저장 구조·저장 키 버전은 그대로.
* **소리를 껐거나 소리가 나지 않는 기기**: 3D 장면에 **"소리 크기 ▮▯▯ / ▮▮▮"** 표시와 퍼지는 고리(전지 한 개는 고리 2개·작게, 직렬은 3개·크게), 2D 화면에는 3칸 게이지 + "소리 크기: 작게/크게" 글자. 같은 방식으로 전구에 "밝기", 전동기에 "빠르기" 표시를 넣었다(움직임 줄이기 설정에서도 차이를 알 수 있게).
* **"더 탐구해 보고 싶어요" 팝업**: 실험 화면에서 열리는 앱 안 모달. 병렬연결 그림(SVG) + "교과서에서 배우는 내용은 아니고, 궁금한 사람만 살펴보는 코너예요. 여기에서는 기록하지 않아요." + 설명(밝기는 전지 한 개일 때와 비슷하고 더 오래 쓸 수 있다, 연결 방법에 따라 밝기가 달라진다) + 닫기. **기록·채점·질문 없음**, Esc·바깥 누르기로 닫히고 포커스가 원래 단추로 돌아간다.

## 3. spec과 다른 점(3가지)

1. **조건(factor)을 2개로 했다.** spec §6은 `factors: [부품]` 1개에 "회로 2종을 factor 없이 phase 안에서" 기록하라고 적었지만, 공통 틀은 한 번 실행에 한 칸(`cellKey`)을 기록하므로 회로를 고를 수단이 필요했다. **부품 × 회로 2개 factor**로 만들어 spec이 요구한 6칸·`cellKey: part|circuit`·기록 형태를 그대로 지켰다. 지도서의 "두 회로를 동시에 만들어 비교" 의도는 **두 회로를 항상 화면에 함께 두는 것**으로 살렸다(한 회로를 기록하면 같은 부품의 다른 회로가 자동으로 골라진다).
2. **관찰 카드에 '확인하기'를 두었다**(본 것과 같은 보기를 골라야 기록됨). spec에는 없지만 본보기 앱(6-2-2-1)과 같은 방식이고, 오답 기록으로 분석 표가 틀어지는 것을 막는다.
3. **실험하기 단계 안내(phase lead)의 굵게(`**`) 표시를 뺐다.** 공통 틀이 이 문장을 글자 그대로 넣어 `**`가 화면에 보였다(틀을 고치지 않고 문구만 고쳤다).

그 밖에 3D 장면의 세부(카메라 고정, 세기 표시 추가, 부품을 고르기 전에도 전구를 끼워 둔 것)는 점검하며 다듬은 부분이다.

### 소요 시간

기계로 진행한 시간(읽기·타이핑 제외)은 전체 약 23초, 한 칸당 실행 애니메이션 **약 2.0~2.6초**(칸당 조작까지 3.0~3.3초)다. 여기에 읽기·타이핑을 더한 학생 예상 시간은 **약 6.3분**(예상하기 1.0 / 실험 도입 0.5 / 6칸 2.0 / 분석 1.5 / 정리 1.0 / 궁금한 점 0.3)으로 spec의 6.8분 안에 든다. **실제 학생 시간은 재지 못했다.**

## 5. 확인하지 못한 것

* **실제 소리의 크기 느낌** — headless 브라우저에는 소리 장치가 없어 음량 값(0.15/0.35)과 재생 호출만 확인했다. 교실에서 적당한 크기인지 사람이 한 번 들어 봐야 한다.
* **실제 iPad·태블릿 터치**(3D 드래그·확대/축소, 세로 화면 스크롤)와 실제 GPU에서의 3D — SwiftShader headless로만 확인했다.
* **실제 Supabase DB**(로그인·진행 저장·결과 저장) — 가짜 응답으로만 확인했다. 실 DB 쓰기는 금지되어 있다.
* 두 학생 계정을 번갈아 쓰는 흐름(기록 주인 바뀜 삭제), 블로그 로그아웃 시 `sci6…` 삭제 — 공통 틀 기능이라 이번에 따로 시험하지 않았다.
* `npm run build` — 다른 앱을 동시에 만드는 중이라 `.next/`를 건드리지 않으려고 돌리지 않았다(이 앱은 `public/` 아래 정적 파일이라 번들에 들어가지 않는다). Embed 단계에서 확인이 필요하다.
* 스크래치 폴더(`scratchpad/build-sci-6-2-3-2/`: 시험용 사본·스크린숏·임시 프로필)는 삭제 명령이 권한 거부되어 남아 있다. 서버와 headless 브라우저는 종료했다.
