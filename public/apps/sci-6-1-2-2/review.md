**과학적 정확성 결론**: 꽃 4개의 위치, 이동 규칙(상하좌우 한 칸, 한 칸 = 1초, 대각선 없음), 6짝의 걸린 시간(5·8·5·3·4·5초)은 지도서 199·200·204·205쪽과 **정확히 일치**한다. 직접 계산한 값과도 같고, 지도서 예시 4개(제비→유채 3, 제비→진달래 4, 수선화→진달래 5, 진달래→유채 5초)와도 맞는다. 결론 모범 답안은 200·201·205쪽 문장 그대로다. 브라우저에서 잰 한 칸 연출 시간은 약 0.5초였다(8칸 이동은 출발 준비를 빼고 약 4초). 화면에 적힌 "한 칸을 0.5초 만에 움직이는 빨리 감기"와 맞는다. 금지 용어(기준점·좌표·x축·y축·속력·빠르기·거리)는 화면에 0건이다. 좌표 숫자쌍이나 두 위치 사이 거리도 보여 주지 않는다(182·198쪽 유의점 준수). 값 자체의 오류는 없다. 과학 관련 문제는 **A3(3D에서 칸 세기 단서가 틀림)** 하나이고, 나머지는 교수 설계 문제(A1, A2, M1~M4)다.

## 5. 확인한 것 vs 못 한 것

**확인한 것** (자체 헤드리스 Chrome 153, 별도 포트 9461·프로필. 공유 Browser 패널은 새 탭을 열 수 없어서 쓰지 않았다. 이 앱 키 `sci612sim2:*`만 지웠다.)
- 지도서 180~184, 198~205쪽 원문 대조. 인쇄 쪽 오프셋 +180. 6짝의 칸 수를 손으로 계산.
- 전체 흐름(1024×768 라이트): 예상하기 게이트 → 힌트 3개 → 실험 7회(6짝 + 반대 방향 1회). 매번 오답 → 2회째 도움말 → 정답 → 문장 미리보기 → 기록. 이어서 분석 표·그래프·반대 방향 비교 → 퀴즈 4문항 오답·정답 피드백 → 정리 3문항 → 궁금한 점 → 마치기(`Class1Record.save`를 가짜로 바꿔 payload 확인, 실 DB 쓰기 없음).
- 연출 시간: 칸당 약 0.5초(5칸 3.7~4.2초, 8칸 5.4~5.8초). 카운터 0→N초 → "도착!".
- 768×1024 다크, 375×812 다크(터치 에뮬레이션): 실행하면 3D 캔버스가 머리말 아래로 스크롤되고 이동 내내 화면 안에 있음(768: 128~576 / 푸터 955, 375: 148~446 / 푸터 743). 5단계 모두 가로 스크롤 없음.
- `?no3d=1`: 캔버스 0, 2D 정원판, 발자국 8개(도착 칸 포함) 모두 보임, 이동 중 정원판이 화면 안에 있음.
- 3D↔2D 40번 클릭(20회 왕복): 캔버스 1개, 경고 토스트 없음, 이어서 3D 실행 정상.
- 새로고침: 단계·선택 꽃·기록 복원. 반대 방향 결과 화면 복원 실패(m2).
- 콘솔 오류·예외 0건(모든 시나리오). SRI 직접 계산. XSS 입력. localStorage 크기(가장 큰 키 records 454 B).
