## 2. 과학적 정확성(화면에 나오는 값)

- 꽃 위치(분수 기준): 수선화꽃 왼쪽 3칸 / 제비꽃 위쪽 2칸 / 유채꽃 오른쪽 2칸·위쪽 3칸 / 진달래꽃 오른쪽 1칸·아래쪽 1칸 — 지도서 199쪽 텍스트를 `fitz`로 다시 확인.
- 규칙: 위·아래·왼쪽·오른쪽 한 칸씩(대각선 없음), 한 칸 = 1초(198~200쪽).
- 걸린 시간 = 가로 칸 차 + 세로 칸 차(코드 `cellsBetween`). 6짝 값: 수선화~제비 5, 수선화~유채 8, 수선화~진달래 5, 제비~유채 3, 제비~진달래 4, 유채~진달래 5초. 200쪽 예시 4개(3·4·5·5초)와 일치. 브라우저에서 이 값으로만 '확인'이 통과함을 확인.
- 꿀벌은 가장 짧은 길(가로 먼저 또는 세로 먼저 중 분수·다른 꽃 칸을 지나지 않는 쪽)로만 움직인다. 발자국 수 = 칸 수 = 초.
- 화면(aria-label·title 포함)에 "기준점·x축·y축·좌표·속력·빠르기·이동 거리·거리"가 0건(자동 검사). 칸 번호 숫자쌍은 코드에만 있다.
- "모형" 배지 + modelNote, 카운터마다 "⏩ 빨리 감기", 상시 배지 "⏱ 규칙: 1칸 = 1초", 알아 두기에 "한 칸을 0.5초 만에 움직이는 빨리 감기, 걸린 시간은 규칙대로 한 칸에 1초".

## 3. spec과 다른 점 / 앱에서 보완한 것

1. **관찰값 확인(spec 3.2 ④)**: 공통 틀의 수치 입력은 바로 '기록하기'가 켜지므로, 앱 코드(`wireCheck`)가 입력칸 뒤에 '✔️ 확인하기'를 붙이고 맞게 센 값일 때만 '기록하기'를 켠다. 틀리면 "다시 한 번 움직이며 세어 볼까요?" + '🔁 꿀벌 다시 움직여 보기'(실행 버튼 재실행). 같은 짝을 2번 이상 틀리면 "발자국(●)을 하나씩 짚으며 세어 보세요" 도움말(답은 말하지 않음). 틀 수정 없이 DOM 선택자(`#ss-num-seconds`, `.ss-observe > .ss-btn-primary`)에 기대므로, 틀의 관찰 카드 구조가 바뀌면 함께 확인해야 한다. **틀 반영 제안**: numeric 관찰에 `check(values) → true | "피드백"` 옵션.
2. **자동 채움 없음 + 도착 후 카운터**: 카운터는 이동 중에만 초를 보이고, 도착하면 "🏁 도착! 몇 초가 걸렸나요?"로 바뀐다(스톱워치 값을 그대로 옮겨 적지 않고 세어 보게). 꿀벌 머리 위 말풍선(1초, 2초…)도 도착하면 사라진다.
3. **출발 꽃 = 도착 꽃**: 공통 틀 `skipCells`로 막았다(실행 버튼 비활성 + "출발 꽃과 도착 꽃이 같아요" 안내, 미니 표 대각선 🚫 "같은 꽃"). 안전 문구가 아니라 앱 문구로 바꿨다.
4. **반대 방향**: 진행 조건은 방향과 상관없이 6짝(`cellKey`를 정렬한 짝으로). 같은 짝을 반대 방향으로 기록하면 표에는 마지막 방향으로 바뀌고, 방향별 값은 `dirTimes`에 따로 남겨 분석 단계에 "반대 방향으로도 움직여 본 짝" 비교를 보여 준다(없으면 해 보라는 질문만, 답은 말하지 않음).
5. **새로고침 복원**: 공통 틀의 scene 복원은 phases에 적은 방향만 되살리므로, 앱이 마지막 실행(`lastRun`)과 현재 선택(`curSel`)을 따로 저장해 되살린다. 실행 뒤 아직 기록하지 않은 관찰 카드는 복원되지 않는다(틀 동작, 기록은 지워지지 않음).
6. **정원판 크기**: spec "가로 7칸×세로 6칸 정도" → 가로 8칸×세로 7칸(분수 기준 왼쪽 4·오른쪽 3·아래 2·위 4칸). 꽃 주위에 여유 칸을 한 칸씩 두려고 조금 키웠다.
7. **방향 이름표**: 3D를 돌려도 방향을 잃지 않도록 정원판 네 변에 "↑ 위쪽 / ↓ 아래쪽 / ← 왼쪽 / 오른쪽 →"를 붙였다(2D도 같음).
8. **처음·나중 위치 표시**: 도착하면 출발 칸에 흐린 꿀벌 + "처음 위치", 도착 칸에 진한 꿀벌 + "나중 위치"(199쪽 명암 구분). 2D는 범례 글자로도 설명.
9. **발전 질문 2 그림**: "가 정류장 🚏 ── 5분 ──▶ 🚏 나 정류장" 그림을 입력칸 위에 넣었다(글자로도 모두 적음).
10. 퀴즈 보기 id는 틀 형식(`{id, label}`)으로 바꿨고, q4에 빠뜨린 정답별 피드백(`missBy`, 답을 직접 말하지 않음)을 더했다.
11. 예상하기 그림 캡션만 두고 질문·힌트는 spec 그대로다.

## 4. 확인한 것

공유 Browser 패널(자기 탭 tab-21, 숨김 탭이라 애니메이션은 즉시 끝남)과 **자체 헤드리스 Chrome 153(SwiftShader, 별도 프로필·포트)** 을 CDP로 조작했다. 저장은 `Class1Record.save`를 가짜 응답으로 바꿔 확인했다(실 DB 쓰기 없음).

- **전체 흐름(1024×768 라이트, 768×1024 다크, 375×812 모바일·터치 다크)**: 예상하기 → 실험하기 7회 실행(6짝 + 반대 방향 1회, 모두 기대 초로 확인 통과) → 분석 표 6행·막대 6개·반대 방향 비교 → 퀴즈 4문항 오답 피드백 → 정답 → 정리 3문항 제출(버스 그림) → 궁금한 점 → 마치기(요약 "6/6짝, 4/4", detail 약 1,000자 < 16,000자).
- **세로 화면 애니메이션**: 실행하면 3D 화면이 머리말 바로 아래로 스크롤되고, 이동 내내 화면 안(768×1024: top 127 / bottom 577, 375×812: 147 / 447)에 있으며 카운터가 1초씩 올라간다.
- **가로 스크롤 없음**: 모든 단계에서 scrollWidth = 화면 폭(1024 / 768 / 375).
- **확인 흐름**: 틀린 값 → 기록하기 꺼짐·다시 움직이기 버튼, 두 번째 오답에 발자국 도움말, 입력을 바꾸면 다시 꺼짐, 맞는 값 → 문장 미리보기 + 기록하기 켜짐.
- **같은 꽃 선택**: 실행 버튼 비활성, 안내 카드 표시.
- **`?no3d=1`**: 캔버스 0, 2D 정원판·꽃 탭 고르기·이동 애니메이션·발자국 5개(진달래→유채)·흐린/진한 꿀벌, 3D 버튼 비활성.
- **3D↔2D 40번 클릭(20회 왕복)**: 캔버스 1개, 컨텍스트 손실 없음, 경고 토스트 없음, 이어서 3D 실행 정상.
- **새로고침 복원**: 단계·예상·기록·현재 선택·마지막 실행 결과(반대 방향 포함, 2D·3D 모두) 복원.
- **앞 단계 이동**: 이전 단계 버튼으로 예상하기에 돌아가도 입력 유지. **처음부터 다시 하기**: 이 앱 키만 지우고 예상하기로 돌아감.
- **콘솔 오류·예외**: 모든 시나리오 0건. `node --check` 통과. `innerHTML`·`insertAdjacentHTML`·`outerHTML` 사용 0건(학생 입력은 textContent). 색만으로 전달하지 않음(꽃은 모양 기호+이름, 링 위치는 버튼 선택·안내 문장으로도, 그래프는 막대 위 숫자).
- 3D `dispose`는 `v.dispose`를 그대로 불러 WebGL을 반납하고, 발자국·이름표·말풍선은 `v.discard`로 해제한다.

## 5. 못 한 것

- 실제 태블릿 터치(드래그·핀치·더블탭), iOS Safari WebGL.
- 로그인 상태의 실제 저장(가짜 응답으로만 확인).
- `npm run build`는 돌리지 않았다(블로그 파일을 건드리지 않았고 정적 앱이라 영향 없음).
- 3D에서 꽃을 탭해 고르기(레이캐스트)는 헤드리스에서 좌표 탭으로 확인하지 않았다(2D 꽃 탭은 확인, 3D는 공통 틀 `pickable` 경로).
- 정리: 공유 패널의 자기 탭은 이 앱 키(`sci612sim2:*`)만 지우고 닫았다. 헤드리스 Chrome은 종료했지만, 스크래치 폴더(`scratchpad/b2`, `prof`, `chrome.log`, `chrome.pid`)는 삭제 권한이 거부되어 남아 있다.
- 참고: 작업 중 다른 에이전트가 공통 틀 정본(`experiment.js`, `sim3d.js`, `style-common.css`, `README.md`)을 고치고 있었다. 이 앱의 `science-sim/`은 **작업 시작 때 복사한 판(HEAD와 같음)** 이며, 정본 변경은 반영하지 않았다. 나중에 정본을 다시 복사하면 관찰 카드 구조(3절 1번 선택자)를 다시 확인해야 한다.
- 헤드리스 검증 초기에 포트 9337이 이미 다른 에이전트의 헤드리스 Chrome(`scratchpad/t5`)에 쓰이고 있어 몇 번 그 브라우저에 새 탭을 열어 검사했다(자기 탭만 열고 닫았고, 이 앱 키만 지웠다). 그 뒤 자체 Chrome(별도 포트·프로필)으로 다시 검증했다.
