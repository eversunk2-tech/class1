## 과학 처리
- 참값은 거리 = 모형 계산값이다. 5초에서 **135 cm / 122 cm**로 지도서 207·211쪽과 정확히 같다. 3초는 81 / 73.2 cm, 8초는 216 / 195.2 cm다. 달릴 때마다 두 자동차 위치에 ±1 cm 이내 무작위 오차(0.1 cm 단위, x.5는 피함)를 넣는다. 두 자동차의 차이는 가장 작아도 약 8 cm라 순위가 바뀌지 않는다.
- 두 자동차는 **동시에** 출발해 고른 시간 동안 **실제 시간**으로 달린다. 그 뒤 셔터 효과를 내고 '사진'을 보여 준다. 학생은 확대 화면에서 자동차 **앞부분**을 읽어 **반올림한 정수 cm**를 직접 입력한다(빈칸, 열린 질문 1 추천안). 입력값이 사진과 2.5 cm 이상 다르거나 정수가 아니면 답을 알려 주지 않고 다시 보라고만 안내한다. 분석 표에서도 그런 기록을 알려 준다.
- 화면에 '속력', 거리÷시간, m/s, km/h는 없다. 막대그래프는 범주형(관찰 시간 × 자동차)이다. 안내 문구는 '같은 시간 안에서' 두 막대를 비교하게 한다.
- 모형 표시: '모형' 배지, 모형 안내("일정하게 달린다고 단순화", "실제 시간(빨리 감기 없음)", 오차 설명), 사진 캡션 "(모형)"을 넣었다.
- 1초 이동 거리 표에는 "공식 경기 기록·세계 기록 기준 참고용 값, 평균적인 빠르기 아님"(208쪽 지도 길잡이 6)을 붙였다.

## spec과 다른 점
1. **발전 질문 2의 모범 답안**: spec 3.4의 "정해진 시간 동안 … 여러 육상·수영 경기"는 사실과 다르다. 대부분의 경주는 같은 거리 경기이고, 이는 탐구 4 내용이기도 하다. 그래서 실제로 같은 시간 동안 간 거리로 겨루는 사이클 **아워 레코드**와 육상 **1시간 달리기** 기록으로 바꿨다. 단체 추발 설명은 지도서 210쪽에 맞췄다(동시 출발 → 같은 시간 동안 더 긴 거리를 달린 팀이 따라잡음). 질문 문구에는 두 경기의 짧은 설명을 넣고 "운동 경기나 생활에서"로 넓혔다.
2. **분석 6의 오답 보기**: "술래보다 먼저 출발한다"를 "술래가 구호를 외치는 동안 움직이지 않는다"로 바꿨다. 원래 보기는 놀이 규칙상 어색하다.
3. 분석 5의 정답 피드백에 "동시에 출발했더라도 출발선이 다르면 맨 앞이라고 가장 빠르다고 할 수 없다"를 더했다(208쪽 바로잡기). 오답 보기마다 피드백(wrongBy)도 넣었다.
4. 분석 2·3 그림의 칸 수(㉠3·㉡5·㉢7·㉣9)는 임의 값이다(지도서에 좌표 없음, 코드 주석에 적음). 순서 ㉣ > ㉢ > ㉡ > ㉠만 지켰다.
5. 3D 카메라는 출발선에 다가간 뒤 달리는 동안 두 자동차를 따라간다(자동차가 작게 보이는 문제 때문). 끝나면 두 자동차와 줄자 눈금이 보이도록 다가가 멈춘다. '처음 방향으로'를 누르면 경주로 전체가 보인다.
6. 공통 틀 확장은 없다. `observe.body`로 사진과 확대 화면을 넣고, `q.text`에 DOM 노드를 넣고, 발전 질문 1 카드 안에 표를 넣었다(앱 코드에서 처리).

## 확인한 것
헤드리스 Chrome(CDP, 별도 프로필, swiftshader)으로 `http://localhost:3000/class1/apps/sci-6-1-2-3/index.html`을 확인했다. 결과 저장은 `Class1Record.save`를 가짜 응답으로 바꿔 확인했다.
- 전체 흐름을 **네 가지 조건**에서 끝까지 진행했다: 1024×768 라이트(3D), 768×1024 세로 다크(3D), 375×812 모바일·터치(3D), `?no3d=1` 1024×768 다크(2D). 순서는 예상(힌트) → 18번 측정(1번은 일부러 +6 cm) → 분석(표·그래프·재확인 안내, 분석 1 오답 피드백 뒤 6/6) → 결론과 발전 2개 → 궁금한 점 → 마치기(detail 약 1.8천 자, records 18개)다.
- 달리는 동안 3D 화면이 뷰포트 안에 있었다(세로 127~578/1024, 모바일 166~466/812). 타이머에 "⏱ x.x초 / N초 (실제 시간)"이 떴다.
- 새로고침하면 단계와 진행률(2/6)이 되살아난다. 3D↔2D를 6번 전환한 뒤에도 캔버스는 1개였다. `?no3d=1`에서는 캔버스 0개, 버튼은 "3D를 쓸 수 없는 기기예요"였다. 마친 뒤 실험하기로 돌아가 다시 측정할 수 있었다.
- 가로 스크롤은 없다(모든 단계 scrollWidth = 뷰포트 폭). XSS 입력(`<img onerror>`)은 글자 그대로 보였다. 콘솔 오류와 예외는 0건이다(헤드리스 GPU 성능 경고만 있음).
