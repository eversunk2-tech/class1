## 1. 지도서 분석

### 1.1 차시 정보(단원 지도 계획, 184~185쪽)

* 차시: 5/12, 과학 44~45쪽, 실험관찰 27쪽, 지도서 214~219쪽.
* 학습 목표: "같은 거리를 이동한 물체의 빠르기를 비교하는 방법을 설명할 수 있다.", "물체가 이동한 시간을 측정하고 빠르기를 비교할 수 있다."(184, 214쪽)
* 성취기준: [6과10-02] 물체의 이동 거리와 걸린 시간을 측정하여 속력을 구하고 빠르기를 비교할 수 있다(217쪽). 이 차시는 성취기준 중 "걸린 시간 측정 → 빠르기 비교" 부분만 다루고, "속력을 구하는" 부분은 다음 차시 몫이다(181쪽 교과서 차시 구성표: 4차시=같은 시간 비교, **5차시=이 차시(같은 거리 비교)**, 6차시=속력으로 비교).
* 평가 유형: 실험·실습, 관찰법(185쪽).
* 준비물(모둠별): 태엽 자동차 2대, 색 테이프, 줄자, 초시계(214, 219쪽). "초시계 대신 스마트 기기의 초시계 애플리케이션을 활용할 수도 있다"(214쪽).
* 태엽 자동차는 **이전 차시(탐구 3)에서 쓴 것을 그대로 사용**(214쪽) — 탐구 3(sci-6-1-2-3)과 소품을 맞출 필요는 없음(각 앱은 자체 완결). 다만 두 차시가 "빠르기 비교" 짝 차시이므로 이 앱은 탐구 3 앱의 화면 구성(있다면)과 크게 다르지 않게 만든다.

### 1.2 실험 절차(214, 215, 219쪽)

1. 색 테이프로 출발선을 표시하고, 출발선에서 수직으로 **100 cm** 떨어진 곳에 결승선을 표시한다(214, 215, 219쪽).
2. 초시계를 든 친구의 신호에 따라 태엽을 감은 자동차를 **한 대씩** 출발시키고, 결승선까지 이동하는 데 걸린 시간을 각각 측정한다(215쪽 지도 길잡이2: "정확한 시간 측정과 편리한 초시계 사용을 위해 태엽 자동차를 한 대씩 출발시킨다").
3. 태엽 자동차의 앞부분이 결승선에 도달한 시간을 **반올림하여 소수 첫째 자리까지** 나타낸다(215쪽 지도 길잡이1, 219쪽).
4. 두 태엽 자동차의 빠르기를 비교하고 그렇게 생각한 까닭을 이야기한다(214, 215쪽).
* 지도 길잡이3(215쪽): "교실 환경에 따라 출발선과 결승선 사이의 **거리를 100 cm보다 짧거나 길게 할 수 있다**." → 이 문장이 **이 앱에서 이동 거리를 여러 값으로 바꿔 실험하는 설계의 근거**다(순수 창작이 아니라 지도서가 명시적으로 허용한 변형).
* 실험관찰 27쪽 예시 표: 초록색 자동차 **예 4.2초**, 노란색 자동차 **예 5.8초**(100 cm 기준). "예"로 표시된 참고 답이며 앱이 반드시 재현해야 할 고정값은 아니다(§4에서 다룸).
* 실험관찰 27쪽 문장 완성: "그 까닭은 초록색 자동차가 노란색 자동차보다 결승선까지 이동하는 데 걸린 시간이 더 **(길기, 짧기)** 때문입니다." → 정답 "짧기".

### 1.3 정리 문장·평가(216, 217쪽)

* 정리해요(216쪽, 교과서 45쪽과 동일): "같은 거리를 이동한 물체의 빠르기를 비교하는 방법을 이야기해 볼까요? — 같은 거리를 이동한 물체의 빠르기는 걸린 시간을 측정해 비교할 수 있으며 걸린 시간이 짧을수록 더 빠릅니다."
* 교과서 45쪽 빈칸(216쪽에 재수록): "① 같은 거리를 이동한 물체는 걸린 시간이 **(길수록, 짧을수록)** 더 빠릅니다." → 정답 "짧을수록".
* 교과서 45쪽 질문 ②(216쪽): "같은 거리를 이동하는 데 걸린 시간을 비교하는 운동 종목에는 무엇이 있는지 이야기해 봅시다." 예시 답: 조정, 쇼트트랙, 봅슬레이(216쪽). 보충 자료(218쪽)에 달리기(100·200·400 m), 조정(2,000 m 직선 코스, 뒤로 이동), 쇼트트랙(개인전 500·1,000·1,500 m), 알파인 스키(활강=최고 속도 기준 가장 빠른 종목), 단체 스프린트(3인 1조, 3바퀴, 바퀴마다 탈락)가 정리되어 있음.
* 차시 평가 문항(217쪽):
  * 선택형: 선수 ㈎㈏㈐㈑의 100 m 기록(17·20·18·19초) 중 가장 빠른 선수·가장 느린 선수 = **㈎, ㈏**.
  * 서술형(모범 답안 그대로 인용): "쇼트트랙과 100 m 달리기에서 선수들의 빠르기를 비교해 순위를 결정하는 공통적인 방법을 '출발선, 결승선, 걸린 시간'이라는 단어를 모두 사용해 써 봅시다." → 모범 답안: "선수들이 출발선에서 결승선까지 이동하는 데 걸린 시간이 짧은 순서대로 순위를 결정한다."
* 보충 자료(218쪽): 초시계의 스플릿 타임 기능(각 구간의 누적 시간), 랩 타임 기능(각 구간의 시간 차이) — 핵심 활동은 아니지만 "더 알아보기" 정보 카드로 쓸 수 있음.

### 1.4 지도상 유의점·안전·인성(214쪽, 182쪽 단원 공통)

* "이 차시는 물체가 이동하는 데 걸린 시간을 정확하게 측정하고 빠르기를 비교하는 데 중점을 두고 지도한다."
* "물체가 같은 거리를 이동하는 동안 걸린 시간과 빠르기의 관계를 이해해 과학적 사고력을 기를 수 있도록 지도한다."
* "물체가 이동하는 데 걸린 시간을 측정하고 비교할 때 모둠원과 역할을 나누어 수행하되 서로 협력할 수 있도록 지도한다."
* "**빠르기를 비교하는 활동이 경쟁 요소가 되지 않도록 유의한다.**" → 앱 설계 제약: 학생 간 순위·경쟁 요소(리더보드 등)를 넣지 않는다. 비교는 "자동차 vs 자동차"에 한정하고 "나 vs 다른 학생" 비교는 만들지 않는다.
* 안전: "줄자에 손을 다치지 않도록 주의한다.", "태엽을 과도하게 감지 않도록 주의한다."(214, 215, 219쪽) → 3D 장면에서 줄자를 조작하는 연출을 넣는다면 이 안전 문구를 안내로 노출한다. 이 차시는 관찰하지 않는 칸(`skipCells`)이 필요한 위험한 조합은 없다(모든 물체×거리 조합을 안전하게 측정 가능).
* 단원 공통 지도상 유의점(182쪽): "물체의 속력을 구할 때 물체가 한 길을 따라 한 방향으로 운동하는 경우만 다룬다." → 이 차시에도 적용(직선 트랙만).

**sim(실험 시뮬레이션)**. 이 차시는 "[탐구 활동] 물체가 같은 거리를 이동하는 동안 걸린 시간 비교하기"라는 실습이 핵심이고(215쪽), 평가 유형도 실험·실습/관찰법이다(185쪽). CLAUDE.md 규칙상 "실험이 있는 차시 → 실험 시뮬레이션 앱"에 해당한다. `scripts/templates/science-sim/README.md`의 "(2) 수치 측정형" 예시가 정확히 이 도메인(물체의 운동 · 이동 거리·걸린 시간)을 들어 설명하고 있어 그대로 재사용할 수 있다.

## 3. 화면 설계

공통 틀 5단계(`predict → experiment → analyze → conclude → curiosity`)를 그대로 쓴다.

### 3.1 예상하기 (predict)

절대 답을 미리 주지 않는다. 두 질문에 직접 타이핑(`minLength: 5`).

* Q1(도입, 215쪽 도입 발문을 각색): "수영 경기나 달리기 경기를 본 적이 있나요? 그런 경기에서는 순위를 어떻게 정할까요? 여러분의 생각을 적어 보세요."
* Q2(탐구 목표, 215쪽 "같은 거리를 이동한 물체의 빠르기를 비교할 수 있다"): "출발선에서 같은 거리를 이동한 두 태엽 자동차 중 어느 것이 더 빠른지, 무엇을 측정하면 알 수 있을지 여러분의 생각을 적어 보세요."

힌트(생각 거리만 제공, 답 누설 금지 — 이전 차시 리뷰의 "힌트가 답을 말함" 지적을 피함):

1. "달리기 경기에서 선수들이 동시에 출발한다면, 결승선에 먼저 들어온 선수와 나중에 들어온 선수 사이에는 어떤 차이가 있을까요?"
2. "시계나 초시계를 눌러서 무언가의 시간을 재 본 경험이 있나요? 어떤 상황이었나요?"

(어느 힌트도 "걸린 시간이 짧을수록 빠르다"는 결론 문장을 직접 말하지 않는다.)

### 3.2 실험하기 (experiment)

* **인트로 문구**: "태엽 자동차 두 대를 출발선에서 동시에 준비하고, 한 대씩 출발시켜 결승선까지 이동하는 데 걸린 시간을 재요. 줄자에 손이 다치지 않게 조심하고, 태엽은 너무 세게 감지 마세요."(214, 215, 219쪽 안전 문구 반영)
* **조건(factors)** 2개:
  * `car`(자동차 고르기): 초록색 자동차 / 노란색 자동차(실험관찰 27쪽 표 그대로).
  * `dist`(이동 거리 고르기): 50 cm / **100 cm(기본, 지도서 기준값)** / 150 cm. 근거: 지도서 215쪽 "거리를 100 cm보다 짧거나 길게 할 수 있다."
* **phase**: 단일 phase `M`("측정"), `trials: 3`(같은 조건을 3번씩 재어 평균을 구함 — §7에서 "지도서 외" 표시). 셀 수 = 2 × 3 = 6칸, 칸마다 3회 = 18회 측정.
* **3D 장면**: 직선 트랙(출발선 색 테이프 + 결승선 색 테이프, 거리 조건에 따라 트랙 길이가 달라짐), 자동차 두 대(초록/노랑 몸체), 드래그로 시점 회전(측면/위에서 보기). "▶ 출발!" 버튼을 누르면 고른 자동차가 트랙을 달리는 애니메이션이 재생되고, 화면 한쪽의 디지털 스톱워치가 실시간으로 올라가다가 자동차 앞부분이 결승선에 닿는 순간 멈춘다(215쪽 지도 길잡이1: "태엽 자동차의 앞부분이 결승선에 도달한 시간"). 애니메이션은 실제 시간(2~9초)을 그대로 보여주며 빨리 감기하지 않는다(시간 자체를 왜곡하지 않으므로 "빨리 감기" 표시 불필요).
* **모형(단순화) 표시**: 실제 태엽 자동차는 태엽이 풀리며 속력이 점점 느려질 수 있지만, 이 화면에서는 **자동차마다 일정한 빠르기로 움직이는 모형**으로 단순화한다. 3D 화면에 "모형" 배지와 함께 실험 인트로에 "🔧 모형: 이 화면의 자동차는 태엽이 풀리는 동안 일정한 빠르기로 달리는 것으로 단순화했어요."를 명시한다(지도서에 없는 단순화 — §4·§7에서 "지도서 외"로 표시).
* **관찰·기록**: `observe`는 수치 입력(`type: "numeric"`) 1칸 — `{ id: "time", label: "걸린 시간", unit: "초", step: 0.1, min: 0.1, max: 20 }`. 스톱워치가 멈춘 값을 미리 채워 주고(`view.lastTime`), 학생은 화면에 보이는 숫자를 그대로 옮겨 적는다(219쪽 "측정해 써 봅시다"). 기록 버튼으로 저장(같은 칸 재실험 시 회차별로 최대 3개 보관, 템플릿 `RecordStore`).
* **미니 표**: 행 = 자동차 2개, 열 = 이동 거리 3개, 칸에 "n/3" 표시.
* **보충 정보 카드(선택)**: "초시계에는 스플릿 타임(누적 시간)·랩 타임(구간 차이) 기능이 있어요."(218쪽 보충 자료) — 핵심 흐름을 막지 않는 부가 정보 카드로만 넣는다.

### 3.3 기록·분석하기 (analyze)

* **표**: 열 = 자동차, 이동 거리(cm), 1회·2회·3회(초, 소수 1자리), 평균(초). `TableChart.renderTable` 평균 줄 포함.
* **꺾은선그래프**: x축 = 이동 거리(cm), y축 = 평균 걸린 시간(초), 계열 2개(초록색 자동차/노란색 자동차). 캡션: "이동 거리에 따른 평균 걸린 시간". (거리가 길수록 두 계열 모두 시간이 늘고, 노란색 계열이 항상 위에 있음 → 자연스럽게 "짧은 시간 = 빠름" 시각화.)
* **막대그래프**: 카테고리 = 이동 거리 3개, 계열 2개(자동차별), 값 = 그 거리에서의 평균 **걸린 시간**(초). 캡션: "이동 거리별 자동차 평균 걸린 시간". **"속력" 막대그래프는 만들지 않는다**(다음 차시 스포일러 방지 — §0, §7 참고). `science-sim` README 3(2)절의 "평균 속력" 막대 예시는 이 차시에는 적용하지 않는다.
* **분석 퀴즈(보기 고르기, 3문항)**:
  1. (교과서 45쪽 빈칸 그대로) "같은 거리를 이동한 물체는 걸린 시간이 무엇 할수록 더 빠를까요?" 보기: 길수록 / 짧을수록 / 관계없다. 정답: 짧을수록. 오답 피드백(`wrongBy`): "길수록"→"표에서 걸린 시간이 짧은 자동차와 긴 자동차 중 어느 쪽이 먼저 결승선에 도착했는지 다시 확인해 보세요." "관계없다"→"두 자동차의 평균 걸린 시간이 서로 같은지 표에서 확인해 보세요."
  2. "이동 거리 100 cm에서 초록색 자동차와 노란색 자동차 중 어느 자동차가 더 빠른가요?"(실제 정답은 학생이 기록한 값 기준으로 채점 — `grade` 함수 사용, 시뮬레이션 상수상 초록색이 항상 더 빠름) 보기: 초록색 자동차 / 노란색 자동차 / 두 자동차의 빠르기가 같다. 정답: 초록색 자동차. 근거 피드백에 "결승선까지 걸린 시간이 더 짧기 때문이에요."(219쪽 문장 완성 "짧기" 인용)
  3. "이동 거리를 50 cm, 100 cm, 150 cm로 바꿔서 실험해 보니, 더 빠른 자동차(걸린 시간이 더 짧은 자동차)가 거리에 따라 바뀌었나요?" 보기: 바뀌지 않았다(항상 같은 자동차가 더 빠르다) / 거리마다 달랐다 / 알 수 없다. 정답: 바뀌지 않았다. (자기 실험 데이터를 근거로 답하는 문항이며 "속력"이라는 말은 쓰지 않는다.)

### 3.4 정리하기 (conclude)

* **결론**(직접 적기 → 모범 답안 비교): 프롬프트 "같은 거리를 이동한 물체의 빠르기를 비교하는 방법을 정리해 봅시다." 모범 답안(216쪽 그대로): "같은 거리를 이동한 물체의 빠르기는 걸린 시간을 측정해 비교할 수 있으며 걸린 시간이 짧을수록 더 빠릅니다."
* **발전 질문 1**(217쪽 서술형 평가 문항 그대로, 자동차 실험과는 다른 맥락 — 앞선 분석 퀴즈와 겹치지 않음): "쇼트트랙과 100 m 달리기에서 선수들의 빠르기를 비교해 순위를 결정하는 공통적인 방법을, '출발선', '결승선', '걸린 시간'이라는 세 낱말을 모두 사용해 써 보세요." 모범 답안(217쪽 그대로): "선수들이 출발선에서 결승선까지 이동하는 데 걸린 시간이 짧은 순서대로 순위를 결정한다."
* **발전 질문 2**(216쪽 교과서 질문 응용): "같은 거리를 이동하는 데 걸린 시간을 비교해 순위를 정하는 운동 종목을 아는 대로 적어 보세요." 모범 답안(216, 218쪽): "조정, 쇼트트랙, 봅슬레이, 달리기(100 m·200 m·400 m 등), 알파인 스키(활강), 단체 스프린트 등이 있다." (학생 답이 이 중 하나만 있어도 정답으로 인정 — `minLength`만 걸고 자유 서술, 모범 답안과 나란히 비교만 함.)

```js
  makeRecord: (sel, v) => ({ car: sel.car, distance: Number(sel.dist), time: v.time }),
  miniTable: { rows: C.cars, cols: C.distances.map(d => ({ id: String(d), label: d + " cm" })),
               sel: (r, c) => ({ car: r.id, dist: c.id }) },
});

// run(sel) 내부 시간 계산 예(app.js, 지도서 외 물리 모형):
function computeTime(car, distance) {
  var base = distance / car.speed;                       // 거리 = 빠르기 × 시간
  var noise = C.noise.min + Math.random() * (C.noise.max - C.noise.min);
  return Math.round((base + noise) * 10) / 10;            // 소수 첫째 자리 반올림(215, 219쪽)
}
```

## 6. 3D 장면 스케치

* **바닥/트랙**: 회색 직선 트랙. 시작 쪽에 초록빛 색 테이프 줄(출발선), 고른 이동 거리(50·100·150 cm)만큼 떨어진 위치에 두 번째 색 테이프 줄(결승선). 트랙 길이는 거리 조건에 비례해 3D에서도 시각적으로 달라진다(50 cm 조건이 가장 짧고, 150 cm 조건이 가장 긺).
* **자동차 모형**: 단순화한 상자+바퀴 모양 두 개, 각각 초록/노랑으로 색칠(이름표 포함 — 유닛1 리뷰에서 "3D 물체에 이름 없음" 지적을 반영해 자동차 위에 작은 이름표를 둔다). 출발선 뒤에 나란히 대기.
* **줄자 소품**: 트랙 옆에 눕혀 둔 줄자 모형(장식용, 안전 문구와 연결).
* **스톱워치 HUD**: 화면 상단 또는 트랙 옆에 디지털 숫자로 경과 시간 표시. "출발!" 버튼을 누르면 0.0부터 올라가다가 자동차 앞부분이 결승선 테이프에 닿는 순간 정지하고 값을 확정한다(215쪽 "앞부분이 결승선에 도달한 시간").
* **카메라**: 기본은 트랙 전체가 보이는 비스듬한 위쪽 시점, 드래그(터치 포함)로 회전 가능. 결승선에 가까운 낮은 시점으로도 볼 수 있게 허용(도착 순간을 가까이서 관찰).
* **연출**: 자동차가 결승선을 통과하면 테이프가 끊어지는 짧은 이펙트 + 스톱워치 숫자가 굳어지는(색이 바뀌는) 피드백으로 "측정 완료"를 알린다.
* **"모형" 배지**: 화면 한 켠에 "🔧 모형: 자동차는 일정한 빠르기로 달리는 것으로 단순화했어요" 배지를 상시 노출.
* **2D 대체 화면**(`?no3d=1` 또는 WebGL 실패 시): 위에서 본 가로 트랙, 출발선·결승선 세로줄, 자동차는 색이 있는 사각형 아이콘, 동일한 스톱워치 HUD.
