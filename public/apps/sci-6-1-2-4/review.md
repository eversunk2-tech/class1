## 5. 확인한 것 vs 못 한 것

**확인한 것**
* 지도서 180~182, 214~220쪽 원문과 모든 화면 문장·수치를 대조했다.
* 공유 Browser 패널의 자기 탭(tab-25, 800 px 폭, 백그라운드라 애니메이션은 즉시 끝남)에서 전체 흐름을 끝까지 진행했다. 예상하기 → 실험 18회(칸마다 첫 회에는 틀린 반올림 값을 먼저 넣어 버튼이 꺼지고 안내가 맞게 나오는지 확인) → 분석(모든 오답 피드백과 정답) → 정리 3문항 → 궁금한 점 → 마치기(`Class1Record.save`를 가짜로 바꿈). 표의 평균값은 손으로 다시 계산해 맞췄다.
* XSS: 예상·결론·발전 입력에 `<img onerror>`, `<script>`를 넣었는데 글자로만 표시되었다(요소 0개). 공통 틀은 innerHTML을 쓰지 않는다.
* 새로고침 복원, 3D↔2D 6번 전환(캔버스·초시계 화면이 쌓이지 않음), 콘솔 오류 0.
* 자기 전용 헤드리스 Chrome 153(포트 9461, SwiftShader): 1024×768 라이트, 768×1024 다크, 375×812 다크(3D), 375×812 `?no3d=1`(2D). 네 경우 모두 가로 스크롤이 없었고(scrollWidth = innerWidth), 달리는 동안 실험 화면이 화면 안에 보였고, 실제 시간이 초시계 값과 같았고, 콘솔 오류가 0이었다. 휴대폰 다크 모드의 분석 그래프도 확인했다.
* `diff -r scripts/templates/science-sim public/apps/sci-6-1-2-4/science-sim` → 차이 없음. CDN은 three.js(importmap integrity + modulepreload SRI)와 supabase-js 2.116.0(SRI)이다.
* 앱 localStorage 키(`sci612sim4:v1:*`)만 지웠고, 탭 크기를 원래대로 돌린 뒤 탭을 닫았다.

**못 한 것**
* 실제 태블릿 터치(드래그 회전·핀치), 실제 로그인 저장(가짜 응답만), 스크린 리더 실사용.
* 애니메이션 예외 경로(i3)는 코드 검토로만 판단했다.
* 스크래치 폴더 삭제(권한 거부, i5).
