## 확정된 사용자 결정
1. **대시보드 구조**: `/admin/`을 대시보드로 통합. `/admin/` = 개요, `/admin/posts/` = 글 관리(기존 `/admin/` 목록 이동, `/admin/write/` 유지), `/admin/members/` = 회원, `/admin/learning/` = 학습 현황(+과제 관리 위치는 설계에서 결정). 사이드 메뉴(모바일은 상단 탭/드로어).
2. **회원 관리**: 가입한 모든 회원 조회(아이디/이메일, 이름, 가입 방식 email/github/google, 가입일, 마지막 로그인, 역할). 검색·정렬.
3. **비밀번호 초기화**: 관리자가 버튼 → 임시 비밀번호 자동 생성 → 관리자 화면에 **한 번만** 표시(복사 버튼) → 학생에게 전달 → 학생은 로그인 직후 새 비밀번호 설정 화면으로 강제 이동. OAuth 전용 계정은 초기화 대상 아님(UI에서 구분).
4. **학습활동 저장 범위(전부)**:
   * 웹앱 학습 결과 — `/public/apps/{앱}/` 정적 앱이 공통 형식으로 기록(점수, 만점, 완료, 소요 시간, 자유 JSON 상세). 앱 쪽에서 쓸 **작은 공통 JS 헬퍼**(CDN supabase-js + 블로그 세션 공유 전제)와 기록 API 형태를 설계. 앱은 CLAUDE.md상 자체 완결이어야 하므로 헬퍼를 각 앱에 복사하는지 공용 파일을 참조하는지 트레이드오프를 적고 추천.
   * 글 읽기 기록 — 로그인 사용자가 글 상세를 열면 기록(중복 정책 제안: 예 사용자×글 1행 + 마지막 읽은 시각/횟수).
   * 댓글·좋아요 — 기존 테이블을 집계(새로 복제 저장할지 뷰로 볼지 결정).
   * 과제 제출 — 관리자가 과제 생성(제목, 설명(마크다운), 마감일, 공개 여부), 학생이 텍스트/링크 제출·수정(마감 후 정책 제안), 관리자가 제출물 확인·상태(제출/검토완료 등).
5. **피드백: 양방향 대화** — 학생별 스레드(학생 전체에 대한 대화) + 특정 학습 결과/과제 제출에 연결된 대화 가능. 학생도 답글. 읽음 표시(안 읽은 개수 배지). 학생은 자기 스레드만, 관리자는 전체.
6. **학생 화면**: 헤더 사용자 메뉴(프로필 메뉴)에 "내 학습 활동" → `/me/learning/`(이름은 제안 가능): 내 웹앱 결과, 읽은 글, 댓글·좋아요, 과제 목록/제출, 피드백 대화. 새 피드백 알림 배지.

## 반드시 다룰 설계 이슈
* **service_role 필요 작업**(회원 전체 조회의 auth 정보, 비밀번호 초기화): 정적 사이트라 브라우저에 키 불가 → **Supabase Edge Function** 설계(함수 목록, 요청/응답, 호출자 JWT로 `is_admin` 검증, CORS 허용 origin: `https://eversunk2-tech.github.io`, `http://localhost:3000`). 배포 방법 2가지(Supabase CLI / 대시보드 에디터)를 사용자용 단계로 정리. 가능한 부분은 Edge Function 없이 처리(예: 가입 방식·이메일·마지막 로그인을 트리거로 profiles나 관리자 전용 테이블/뷰에 동기화)하는 대안과 비교 후 추천.
* **강제 비밀번호 변경**: 플래그 저장 위치(예: `profiles.must_change_password` — 사용자가 스스로 끌 수 없어야 함, 변경 완료 시 해제 방법), 클라이언트 가드(모든 페이지에서 리다이렉트), 새 비밀번호 설정 화면 URL.
* **RLS**: 모든 새 테이블 정책(학생 본인만/관리자 전체), 학생이 점수 등을 조작할 수 있는 한계 명시(클라이언트 기록이므로 신뢰도 한계와 완화책).
* 조회 성능: 대시보드 집계용 뷰/RPC(security definer + is_admin 검사) 제안, 인덱스.
* 기존 코드 영향: `/admin/` 경로 이동에 따른 링크 수정 목록, admin-guard 재사용.
* basePath `/class1`, 정적 export 제약, 한국어 UI, 모바일 대응 준수.
