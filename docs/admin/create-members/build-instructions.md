# Build 서브에이전트 지침: 관리자 계정 생성(단일 + 엑셀 일괄) — 2026-09-23 사용자 승인

관리자 대시보드 **회원 관리**에서 새 계정을 직접 만든다. 지금은 `scripts/import-users.mjs`로 로컬에서만 가능하다.

## 확정 사항(사용자 결정)
* 엑셀 칸은 **아이디 · 비밀번호 · 역할** 3개.
* 역할 값은 **학생 / 교사** 두 가지. `학생 → profiles.role='user'`, `교사 → 'admin'`(사이트에는 admin·user 두 역할뿐이다. **새 역할을 만들지 않는다 = SQL 변경 없음**).
* 새 계정은 **첫 로그인 때 비밀번호 변경을 강제**한다(`profiles.must_change_password = true`, 비밀번호 초기화와 같은 방식).
* 화면에 **엑셀 규격 안내 문구**와 **서식 파일 내려받기**를 둔다.

## 만들 것
1. **Edge Function** `supabase/functions/admin-create-member/`
   * 기존 `admin-reset-password`·`admin-delete-member`와 같은 패턴: Authorization JWT 확인 → 호출자가 관리자인지 확인(아니면 401/403) → service_role로 계정 생성.
   * 입력: `{ rows: [{ id, password, role }] }` (한 번에 최대 100행, 본문 크기 제한). 아이디는 `scripts/import-users.mjs`와 **똑같이** `아이디@class1.local`(소문자)로 바꾼다. `LOGIN_EMAIL_DOMAIN`은 `src/lib/auth.ts` 값과 같아야 한다.
   * 각 행: `auth.admin.createUser({ email, password, email_confirm: true, user_metadata:{ full_name: 아이디 } })` → 성공하면 `profiles`에 역할·이름·`must_change_password=true` 반영(트리거가 만든 행을 service_role 전용 RPC로 갱신 — `admin_finalize_password_reset` 패턴을 따르되 **새 마이그레이션 없이** 기존 권한으로 가능한 방법을 먼저 찾고, 꼭 필요하면 새 마이그레이션 파일 초안을 만들어 보고서에 적는다. 이미 실행된 파일은 고치지 않는다).
   * **행마다 결과**를 돌려준다: 성공 / 이미 있는 아이디 / 비밀번호 규칙 위반 / 형식 오류 / 그 밖 오류(사유 문구). 비밀번호는 응답·로그 어디에도 남기지 않는다.
   * 부분 실패를 허용한다(성공한 행은 그대로 두고 실패 목록만 돌려준다).
2. **회원 관리 화면**(`src/app/admin/(dashboard)/members/`)
   * "회원 추가" 버튼 → 모달에 두 가지 탭: **한 명 만들기**(아이디·비밀번호·역할), **엑셀로 여러 명**.
   * 엑셀 탭: 파일 고르기(.xlsx/.csv) → **미리보기 표**(행 번호·아이디·역할·검사 결과)에서 문제 행을 빨간 글자+아이콘으로 표시 → "○명 만들기" 버튼 → 진행 표시 → 결과 요약(성공 n, 실패 m)과 실패 사유 목록, 실패 행만 다시 시도.
   * 규격 안내: "첫 줄은 제목(아이디, 비밀번호, 역할), 역할은 학생 또는 교사, 비밀번호는 6자 이상"처럼 한눈에.
   * **서식 내려받기 버튼**: 바로 쓸 수 있는 `.xlsx`(제목 줄 + 예시 2줄). 정적 사이트이므로 미리 만들어 `public/templates/`에 두고 basePath를 붙여 링크하거나, 화면에서 만들어 내려받게 한다(둘 중 택일, 근거를 보고서에 적기).
   * 만들고 나면 목록을 새로 고쳐 새 회원이 보이게 한다.
3. **엑셀 읽기**: 새 의존성 추가는 되도록 피한다. `scripts/import-users.mjs`에 이미 .xlsx(zip) 최소 파서가 있으니 그 방식을 참고해 브라우저용으로 옮기거나, 라이브러리를 쓸 거면 이유·용량·보안(알려진 취약점)까지 보고서에 적고 CDN이 아니라 번들로 넣는다. CSV도 함께 지원한다(제목 줄 이름 흔들림 허용: 아이디/id/학번, 비밀번호/password, 역할/role).

## 반드시 지킬 것
* service_role 키는 함수 안에서만. 클라이언트·저장소·로그에 절대 없다.
* 비밀번호는 화면에 적은 뒤 전송만 하고, 응답·로그·`localStorage`에 남기지 않는다. 미리보기 표에도 비밀번호는 보여 주지 않는다(길이만 확인).
* 관리자만 호출 가능. 함수 안에서 검증하고, 화면 가드만 믿지 않는다.
* 한 번에 만들 수 있는 수를 제한하고(예: 100행), 큰 파일은 나눠 보낸다. 실패 시 사용자가 무엇을 고쳐야 하는지 분명히.
* 정적 export 제약(서버 기능 금지), basePath 규칙, lint·tsc·`npm run build` 통과.
* git 명령 금지, 실 DB·Auth 호출 금지(가짜 응답으로 시험), 자기 전용 headless 브라우저만, `localStorage.clear()` 금지.
