# Build(수정) 서브에이전트 지침: 학생 응답·일괄 칭찬 review 1차 수정

## 목표
`docs/admin/responses-review.md`의 **높음·중간·낮음 문제를 모두** 수정한다(참고는 판단). 기준: `docs/admin/responses-spec.md`(§12 우선), `CLAUDE.md`.

## 특히
* **높음 — 질문별 보기에서 버전이 다른 답이 섞임**: 질문의 정체성을 (앱 버전/매핑 스키마 + 질문 id + 질문 문구)로 구분해 같은 질문끼리만 묶는다. 다른 버전의 질문은 별도 묶음(예: "이전 버전 질문" 표시)으로 보여주고, 선택 수·정답 수 집계도 분리.
* **이름 치환**: 표시 이름이 없거나 이메일·아이디 형태이면 `{이름}` 자리를 자연스럽게 처리(예: 이름 없이 "오늘 활동을…"으로 시작하도록 문장 정리, 또는 교사가 확인 화면에서 이름 없는 학생을 미리 보게). 전송 전 미리보기에서 실제로 나갈 문장을 학생별로 확인 가능하게.
* **sci-6-1-1-6 "참고 자료를 열어 봤나" 값**: 앱 코드를 확인해 매핑이 실제 저장 값을 올바르게 해석하도록 수정(앱 코드는 수정하지 않는다 — 학생이 이미 사용).
* **1단원 실제 기록 브라우저 확인**: 1단원 앱 최소 2개(sim 1, guide 1)를 가짜 로그인으로 **실제로 끝까지 진행**해 만든 detail을 가짜 DB에 넣고 학생 응답 화면에서 확인.
* **중복 칭찬**: "이미 보냄"을 최신 결과만이 아니라 그 학생·그 앱 기준으로 판정(다시 하기 포함), 응답 유실 후 재시도 시 중복 전송 방지(보내기 전 최신 상태 재조회 또는 멱등 처리).
* 낮음 항목 전부.

## 수정 범위
`src/**`, `src/data/app-responses/**`. 필요하면 **새** 마이그레이션 파일(`supabase/migrations/20260922030000_*.sql`, 재실행 안전)만. 앱 폴더·공통 틀·기존 마이그레이션 수정 금지. git commit/push·실 DB 쓰기 금지.

## 검증
lint·tsc·`npm run build`(개발 서버가 떠 있으면 빌드 산출물 충돌에 주의 — 필요하면 빌드 후 개발 서버가 정상인지 확인) 통과. 가짜 DB로: 질문별 보기 버전 분리, 이름 없는 학생 미리보기·전송, 중복 칭찬 방지, 부분 실패 재시도, 1단원 실제 기록 표시, 태블릿·375px·다크모드, 콘솔 오류 0. 브라우저는 자기 탭 또는 자기 전용 headless만, `localStorage.clear()` 금지. 임시 파일은 스크래치에만.
