# Build 서브에이전트 지침: 로그인 잠금 범위 고치기 (2026-09-23 사용자 결정)

지금 구현(마이그레이션 `20260923010000_login_required.sql` + 화면)은 잠금을 켜면 **사이트 전체**가 가려진다. 사용자가 원한 범위는 다르다. 아래대로 바꾼다.

## 확정된 동작
| 상태 | 홈·메뉴 | 블로그 글 | 자유게시판(읽기·쓰기) | 학습게임 글 | 과학 시뮬레이션 앱 |
|---|---|---|---|---|---|
| 잠금 **꺼짐**(기본) | 다 보임 | 누구나 읽기 | 누구나 읽기, 쓰기는 로그인 | 누구나 읽기 | **비로그인도 실행 가능** — 기록 저장 안 됨 |
| 잠금 **켜짐** | 다 보임(메뉴·홈 화면 자체는 그대로) | **로그인 필요** | **로그인 필요** | **로그인 필요** | **로그인 필요**(지금 동작) |

* 홈 화면은 잠금과 상관없이 열리고 레이아웃이 그대로여야 한다. 데이터를 읽지 못하는 칸(최근 글·게시판·게임 미리보기)은 오류가 아니라 **"로그인하면 볼 수 있어요"** 같은 안내로 바뀐다. 과학 수업 차시 목록(코드에 있는 데이터)은 계속 보인다.
* 로그인 화면·비밀번호 재설정은 잠금과 무관하게 늘 동작한다. 관리자는 항상 통과. 설정값(`site_settings`) 읽기는 절대 잠그지 않는다.

## 1. SQL — 새 마이그레이션(사용자가 실행, 재실행 안전)
`supabase/migrations/20260923020000_login_required_scope.sql`
* 게이트(`can_browse()`)를 **유지**: `posts`, `comments`, `community_posts`, `community_comments`, `community_likes`, `storage.objects`(game-uploads).
* 게이트를 **제거**(원래 정책으로 되돌림): `profiles`(이름 표시·메뉴가 깨지지 않게), `likes`, `views`, `assignments`. 각 정책을 `20260921000000_init_blog.sql`·`20260921020000_admin_learning.sql`의 원문과 1:1로 대조해 되돌린다.
* 파일 상단에 실행 방법·확인 쿼리(어떤 정책에 게이트가 남았는지 세는 쿼리 포함). 이미 실행된 두 파일은 고치지 않는다.

## 2. 과학 앱 — 잠금이 꺼져 있으면 비로그인도 실행
공통 틀 `scripts/templates/science-sim/persist.js`(+ 필요하면 `lesson.js`)와 `scripts/templates/science-guide/`, `scripts/templates/class1-record.js`를 고치고 **23개 앱 사본에 동기화**(`diff -r` 확인).
* 앱을 열면 `site_settings.login_required`를 읽는다(공개 읽기). 실패하면 **꺼짐으로 간주**(지금처럼 갇히지 않게).
* 꺼짐 + 비로그인 → 로그인 가림막 대신 **체험 모드**로 진행: 모든 단계 사용 가능, 입력은 이 기기(localStorage)에만, `app_progress`·`app_results` 호출 없음. 머리말이나 시작 화면에 한 줄: "로그인하면 기록이 저장돼요."(로그인 링크 포함)
* 꺼짐 + 로그인 → 지금과 완전히 동일(저장·이어서 하기).
* 켜짐 + 비로그인 → 지금처럼 로그인 안내 가림막.
* 체험 모드에서 로그인하면 이 기기에 남은 입력을 그 학생 기록으로 이어받을지 판단해 설계하고 보고서에 적는다(주인 확인 규칙을 깨지 않는 선에서. 간단히 "체험 기록은 이어받지 않고 지운다"도 가능 — 근거를 적을 것).
* 저장 키(`:vN`)·저장 구조(`app_progress.state`, `app_results.detail`/`detail.qa`)는 **바꾸지 않는다**.

## 3. 사이트 화면
* 홈(`src/app/page.tsx`와 관련 컴포넌트): 잠금 상태에서 읽기 실패한 섹션을 오류가 아닌 안내 카드로 바꾼다.
* 블로그 글 목록·상세, 자유게시판, 학습게임: 잠금 상태에서 비로그인이면 로그인 안내(지금 구현 재사용).
* 관리자 토글 화면의 설명 문구를 새 범위에 맞게 고친다(무엇이 막히고 무엇이 안 막히는지 그대로 적기).

## 규칙
git 명령 금지, 실 DB·Storage 쓰기 금지, 실제 Auth·Gemini 호출 금지(가짜 응답으로 시험), 브라우저는 자기 전용 headless만(자기 포트), `localStorage.clear()` 금지. lint·tsc·`npm run build` 통과.

## 검증(가짜 Supabase 응답)
잠금 꺼짐/켜짐 × 로그인/비로그인 4가지로: 홈·블로그·게시판·게임·과학 앱 1개(실험)와 1개(조사)를 실제로 열어 확인. 체험 모드에서 끝까지 진행해도 저장 호출이 0건인지, 로그인 상태에서는 지금처럼 저장되는지 확인. 태블릿·375px·다크·콘솔 오류 0.
