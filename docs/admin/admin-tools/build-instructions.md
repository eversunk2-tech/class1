# Build 서브에이전트 지침: 관리자 기능 2가지 (2026-09-23 사용자 승인)

설계: `docs/admin/admin-tools/spec.md` — **끝의 "개정 1"이 본문 추천안보다 우선**(A는 계정 정지가 아니라 **완전 삭제 + 기록 보존**). `CLAUDE.md`(정적 export 제약, SQL 적용 절차, 커밋·배포 규칙)도 읽는다.

## 만들 것
1. **A. 회원 완전 탈퇴**(관리자 > 회원 관리): Edge Function(예: `supabase/functions/admin-delete-member/`)에서 호출자 관리자 검증 → `auth.admin.deleteUser(targetId)` → `profiles.withdrawn_at` 기록. 관리자 자신·다른 관리자 차단. 화면: 케밥 메뉴 → 확인 창(이름 입력 + 경고) → 결과·실패 사유 표시, 목록에서 "탈퇴한 학생" 표시.
2. **B. 로그인 필수 토글**: `site_settings` + `login_required()` + 정책 수정(설계 §2.2 표대로 빠짐없이), 관리자 화면의 켜고 끄기 버튼(현재 상태·마지막 변경 시각·변경자 표시), 비로그인 방문자 화면 처리(로그인 안내), 설정값 캐시·반영 지연 안내.
3. **마이그레이션 2개**(새 파일, 재실행 안전, 파일 상단에 실행 방법·확인 쿼리): 탈퇴용(FK/제약 변경 포함), 로그인 잠금용. **사용자가 직접 실행**하므로 Claude/서브에이전트는 실 DB에 쓰지 않는다.

## 반드시 지킬 것
* **기록 보존이 핵심**: `auth.users` 행을 지워도 `profiles`와 그 학생이 남긴 모든 행(앱 결과·진행·댓글·좋아요·조회·게시글·신고·피드백·과제 등)이 남아야 한다. 마이그레이션 작성 전에 **현재 제약을 전부 조사해 표로 정리**하고, 바꾸는 제약마다 이유를 적는다. 빠진 cascade가 하나라도 있으면 기록이 사라지므로 특히 꼼꼼히.
* **자물쇠 방지**(B): `site_settings` 읽기는 절대 잠그지 않는다. 로그인·비밀번호 재설정 경로는 잠금 상태에서도 동작해야 한다. 관리자는 항상 통과.
* **RLS**: 정책 안에서 같은 표를 다시 조회하지 않는다(42P17). `security definer` 함수는 `set search_path = ''`.
* 정적 export 제약(서버 기능 금지), 내부 링크 `next/link`, basePath 규칙 준수. lint·tsc·`npm run build` 통과.
* git 명령 금지(커밋은 Claude가 한다), 실 DB·Storage 쓰기 금지, 실제 Auth Admin API 호출 금지(가짜 응답으로 시험). 브라우저는 자기 전용 headless만(자기 포트), `localStorage.clear()` 금지.

## 검증(가짜 Supabase 응답으로)
* 탈퇴: 관리자 아님 → 거부, 자기 자신·관리자 대상 → 거부, 이름 확인 불일치 → 실행 안 됨, 성공 후 목록 표시·기록 유지, 함수 실패 시 화면 메시지.
* 토글: 켜기/끄기, 비로그인 방문자 화면, 관리자 화면 접근, 새로고침 후 상태 유지, 설정 읽기 실패 시 안전한 기본값(잠그지 않음).
* 마이그레이션 SQL은 문법·재실행 안전성·제약 이름 충돌을 코드로 꼼꼼히 검토(로컬 Postgres 없음).
