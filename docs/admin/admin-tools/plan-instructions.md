# Plan 서브에이전트 지침: 관리자 기능 2가지 (2026-09-23)

사용자 요청 2가지를 설계한다. 결과는 `docs/admin/admin-tools/spec.md` 하나.

## A. 회원 강제 탈퇴 (관리자 대시보드 > 회원 관리)
* **사용자 결정: 학습 기록은 남기고 계정만 삭제한다.** 탈퇴 뒤에도 관리자 대시보드에서 그 학생의 앱 결과·댓글·게시글을 계속 볼 수 있어야 하고, 작성자 표시는 "탈퇴한 학생" 같은 문구로 바뀐다.
* 방법을 비교해 추천안을 정한다(근거 명시):
  (a) **계정 차단(ban)**: Auth Admin API로 로그인만 막고 행은 그대로 둔다 — 되돌릴 수 있고 기록이 온전하다.
  (b) **실제 삭제 + 기록 보존**: `auth.users` 행을 지우고, 참조하는 표들의 FK를 `on delete set null` 등으로 바꿔 기록을 남긴다(이름은 스냅샷 필요). 되돌릴 수 없고 SQL 변경이 크다.
  둘을 섞는 안(차단을 기본, 완전 삭제는 별도 버튼)도 검토.
* 현재 스키마를 직접 읽고(특히 `supabase/migrations/20260921000000_init_blog.sql`, `20260921020000_admin_learning.sql`, `20260922040000_community.sql`) `profiles`·`app_results`·`app_progress`·`comments`·`likes`·`views`·`post_reads`·`feedback_*`·`community_*`의 FK와 `on delete` 규칙, not null 여부를 표로 정리한 뒤 설계한다.
* service_role이 필요하므로 Edge Function(`supabase/functions/`)으로 한다. 기존 `admin-reset-password`를 본보기로 하고, **호출자가 관리자인지 함수 안에서 검증**한다. 관리자 자신·다른 관리자를 지울 수 없게 막는다.
* 되돌리기 어려운 작업이므로 화면에서 확인 절차를 둔다(예: 학생 이름을 그대로 입력). 처리 결과·실패 사유를 분명히 보여 준다.
* 탈퇴 후 그 학생의 로컬 기기에 남은 과학 앱 입력(`sci6…`)·세션은 어떻게 되는지도 적는다.

## B. "로그인해야만 이용" 켜고 끄기 (관리자 대시보드 버튼)
* **사용자 결정: 화면뿐 아니라 데이터(RLS)까지 잠근다.** 켜면 비로그인 방문자는 글·댓글·게시판·게임·과학 앱 내용에 접근할 수 없어야 한다(검색엔진에도 안 보임).
* 설정값은 DB에 둔다(예: `site_settings` 표, 누구나 읽기·관리자만 쓰기). 정적 사이트이므로 클라이언트가 이 값을 읽어 화면을 가린다.
* RLS 잠금은 **`security definer` 함수**(예: `public.login_required()`)를 만들어 각 읽기 정책에 `(not public.login_required()) or auth.uid() is not null` 식으로 더한다. **정책 안에서 같은 표를 조회하지 않는다(42P17)**. 어떤 표의 어떤 정책을 바꾸는지 전부 표로 적는다.
* 다음을 반드시 검토해 설계에 적는다: 켠 상태에서도 **로그인 화면·비밀번호 재설정·설정값 읽기 자체는 되어야** 한다(자물쇠에 갇히지 않게). 관리자가 실수로 켜서 스스로 못 들어가는 경우가 없어야 한다. 캐시(정적 페이지·브라우저)로 인해 바로 반영되지 않는 부분과 그 한계도 적는다.
* 버튼은 관리자 대시보드에 두고, 지금 상태(켜짐/꺼짐)와 마지막 변경 시각·변경자를 보여 준다. 잘못 눌렀을 때 바로 되돌릴 수 있어야 한다.
* SQL은 **새 마이그레이션 파일 초안**으로 적는다(사용자가 직접 실행, 재실행 안전, 확인 쿼리 포함). 이미 실행된 파일은 고치지 않는다.

## 공통
* `CLAUDE.md`(정적 export 제약, SQL 적용 절차, 규칙)와 `docs/admin/spec.md`, `src/app/admin/**`, `src/lib/learning.ts`, `src/lib/auth.ts`(있다면), `supabase/functions/admin-reset-password/**`를 읽고 지금 구조에 맞춘다.
* 화면 설계(회원 관리 표의 버튼 위치, 확인 창 문구, 토글 위치), 실패·권한 오류 처리, 접근성(키보드·색 외 표시)도 적는다.
* 단계별 작업 계획과 **사용자가 할 일**(SQL 실행, 함수 배포 명령)을 분리해 적는다.
* 열린 질문은 추천안을 붙인다.
