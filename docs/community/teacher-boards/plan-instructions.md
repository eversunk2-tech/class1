# Plan 지침 — 자유게시판을 담임교사별로 (2026-09-28)

## 사용자 요청(문구 그대로)
> 자유게시판 보기에 문제가 있어. 담임교사(총괄)가 생성한 계정이 아니어도 로그인 하니 총괄 관리자의 자유게시판 사용이 가능하게 나와. 학생은 해당 담임교사의 자유게시판만 사용할 수 있도록 하는게 나의 의도였는데 반영이 잘못된 것 같아. 같은 담임교사이면 학급이 다른 학생들도 같은 자유게시판을 이용할 수 있지만, 담임교사(총괄 계정 포함)의 개설 학급 학생이 아니면 그 담임교사(총괄 포함)의 자유게시판은 이용 못 하도록 해줘. 그 담임교사의 자유게시판이 나타나는 것으로 이해했었는데 그렇게 개발되지 않았나봐.

## 이미 정한 것(사용자 답 2026-09-28 — 모두 추천안)
1. **게시판 = 담임교사 한 명마다 하나.** 그 교사가 담임인 학급(`class_teachers`)의 학생들이 함께 쓴다(학급이 여러 개여도 한 게시판). 그 교사의 학급 학생이 아니면 그 게시판을 볼 수도 쓸 수도 없다. 학급이 없는 계정(구글·깃허브로 들어온 계정 등)은 자유게시판을 쓸 수 없다.
2. **담임이 두 명인 학급**: 학생은 **두 담임의 게시판을 모두** 본다 — 게시판이 둘 이상이면 위에서 "○○ 선생님 게시판"을 고르고, 하나면(지금처럼) 고를 것 없이 바로 그 게시판.
3. **총괄**: 자기 게시판(자기가 담임인 학급 학생들과)을 쓰고, **관리용으로 모든 게시판을 볼 수 있다**(신고 처리·숨기기·삭제 — 다른 담임 게시판에 글은 쓰지 않음). 학생 학습 기록처럼 다른 반을 못 보게 하는 규칙과는 다르다(게시판 관리 책임).
4. **학습게임**(`community_posts.kind='game'`)은 **지금처럼 모두 함께**(로그인 잠금 스위치대로) — 바꾸지 않는다.
5. **지금까지 올라온 자유게시판 글**: **글쓴이의 담임 게시판**으로 — 학생 글은 그 학생 학급 담임의 게시판(지금 학생은 모두 부엉이반, 담임 = 총괄), 교사가 쓴 글은 그 교사의 게시판, 학급 없는 계정의 글·글쓴이 없는 글은 총괄 게시판. 학급 담임이 둘 이상이면 규칙을 정해 적는다(추천안).

당신은 **Plan** 담당이다. **계획서만 쓴다** — 코드·SQL 파일을 만들거나 고치지 않는다. 결과물: `docs/community/teacher-boards/spec.md` 하나(한국어). 실 DB에 쓰지 않고 외부 요청도 하지 않는다(저장소 SQL·코드로 판단). 저장소가 공개라 개인정보(이메일·학생 이름)를 쓰지 않는다.

## 계획서에 담을 것
1. **지금 상태**: 자유게시판 글·댓글·좋아요·신고의 읽기·쓰기 정책(누가 무엇을), 화면의 모든 진입점(목록·글·쓰기·홈 미리보기·글 수·검색·신고 관리·알림 등), 학습게임과 같은 표를 쓰는 부분.
2. **데이터 설계**: 게시판을 무엇으로 가르나(추천: `community_posts`에 게시판 주인 교사 열 — 예 `board_owner uuid` — `kind='board'`만 필수, 게임은 null), 외래키 on delete(교사 계정이 담임 해제되거나 완전 삭제될 때 그 게시판 글은? — 추천안), 인덱스, 기존 글 옮기기(위 5 — 담임이 둘 이상인 학급 규칙 포함, 재실행 안전한 한 번짜리 갱신).
3. **권한(RLS)**: 누가 어느 게시판 글·댓글·좋아요·신고를 보고·쓰고·고치고·지우나 — 학생(자기 학급 담임들의 게시판), 담임(자기 게시판 — 담임 해제되면?), 총괄(모든 게시판 보기·관리, 쓰기는 자기 게시판), 학급 없는 계정(없음), 비로그인(없음). 판별은 `security definer` 함수로(정책 안에서 같은 표 다시 조회 금지 — 댓글·좋아요·신고 정책이 글 표를 볼 때도 함수로). 쓸 때 게시판 주인 검사(아무 게시판에나 쓰지 못하게 — 트리거나 with check), 글쓴이가 학급을 옮기면 예전 게시판 글은?(추천안). 학습게임 정책은 그대로인지 확인.
4. **화면**: 게시판이 하나/여럿/없음일 때의 목록 머리(게시판 고르기, "○○ 선생님 게시판" — 이름 표시 규칙: 학생 화면에 학급 이름은 보이지 않는다는 규칙과 맞게), 글쓰기가 어느 게시판에 가는지, 글 상세 주소로 다른 게시판 글을 열 때, 홈 미리보기·글 수, 검색 결과, 관리자 신고 관리(담임 = 자기 게시판 신고, 총괄 = 모두), 총괄의 관리용 보기(글쓰기 없음), 학급 없는 계정 안내 문구.
5. **바꿀 것 목록**: 새 마이그레이션 SQL(파일 이름 제안 — `supabase/migrations/2026092801…_teacher_boards.sql` 식, 앞선 파일 고치지 않음, 파일 위 실행 방법·확인 쿼리, 맨 끝 점검, 되돌리기 방법), 화면 파일, `CLAUDE.md` 개정 문구(커뮤니티 규칙 "로그인한 사용자 누구나 글·댓글·좋아요·신고" → 담임별 게시판), 완전 삭제 SQL(`admin_purge_oauth_member`)과의 관계(게시판 주인이 지워질 때).
6. **배포 순서**: SQL 실행(사용자) → 확인 → push(화면이 새 열에 의존하면 SQL 먼저). 새 SQL이 없을 때 화면이 안전하게 동작하는지(지금처럼 보이거나 "준비 중").
7. **시험 계획**: 가짜 응답으로 확인할 것(화면 — 학생 A(총괄 반)·학생 B(다른 담임 반)·담임 둘인 학급 학생·학급 없는 계정·담임·총괄), 실 DB에서 사용자가 확인할 것(anon·로그인 계정으로 다른 게시판 글이 안 보이는지), 되돌리기.
8. **열린 질문**(추천안 포함 — 이미 정한 1~5 말고 남은 것만): 예) 담임 해제된 교사의 게시판 글 처리, 글쓴이가 다른 학급으로 옮겼을 때, 게시판 이름 표시 방식, 총괄이 관리용으로 볼 때 화면 구분.
