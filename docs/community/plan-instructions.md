* 글쓰기: **로그인한 사용자 누구나**(학생·교사). 읽기는 기존 원칙(비로그인 읽기 가능)을 따르되 설계에서 확인.
* 학습게임: **올리면 바로 공개**(교사는 숨기기·삭제 가능).

* 두 게시판 모두 **댓글과 좋아요** 포함(교사는 댓글도 숨기기/삭제).
* 작성자는 자기 글·댓글 수정/삭제.

## 반드시 다룰 설계 이슈
1. **업로드 게임 보안 (최우선)**: 사이트는 같은 출처 localStorage에 Supabase 세션을 둔다. 업로드 HTML은 **절대 같은 출처로 실행하지 않는다.**
   * 실행 방식: `<iframe sandbox="allow-scripts">`(**allow-same-origin 금지**, top-navigation·popups·forms·modals 정책 결정) + `srcdoc` 또는 blob URL. 불투명 출처라 사이트 쿠키·localStorage·부모 DOM 접근 불가. CSP(`<meta http-equiv>` 주입 가능 여부) 검토. 게임 안 localStorage 불가로 생기는 제약 안내.
   * 저장: Supabase Storage(버킷·RLS·공개 여부·Content-Type — **HTML을 사이트 출처나 Storage 공개 URL에서 직접 열지 않도록**, 브라우저가 문서로 렌더링하지 못하게) vs DB 텍스트 컬럼. 크기 제한(예: 2MB), 파일 형식 검사(.html 한 개, UTF-8), 여러 파일 게임은 미지원(인라인·CDN만).
   * 전체 화면, 태블릿 터치, 소리, 무한 루프·과부하 게임에 대한 대응(정지 버튼·iframe 제거).
   * 신고하기(선택) 제안, 교사 숨기기/삭제, 작성자 삭제.
2. **자유게시판**: 글(제목·본문, 마크다운 여부 — 학생 글은 XSS 위험 → 일반 텍스트 또는 제한 마크다운 + DOMPurify), 이미지 첨부 여부(추천안), 목록·상세·작성·수정 화면, 쿼리스트링 라우팅(정적 export).
3. **DB 설계**: 기존 `posts`(관리자 블로그 글)와 분리할지(새 `board_posts`, `game_posts` 또는 통합 `community_posts(kind)`) 비교·추천. 댓글·좋아요: 기존 `comments`/`likes`(posts FK) 재사용 가능 여부 또는 새 테이블. RLS: 로그인 사용자 작성, 본인 수정·삭제, 관리자 숨기기(`hidden`)·삭제, 숨긴 글은 작성자·관리자만. 남용 방지(작성 속도 제한, 글자 수 제한). 재실행 안전 SQL 초안.
4. **메뉴·라우트**: 수학수업 메뉴·페이지 삭제(기존 `/math/` 링크 처리), 자유게시판 메뉴(아이콘·색 토큰), 학습게임 메뉴 개편. 사이드바·모바일 드로어·홈 바로가기 카드.
5. **홈 화면**: 최근 소식·인기글·최근 수학 수업 제거. **최근 과학 수업**(차시별 앱 현황: 예) 단원별 앱 수, 최근에 만든/연결된 차시 앱 목록과 바로가기, 실험/조사 구분), **최근 자유게시판**, **학습게임 미리보기** 3개만. 과학수업 카드 숫자를 차시 앱 개수(현재 12)로 — 집계 기준(과학 글 수 + 앱 수? 앱 수만?) 추천.
6. **관리자**: 숨기기/삭제 관리 화면(또는 각 글에서), 신고 목록(채택 시).
7. 정적 export·basePath·한국어·모바일·다크모드.
