## 사용자가 정한 것(합격 기준)
* 2-1-2: **나무(측정 대상) + 작은 사람(장식)**, 태양을 **직접 끌면 시각이 바뀌고 시간 바와 양방향**, **평행한 옅은 빛줄기 + 나무 꼭대기를 지나 그림자 끝까지 또렷한 한 줄**, 그 선과 땅의 각 = 태양 고도를 **작은 호**로, 값은 **측정값 패널**에만(3D 값 이름표·큰 각도기 없음), 해·빛줄기·그림자·호가 **한 태양 방향에서** 계산되어 늘 맞음. "학생들이 흥미 있게".
* 2-1-3: 궤적 보기는 **"이번 달만"(기본) / "계절 대표 3개(봄·가을 한 선, 여름, 겨울)"** 두 가지뿐(기록한 달이 계속 남는 보기 없음).
* 2-1-4: 예상 질문이 **정확히** "여름과 겨울 중 언제 기온이 더 높았나요? 그리고 그 때 한낮의 태양의 높이는 어떠했나요?"(한 글자도 다르면 불합격), 힌트·칸 안내가 답(여름·높다)을 말하지 않음, 손전등 끌기.
* 2-1-5: 자리(가~라)로 옮겨 확대할 때 **전체 화면의 좌우·전등 방향이 그대로**(거울처럼 뒤집히지 않음), 확대 화면에 전등 방향 표시, 측정 장치 **확대 칸의 그림자 길이 순서 = 교과서 표 값 순서**.
* 4개 모두: 기본 화면·"⛶ 전체 화면 보기"(크게 보기) **두 모드**에서 겹침·잘림 없음, 크게 보기의 장면 안 막대에 측정값과 기록하기, 태블릿 세로(768×1024)는 크게 보기가 기본, 글자가 다른 것을 가리지 않음, 싱크가 맞음, 측정 조건·측정값·저장 키·`detail` 모양은 그대로(2-1-4 예상 질문 id 변경만 예외).

## 확인할 것
1. **과학적 정확성(앱마다 별도 항목, 숫자로)**:
   * 2-1-2: 7개 시각(9:30~15:30)과 눈금 사이 몇 곳에서 — 태양 구의 방향 = 빛줄기 방향 = (나무 꼭대기 → 그림자 끝) 방향, 호의 각 = 패널의 태양 고도 = 자료 값, 그림자 길이 = 나무 높이/tan(고도)와 패널 값(자료)의 관계(모형이면 "모형" 표시), 그림자 방향이 태양 반대, 기온 값이 자료 그대로. 태양을 끌어 놓은 곳의 시각 = 시간 바 = 패널.
   * 2-1-3: "계절 대표 3개"가 3월(봄·가을)·6월·12월 값으로 그려지는지, "이번 달만"이 고른 달만 그리는지, 12칸 기록·남중 고도·낮의 길이 값 그대로.
   * 2-1-4: 손전등 각도 = 슬라이더 = 패널, 30°·80° 값 그대로, 빛 자국 넓이·빛의 세기 관계가 전과 같게.
   * 2-1-5: 8경우(가·나·다·라 × 수직·기울임) 스크린숏과 좌표 — 전체 화면 전등 방향 = 확대 화면 전등 방향 = 측정기 방향, 그림자는 반대쪽, 확대 칸 그림자 길이 순서 = 표 값 순서, 표 값 그대로.
   * 공통: "모형" 표시, 학생 화면에 "지도서" 없음.
2. **답을 먼저 알려 주지 않기**: 실험하기·기록 순간의 모든 글(알림, 관찰 안내, 이름표, 패널 문구, 힌트, 확대 칸 설명)에 "~할수록 ~해요", 원인 단정, 정답과 같은 말이 없는지 — 목록으로.
3. **두 모드 × 화면 크기**: 768×1024(크게 보기 기본)·1024×768(기본 끔 → 켬)·1180×820·1280×800·375×812·812×375·어두움·2D(`?no3d=1`), 머리말 펼침·접힘. 겹침(3D 이름표끼리, 이름표↔측정 지점, HUD↔토글, 확대 칸↔막대), 잘림, 가로 스크롤, 막대가 아래 이동 막대와 겹침, 크게 보기 가로에서 장면+막대가 스크롤 없이. 2-1-3·2-1-4에 새로 연결한 토글이 다른 앱과 같게 동작(기본값·방향별 기억·끄면 원래 자리).
4. **직접 조작**: 태양·손전등·지구본 끌기를 마우스와 터치(`Input.dispatchTouchEvent`)로 — 따라 움직임, 놓으면 알맞은 값·자리에 붙음, 끄는 동안 카메라가 돌지 않음, 빈 곳 끌기는 카메라 회전, 두 손가락, 작은 화면에서 잡기 쉬움, 버튼·슬라이더·시간 바와 동기화, 조작 단계·시간이 늘지 않음.
5. **시점 방향(모든 카메라 이동)**: 각 앱의 시점 버튼·`focus`·`closeUp`·"처음 방향으로"에서 좌우가 뒤집히지 않는지.
6. **끝까지 흐름·시간**: 예상하기 → 실험(필수 칸 모두 기록) → 분석 → 정리 → 더 탐구하고 싶은 점 → 학습 마치기(체험 모드, 그리고 가짜 로그인으로 `app_results` POST 본문 확인 — `detail`·`detail.qa` 모양이 전과 같은지, 2-1-4는 새 질문 id·문구가 qa에 들어가는지). 새로 고침 뒤 이어 하기. 7분 시간표(각 앱 spec)를 넘는지 추정.
7. **규칙·정리**: 공통 틀 사본 `diff -r` 일치(바뀌면 안 됨), 저장 키 그대로, 임시 코드·`console.log`·`debugger` 없음, `localStorage.clear()` 없음, 앱 안 상대경로, 새 외부 자원 없음, 콘솔 오류 0(두 모드), `npm run lint`.
8. **성능 느낌**: 2-1-2 새 장면(나무·사람·빛줄기) 끌기 중 프레임(headless swiftshader 기준 상대 비교 — 전 버전과), 3D↔2D 10번 전환 시 캔버스·수신기 쌓임 없음.
