## 5. 확인하지 못한 것
- 실제 iPad·태블릿, 실제 계정·실 DB, 실제 로그인 만료. 로그인 풀림은 `getUser()` 흉내로만 봤다.
- 사이트 잠금이 **켜진** 경우. 가짜 서버는 늘 꺼짐이다. 켜짐이면 로그인 안내 가림막이 화면을 덮고, 문구는 예전과 같은 "로그인이 풀렸어요…"를 고른다(코드로 확인).
- 학교 망에서 사이트 설정이 6초 넘게 걸리는 경우. 가짜 1.5초 지연으로만 봤다. 코드상 persist.js가 6초에 "잠금 꺼짐"으로 정하고, 안내는 그 뒤에 나온다.
- 이름표: 멈춘 상태 160개(+사진 40장)만 비교했다. 끌어 돌리는 도중의 모든 장면을 비교하지는 않았다(같은 계산을 매 장면 하므로 같다고 본다).

## 6. 사용자·검토에게 물을 것
1. **(사용자) 정리하기 '제출한 글만' 결과에 넣기를 실험 앱에도 맞출지**
   - 지금 차이: 조사 앱은 제출한 뒤 고친 글을 다시 제출해야 결과에 들어간다. 실험 앱은 "위에서 고쳐 써도 좋아요"라서 고친 글이 바로 결과에 들어간다.
   - 맞추면 실험 앱 진행 기록 모양(`sent` 칸)과 결과 글이 달라진다. 그래서 이번에는 옮기지 않았다.
2. **(사용자) 조사 앱의 휴대폰 가로 머리말 줄이기**: 실험 앱에만 있는 낮은 화면(높이 480px 이하) 머리말·단계 막대 줄이기를 조사 앱에도 넣을지. 나중에 휴대폰 화면 다듬기 때 함께 정하면 된다.
3. **(검토)** 도우미 `autoHideLabels`는 기본으로 `scene.onBeforeRender`에 이어 붙는다. 부른 **뒤에** 앱이 `onBeforeRender`를 새로 대입하면 떨어진다. 그런 앱은 `manual: true`를 쓰도록 README·주석에 적었다(6-2-2-4가 그 예).
4. **(검토)** 체험 안내를 기다리는 방식은 phase를 100ms마다 보는 것이다(`persist.js`는 고치지 않음, `lesson.js`만 고침). persist.js에 "정해짐" 알림을 새로 두는 방법도 있지만, 저장·동기화 핵심 파일이라 건드리지 않았다.
