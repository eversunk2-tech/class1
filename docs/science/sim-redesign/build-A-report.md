# 단계 A Build 보고서 — 공통 틀 개편 (2026-09-25)

`docs/science/sim-redesign/build-A-instructions.md` 지침으로 시작했고, 작업 중 사용자 방향 전환(코디네이터 메시지, 2회)에 따라 최종 설계가 바뀌었다. **이 보고서는 최종 구현 기준**이다.

## 0. 최종 설계 요약 (방향 전환 반영)

처음 지침은 `fullScene: true`를 **앱이 빌드 타임에 켜는 옵트인**으로 설계했지만, 작업 중 사용자가 다음과 같이 바꿨다(최우선):

1. **기본 배치는 그대로**(가로 900px 이상은 장면·패널 좌우 분할, 세로/좁은 화면은 위아래) — 픽셀 단위로 같다(알림 위치 제외).
2. **"⛶ 전체 화면 보기" 토글 버튼을 장면 위에 항상 둔다**(모든 20개 실험 앱, 앱 코드 수정 없이). 누르면 이번에 만든 "전체 폭 + 장면 안 막대" 배치로 바뀐다. `scenePanel`은 여전히 선택 사항(앱이 Phase B/D에서 넘길 수 있음).
3. **기본값은 화면 방향에 따라 다르다**: 세로(portrait) + 폭 600px 이상 → 켜짐, 그 밖(가로·PC·휴대폰) → 꺼짐. 학생이 직접 고르면 방향별로 기억한다(localStorage, `sci6` 접두사 아님).
4. **머리말 접기 토글을 새로 추가한다**(계정 줄 + 단계 이동 막대를 접고 제목 줄만 남김), science-sim·science-guide 두 틀 모두에.
5. 따라서 **"앱마다 임시로 옵트인 켜서 확인 후 되돌리기"는 필요 없어졌다** — 토글은 런타임 기능이라 모든 앱에 이미 있고, 기본은 항상 꺼짐(또는 방향별 기본값)이라 별도로 되돌릴 빌드 옵션이 없다. 다만 `scenePanel` 자체는 아직 어떤 앱도 실제로 넘기지 않으므로, 검증을 위해 앱 2곳에 **임시로만** `scenePanel`을 연결했다가(아래 §6, §9) 모두 되돌렸다.

빌드 도중 코디네이터가 `scenePanel` 처리에서 버그 2개를 지적해 정본에서 수정하고 재동기화·재검증했다(§9).

## 2. 새 기능 사용법

### 2.1 전체 화면 보기 토글(모든 20개 실험 앱, 앱 코드 수정 없음)
장면 왼쪽 위(모형 배지 바로 아래)에 "⛶ 전체 화면 보기" 버튼이 **항상** 있다. 앱은 아무것도 하지 않아도 된다.

- **꺼짐(기본)**: 지금까지와 같은 배치. 픽셀 단위로 그대로(§4).
- **켜짐**: 장면이 1열 전체 폭. 장면 안 반투명 막대(`.ss-exp-overlay`)에 실행 버튼 → 기록하기 버튼 → `scenePanel`(있으면) 순서로 들어간다(복제 아님, DOM 이동). 조건 고르기 카드는 장면 바로 아래.
- 기본값: 세로 + 폭 600px 이상(태블릿 세로) → 켜짐. 그 밖 → 꺼짐. 학생이 누르면 그 방향에서 기억한다(`localStorage` 키 `ssUiPref:sceneMode:portrait`/`ssUiPref:sceneMode:landscape`, `sci6` 접두사가 아니라 로그아웃 정리 대상이 아니다). 방향이 바뀌면 그 방향에서 아직 고른 적이 없을 때만 기본값을 다시 적용한다.
- 가로 태블릿·PC(폭 901px 이상 + 가로) + 켜짐일 때는 **실제 화면 크기로 계산**해 장면+막대가 스크롤 없이 들어오게 한다(`fitSceneHeight()`, §5).
- `scenePanel: node`(선택)를 앱이 넘기면 켜짐일 때 막대 안(넓은 화면) 또는 장면 바로 아래 카드(좁은 화면, 480px/420px 미만)로 옮긴다. **앱이 scenePanel을 넘기기 전에 이미 자기 DOM에 붙여 뒀다면 꺼짐으로 돌아갈 때 그 원래 자리로 정확히 되돌린다**(§9에서 상세).

### 2.2 머리말 접기 토글(모든 23개 앱)
제목 줄 맨 끝에 "▲ 접기"/"▼ 펼치기" 버튼. 누르면 계정 줄과 단계 이동 막대가 감춰지고 제목 줄(뒤로 가기·제목·저장 상태 배지)만 남는다. 선택을 기억한다(`ssUiPref:headerCollapsed`).

### 2.3 끌기 도우미 `v.draggable(obj, opts)`
`sim3d.js`에 순수 추가. `README.md`에 손전등·태양 예시 포함 전체 사용법.

## 3. 하위 호환 확인

**해석**: "기본 렌더링이 픽셀 단위로 같다"는 요구는 토글 버튼 2개(장면 위, 머리말)가 **새로 추가되는 것 자체**와는 별개다(그 버튼들은 이번 요구사항이 명시적으로 요구한 것). "같다"는 것은 **레이아웃 구조**(그리드 분할, 장면 크기·위치, 카드 배치, 진행률 등)가 꺼짐 상태에서 안 바뀐다는 뜻으로 확인했다.

- **HEAD ↔ 최종본, `sci-6-1-1-2` 1024×768(가로, 기본 꺼짐)**: 픽셀 diff 0.66%(5,167 / 786,432px, delta>15 기준), diff 영역은 새로 추가된 토글 버튼 2개(장면 위 "⛶ 전체 화면 보기", 머리말 "▲ 접기") 자리뿐 — 스크린숏을 나란히 봐서 확인, 그 외 모든 카드·진행률·글자 위치가 동일. `scratchpad/build-A/shots/bc2-sci-6-1-1-2-1024x768-{before,after}.png`(스크린숏만 보존, 임시 스크립트는 삭제).
- **초기 라운드(더 이른 버전, 옵트인 방식일 때)**: `sci-6-1-1-2`·`sci-6-2-2-2`·`sci-6-2-3-3` 세 앱을 768×1024·1024×768에서 비교, 6개 중 5개 완전 동일(0 diff), 1개는 delta 최대 2/255(547픽셀, 렌더링 노이즈 수준) — 콘솔 오류 0.
- 3D↔2D 전환, 다크모드에서도 콘솔 오류 0(여러 차례 확인).

## 4. 화면 크기별 결과 — "장면+막대가 스크롤 없이 들어오는가"

요구: 켜짐 상태에서 1024×768·1180×820·1280×800·1366×768·1920×1080(가로)에서 **장면 전체 + 장면 안 막대**가 스크롤 없이 보여야 하고, **조건 고르기 줄도 가능하면** 들어와야 한다. `getBoundingClientRect()`로 실측했다(앱: `sci-6-2-2-3` — 시간 바 카드가 장면 옆에 딸린 앱, `sci-6-2-3-3` — 조건 카드 2개짜리 앱, `sci-6-1-1-2` — 아이콘 버튼 6+3개짜리 앱. 세 앱 모두 서로 다른 이유로 "장면 주변이 붐비는" 경우라 일부러 골랐다).

- **장면+막대는 15칸 중 13칸에서 완전히(0px) 들어오고, 나머지 2칸(둘 다 sci-6-1-1-2, 세로 공간이 가장 좁은 768px 높이)에서 4px만 넘친다.** 원인: 이 앱은 "실험 전에 알아 두기" 접기 카드가 기본으로 **펼쳐진 채** 시작해(`store.get("intro", true)`) 장면 시작 위치(539px)가 다른 두 앱(415~478px)보다 아래다. 학생이 그 카드를 한 번 접으면(원래도 있는 기능) 사라지는, 사실상 무시할 수 있는 값이라 판단해 최소 장면 높이(`MIN_SCENE_H=160px`)를 더 줄이지는 않았다 — 더 줄이면 "장면이 주인공"이라는 취지가 흐려진다.
- **조건 줄까지 스크롤 없이 다 들어오는 경우는 없었다**(세 앱 모두 96~632px 남음, 화면이 클수록 적게 남는다). 원인은 앱마다 다르다: `sci-6-2-2-3`은 장면 옆에 자체 "시간 바" 카드(199px)가 붙어 있고, `sci-6-2-3-3`은 조건 카드가 2개(실험 고르기 + 조건 고르기), `sci-6-1-1-2`는 조건 버튼에 아이콘이 들어가 있어 격자가 높다. **요구사항의 "가능하면"(if at all possible)에 따라 장면+막대(필수)는 항상 지키고, 조건 줄은 이 세 "붐비는" 앱에서는 못 지켰다.**
- **권장(Phase B/D)**: (a) 이런 앱에서 조건 카드/장면 옆 카드를 더 촘촘하게(작은 버튼·아이콘 축소) 만들거나, (b) 장면+막대만 항상 보이고 조건 줄은 살짝 스크롤해서 고르는 것을 허용하거나(현재 동작이 이미 이렇다 — 스크롤 자체가 막힌 것은 아니다), (c) `sci-6-2-2-3`류는 시간 바를 `scenePanel`처럼 막대 후보에 포함하는 걸 검토. 세 방향 다 앱별 판단이 필요해 이번 단계에서는 고치지 않았다.
- **덜 붐비는(조건 1개·아이콘 없는) 대부분의 다른 17개 앱은 이 세 앱보다 여유가 있을 것으로 예상되지만, 이번에 직접 재지는 못했다**(확인하지 못한 것, §11).

## 5. 기본값·기억(로컬스토리지) 확인

`sci-6-1-1-2`로 확인(가짜 토큰, 실제 Supabase 차단):
1. 가로 1024×768 첫 로드: 꺼짐(기본) ✓ → 학생이 켬 → `true`로 바뀜.
2. 새로고침(같은 방향): 꺼짐이 아니라 **켠 상태를 그대로 기억** ✓.
3. 세로 768×1024로 전환(그 방향은 아직 고른 적 없음): **그 방향의 기본값(켜짐, 폭≥600)이 적용됨** ✓(가로에서 고른 값이 새어 들어오지 않음).
4. 다시 가로로 전환: 가로에서 아까 고른 값(켜짐)을 그대로 기억 ✓.
5. `localStorage` 실제 키: `ssUiPref:sceneMode:landscape`만 생김(세로는 기본값만 쓰고 아직 명시적으로 고른 적 없어 키가 안 생김 — 설계대로).

머리말 접기도 별도 확인: 접음 → 새로고침해도 접힌 채 유지, `--ss-header-h`가 180px→82px로 자동 재계산(과학 앱), science-guide 앱에서도 동일하게 동작·기억 확인.

## 6. scenePanel·전체 화면 동작 확인(`sci-6-2-2-3`, `sci-6-2-3-3`에 임시 연결 — 모두 되돌림)

- **run → observe → 확인하기 → 기록하기(막대 안 버튼)** 전체 흐름: `sci-6-2-3-3`에서 실제로 진행, 기록 후 진행률 `0/1 → 1/1` 확인(막대 안 기록 버튼이 실제로 기록을 저장한다).
- **콘솔 오류**: 모든 테스트에서 0건.
- **다크모드**: 세로(기본 켜짐)에서 막대·값 패널 정상.
- **2D 대체 화면**(`?no3d=1`): 켜짐일 때 막대가 장면 안 겹침이 아니라 장면 바로 아래(문서 흐름)에 오는 것 확인(`position:static`).
- **`sci-6-2-1-2`(자체 `vp`/시간 값 패널을 갖고 있고 `factors:[]`로 실행·관찰 카드를 실질적으로 안 쓰는 앱)**: 켜짐 모드에서 이 앱 자신의 `twoCol` matchMedia(가로+900px 이상이면 `vp`를 패널 첫 자리로) 로직과 내 토글이 **함께 정상 동작**했다(값 패널이 깨지지 않고 전체 폭 패널의 첫 카드로 나온다). 다만 **UX 관찰**: 이 앱은 `factors: []`(조건 없음)라 표준 실행 버튼 라벨이 늘 "시간 바의 눈금 버튼을 눌러요"(자기 자신을 쓰지 말라는 안내문)인데, 켜짐 모드에서는 이 버튼이 장면 안 막대에 **눈에 띄게** 나온다(전에는 곁가지 카드에 묻혀 있었음). 마찬가지로 표준 기록 버튼(R.record)도 막대에 나오지만 이 앱은 **자기만의 별도 기록 버튼**(`recBtn`, 값 패널 안)을 쓴다 — 화면에 "기록하기"가 두 자리(막대 안 표준 버튼 + 값 패널 안 자체 버튼)에 보일 수 있다. **기능은 깨지지 않았지만**(각자 자기 역할대로 동작, 크래시 없음) 학생 입장에서 살짝 헷갈릴 수 있어 **Phase B(이 앱 자체가 "가장 깊은 재설계" 대상)에서 이 부분을 정리하는 걸 권장**한다(예: 이 앱처럼 `factors:[]`로 표준 실행/기록을 안 쓰는 앱은 스스로 `R.run`/`R.record`를 감추는 옵션을 템플릿에 두거나, `scenePanel`에 자체 기록 버튼까지 포함).

## 7. `R.record.disabled` 추가가 기존 기록 흐름에 준 영향 — 없음(확인)

`afterSelect()`·`run()`·`btnClear` 핸들러 3곳에 `R.record.disabled = true`를 추가했다(막대에서는 관찰 카드가 숨어 있어도 기록 버튼이 늘 보이므로, 쓸 수 없을 때 스스로 비활성이어야 해서). `showObserve()`(관찰 카드를 새로 그리는 함수, 안 고침)가 매번 그 직후에 트리거 유형(보기 고르기/숫자 입력/확인하기 필요)에 맞게 `disabled`를 **다시 정확히 계산**하므로 실질적인 순서·결과는 그대로다. **`sci-6-1-1-2`(보기 고르기형)로 기본 화면(꺼짐)에서 실제 확인**: 조건 고르기 → 실행 → 관찰 카드 뜸 → 기록 버튼은 관찰 카드 **안**(막대 아님, 꺼짐이므로 올바른 자리) → 고르기 전 `disabled=true` → 고른 뒤 `disabled=false` → 클릭 → 진행률 `0/18 → 1/18`(예전과 동일). 숫자 입력형·확인하기형·반복 측정형은 `showObserve()`/`checkNumeric()` 로직 자체를 안 건드렸으므로 코드 검토로 안전하다고 판단했다(직접 진행 확인은 못 함, §11).

## 8. 끌기 도우미 `v.draggable()` 시험

`sci-6-2-1-4`(표준 `Experiment.create`를 안 쓰는 자체 구현 앱 — 아래 §10 참고, 손전등 `setAngle(deg)` 함수가 있어 시험하기 좋았다)에 임시로 `v.draggable(torch, {...})` + 화면 좌표 확인용 디버그 함수를 넣어 마우스 누르기→움직이기→떼기를 흉내 냈다.
- 커서: 물체 위에서 `grab`, 누르면 `grabbing` ✓.
- `onDrag` 콜백이 평면 교점을 계속 다른 값으로 넘겨줌(포인터 이동에 따라 `[-14.86,14.15,0]` → `[-21.74,6.00,0]`) ✓ — 레이·평면 계산이 정확히 동작.
- 손전등의 화면 좌표가 드래그 방향으로 실제 이동(`dx=-40px, dy=+76px`) ✓ — 3D 오브젝트가 실제로 움직임을 최종 확인.
- (시험 코드에서 내가 부른 `setAngle`이 이 앱 내부의 **다른 스코프**(3D 전용, DOM 라벨은 안 바꿈) 함수와 이름이 겹쳐 각도 숫자 표시(`.val-num`)는 안 바뀌었다 — 이건 내 시험 코드의 변수 스코프 문제이지 `v.draggable()` 자체의 문제가 아니다. 실제 이동 확인으로 메커니즘은 검증됐다.)
- 시험 코드는 `git checkout HEAD -- public/apps/sci-6-2-1-4/app.js`로 완전히 되돌렸다(이 파일은 이번 단계에서 그 외 변경이 없어 안전).

## 9. scenePanel 버그 수정(코디네이터 지적, 빌드 중 발견·수정)

1. **버그 1**: `R.scenePanelOverlay`를 만들기만 하고 `R.overlay`에 못 붙여, 켜짐+넓은 화면에서 `scenePanel`이 문서에 없는 요소 안에 있어 안 보였다. → `R.scenePanelOverlay`를 `R.overlay`의 자식으로 **항상**(꺼짐이어도) 붙이고, `setEnlarged(true)`가 매번 [실행 → 기록하기 → scenePanel] 순서로 다시 정렬하도록 고쳤다.
2. **버그 2**: 켜짐 → 꺼짐으로 돌아갈 때 `scenePanel`이 원래 자리로 안 돌아가 숨은 칸에 남았다. → `create()` 시점에 `scenePanel`의 원래 부모·다음 형제를 기억해 뒀다가(`scenePanelHome`), 꺼짐일 때 그 자리로 정확히 되돌린다. 앱이 아직 어디에도 안 붙인 채 노드만 만들어 넘겼다면(원래 자리가 없음) 꺼짐일 때도 장면 바로 아래 카드(`.ss-scene-panel-card`)를 그대로 쓴다(README에 명시).
3. **확인**(`sci-6-2-2-3`에 실제 값 하나 있는 노드를 "이미 자기 카드에 붙여 둔" 형태로 임시 연결 — 가장 흔할 실사용 패턴): 1024×768(꺼짐→켜짐→꺼짐)·375×812(켜짐 유지하며 리사이즈, 좁은 화면 카드로)·768×1024까지 **6단계**를 오가며 매 단계 `scenePanel` 노드가 **문서 안에 정확히 1개**(0개=사라짐, 2개=복제 모두 없음) 있는지 확인 — **전부 통과**. 넓은 화면+켜짐일 때 막대 안(순서: 실행 → 기록하기 → 값, 스크린숏으로 육안 확인), 좁은 화면+켜짐일 때 장면 아래 카드, 꺼짐일 때 원래 카드로 정확히 복귀. 콘솔 오류 0. 시험 코드는 되돌렸다(`app.js` diff가 문구 수정 전용 5줄만 남도록 확인).

## 12. Supabase 차단 기록

전용 headless Chrome(포트 9346, 프로필 스크래치 전용)으로 `--host-resolver-rules="MAP *.supabase.co 127.0.0.1:9, MAP supabase.co 127.0.0.1:9"` + CDP `Fetch.enable`로 모든 `*supabase.co*` 요청을 가로채 가짜 응답(OPTIONS→204, `site_settings` GET→`login_required:false`, 다른 GET→`[]`, POST/PATCH/PUT→201)으로 처리했다. 모든 테스트에서 **실제 Supabase로 나간 요청 없음**(요청 가로채기 로그로 확인, 전부 인터셉트됨). 실제 Gemini 호출 없음(체험 모드는 애초에 안 부름). 다른 탭·프로세스는 건드리지 않았고, `localStorage.clear()`는 한 번도 안 썼다(항상 `sci6*` 접두사 키만, 이번엔 `ssUiPref:*` 키도 테스트 간 오염 방지를 위해 선택적으로 지웠다 — 둘 다 이 앱들 전용 키). 끝난 뒤 Chrome 프로세스 종료 확인(`ps aux`로 재확인), 임시 `.mjs` 스크립트·Chrome 프로필 삭제, 스크린숏(76장)만 스크래치에 보존.

## 14. 확인하지 못한 것
