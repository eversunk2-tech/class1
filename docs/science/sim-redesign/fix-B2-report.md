## 1. `sci-6-2-1-4`

### M1. 손전등 끌기 (`app.js:791-847`, `v.draggable(torch, …)` 등록부 `app.js:809`)

**원인**: 예전 코드는 끌기 중 손전등의 "잡힌 화면 지점"에서 곧장 절대 각도를 계산해 그대로 `setAngle`에 넘겼다. 손전등은 회전체라 잡은 자리(머리·몸통·버튼)마다 피벗 기준 절대 각이 달라서, **누르기만 해도**(움직이지 않아도) 잡은 자리에 따라 각도가 제멋대로 바뀌었다(review-B: 30°에서 머리 위 모서리 → 36°, 빨간 버튼 → 34°, 몸통 아래 가장자리 → 27°). 잡는 영역도 화면 경계 상자+30px라 기울어진 손전등 옆 빈 하늘까지 넓게 잡혔다(review-B: 45°에서 5칸 떨어진 빈 하늘을 끌면 45°→72~73°로 튐).

**고침**:
1. **상대 각도**: `onStart`에서 잡은 순간의 실제 각도(`dragStart.angle = angle`)와 잡은 지점의 각(`dragStart.point`, `degFromPoint`로 계산)을 함께 저장한다. `onDrag`/`onEnd`에서는 `dragStart.angle + (degFromPoint(지금 지점) − degFromPoint(잡은 지점))`을 새 각도로 쓴다. 손전등은 피벗(센서, `[0,SURF,0]`) 둘레의 강체 회전이라, 잡은 자리가 축 위든(머리·몸통) 축 밖이든(버튼) `degFromPoint`의 **변화량**은 항상 실제 회전각의 변화량과 같다(상수 오프셋만 다름 — atan2 기반이라 어디를 잡아도 델타가 같다는 것을 아래 §확인의 수치로 검증). 그래서 잡는 순간(변화량 0)에는 항상 원래 각도가 그대로 유지된다.
2. **움직임 문턱**(`DRAG_MOVE_PX = 6`, 화면 px): `dragStart.moved`가 `true`가 되기 전(=6px 문턱을 못 넘긴 동안)에는 `onDrag`가 아무것도 하지 않고, `onEnd`도 `!st.moved`면 각도를 건드리지 않는다.
3. **잡는 영역**: `v.draggable(torch, { pad: 0, … })` — 공통 틀에 이미 있는 새 옵션(`pad`, README "추가 기능 2026-09-25")을 0으로 줘 "화면 경계 상자+30px" 기본 여유를 끄고 레이가 손전등 자신(또는 손전등의 자식)에 실제로 맞을 때만 잡히게 했다. 대신 손전등 축(로컬 x, 몸통 끝 −11.2~렌즈 0)을 따라 반지름 4의 보이지 않는 굵은 원기둥 손잡이(`handle`, `opacity:0`·`depthWrite:false`, 머리 반지름(최대 3.05)·버튼 돌출(1.85)보다 넉넉함)를 손전등의 자식으로 추가해(`app.js:802-807`) 터치는 쉽게 하면서 화면 경계 상자보다 훨씬 좁게 잡히는 범위를 유지했다.

### 확인(전·후 수치)

### L1. 확대 칸이 전체 화면에서도 남음 (`app.js:1041-1047` `apply()`, `app.js:1196-1210` `onCam()`)
`bits.inset.show(st.shown)`이 "측정값이 있는지"만 보고 확대 칸을 보였다/숨겼다 해서, 마지막 칸(예: 기울임·라)을 기록하고 처음 방향(전체 화면)으로 돌아와도(`afterRecord()`가 `v.flyHome(450)`을 부름) 확대 칸이 남아 지구본(특히 '라' 자리)을 가렸다(review-B).

**고침**: `apply()`의 마지막 줄을 `bits.inset.show(st.shown && closeNow)`로 바꿨다(`app.js:1047`). 다만 `closeUp()`/`flyHome()` 카메라 트윈은 `apply()`를 다시 부르지 않으므로, `onCam()`(카메라 "change" 이벤트마다 실행, `near !== closeNow`로 실제 경계를 넘는 순간만 처리)에도 같은 줄(`app.js:1204`)을 추가해 카메라가 실제로 멀어지는 그 순간 확대 칸이 사라지게 했다. 확대 칸의 내용 계산(`bits.inset.set`·`aimInset()`)은 그대로 `st.shown`일 때 계속 갱신하고(전에 있던 그대로), 마지막 화면 표시만 `closeNow`로 한 번 더 걸렀다 — 다시 확대하면 바로 최신 값이 보인다.

### L6. 확대 화면에서 자리 이름표가 토글과 겹침 (`app.js:1205-1209`, `onCam()` 안)
'가'~'라' 이름표(`marks[id].tag`)는 세계 좌표에 고정돼 있어, 확대(줌인)하면 화면 투영 위치가 왼쪽 위 "⛶ 전체 화면 보기" 토글과 겹칠 수 있었다(review-B: 가로 기본 화면·세로 끔에서 최대 1495px²).

**고침**: L1과 같은 `onCam()`의 `near !== closeNow` 분기(카메라가 실제로 가깝다/멀다 경계를 넘는 순간)에 `POS_IDS.forEach(id => marks[id].tag.visible = !closeNow)`를 추가했다 — 확대 중에는 자리 이름표 4개를 모두 숨기고, 전체 화면으로 돌아오면 다시 보인다. 위치를 고르는 다른 길(가~라 버튼, 지구본 끌기)은 그대로 있어 기능은 줄지 않는다.

**확인**: 위 L1과 같은 조작으로, 확대 중(`6215-l1-01-after-run-ga.png`) 스크린숏에 '가' 이름표가 뜨지 않고 토글과 겹치는 글자가 없다. 기록 뒤 전체 화면(`6215-l1-02-after-record-home.png`)에서는 '가'·'나'·'다'·'라' 이름표가 다시 모두 보인다(숨김이 영구적이지 않음을 확인).

### L2. 2D + 크게 보기 그림 높이 (`style.css:119-126`)
`.orbit-svg`(2D 궤도 그림)에 크게 보기 전용 `max-height`를 추가했다 — 가로 **30vh**, 세로 **40vh**. 기존 440px 고정값은 크게 보기(넓은 화면)에서 그림이 화면 폭 전체로 커져 장면 안 막대가 아래 이동 막대보다 아래로 밀렸다. 처음 38vh로 시도했을 때도 겹쳐(1024×768에서 +43.8px) 30vh로 더 낮췄다(위 2-1-4와 같은 캐시 문제를 여기서 먼저 발견해 고치고 다시 쟀다).

## 6. 테스트 규칙 이행 기록
자기 정적 서버(`python3 -m http.server 8788 --bind 127.0.0.1 --directory public`)와 자기 전용 headless Chrome(포트 9349, 프로필 `…/scratchpad/fix-B2/profile/`, `--use-angle=swiftshader --enable-unsafe-swiftshader --disable-web-security --host-resolver-rules="MAP *.supabase.co 127.0.0.1:9, MAP supabase.co 127.0.0.1:9"`)만 썼다. Node 24 전역 `WebSocket`으로 CDP에 직접 연결(설치 없음), 모든 새 탭에서 CDP `Fetch.enable(*supabase.co*)`로 `site_settings` GET에만 `[{"login_required":false}]`, 그 밖은 안전한 기본 가짜 응답(OPTIONS 204, GET `[]`, POST/PATCH/PUT 201)만 돌려줬다 — 실제 Supabase·Gemini 요청 0(로그에서 확인). three.js 등 앱이 원래 쓰는 CDN 리소스는 브라우저가 페이지를 정상적으로 열며 스스로 받아 온 것이고, 내가 별도로 `curl`/`wget` 등으로 내려받은 파일은 없다. `localStorage.clear()`는 쓰지 않고 두 앱의 `sci621sim4:v1*`/`sci621sim5:v1*` 키만 지우며 시험했다. 다른 탭·프로세스·다른 Chrome은 건드리지 않았다. git commit/push, 실 DB 쓰기, `npm run build`는 하지 않았다. 스크립트(`.mjs`)·프로필은 스크래치 `…/scratchpad/fix-B2/`에만 뒀고, 끝나면 자기 Chrome(9349)과 정적 서버(8788)를 종료하고 프로필·시험 스크립트는 지운 뒤 스크린숏(`shots/`)만 남겼다.
