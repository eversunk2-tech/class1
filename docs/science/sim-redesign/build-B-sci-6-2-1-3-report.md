## 1. 바꾼 것

### 1.1 "⛶ 전체 화면 보기" 연결(모든 앱 공통 절)
이 앱은 `SciSim.Experiment.create()`를 안 쓰고 `.ss-exp-layout`·`.ss-exp-view`·`.ss-exp-panel`을 직접 만들어 토글이 없었다. `index.html`은 이미 `science-sim/experiment.js`를 `sim3d.js` 뒤에 불러오고 있어서(`SciSim.Experiment.scrollIntoView`를 쓰려고 전부터 넣어둔 것) 스크립트 태그를 추가할 필요는 없었다. `buildExperimentDom()` IIFE가 끝난 직후 한 번 호출한다:

```js
var enl = S.Experiment.enlarge({
  layout: R.layout,       // .ss-exp-layout
  viewBox: R.viewBox,     // .ss-exp-view(하늘 모형 칸)
  panel: R.panel,         // .ss-exp-panel
  record: R.record,       // 📝 기록하기 버튼(막대 아랫줄로)
  scenePanel: R.valuePanel, // "②" 머리말 + 값 그리드 + 궤적 범례(막대 윗줄 또는 좁은 화면 카드)
});
```

값 패널을 **머리말+값(`R.valuePanel`)** 과 **기록 버튼+안내 문구(`R.record`/`R.recordMsg`)** 로 나눴다 — `scenePanel`은 값만, 기록 버튼은 `record`로 따로 넘겨 지침의 "막대 = 윗줄 값 + 아랫줄 실행·기록" 배치를 그대로 따른다. `R.recordMsg`(기록 상태 안내, 예: "다음은 4월을 눌러 보세요")는 옮기지 않고 원래 자리(관찰할 달 고르기 카드 안)에 남긴다 — 막대를 버튼 두 개로 간결하게 유지하려는 선택이다.

3D↔2D 전환 때(`finishMount()`에서 `.is-2d` 클래스를 붙이고 뗀 직후) `enl.fit()`을 호출해 크게 보기 장면 높이를 다시 잰다(README 안내대로).

### 1.2 값 겹침 수정(audit.md N4)
`review-A2.md` N4: "`sci-6-2-1-3/style.css:49`(`.ov-values` top 42px left 10px)... 토글이 앱의 값 표시와 겹침(토글은 끔 상태에도 있음)." 이 배지(`R.ovVal`, 하늘 모형 위 왼쪽 겹쳐 뜨던 "6월 · 남중 고도 75.5° · 낮의 길이 14시간 45분")를 **없앴다**(옮기지 않고 삭제) — `scenePanel`이 이제 같은 역할(빠른 확인)을 태블릿 세로(크게 보기 기본)에서 장면 안 막대로 대신하고, 그 밖의 화면에서는 값 패널이 장면 바로 아래(가로)나 카드로(좁은 화면) 항상 가까이 있어 별도 겹침 배지가 필요 없다고 판단했다. `style.css`의 `.ov-values` 규칙과, 짝이던 `sky2d-glabel`(2D 궤적 이름표, 1.4절에서 없앰) 규칙도 지웠다.

### 1.3 실험하기 첫 진입 스크롤 보정
태블릿 세로에서 크게 보기가 기본으로 켜진 채 처음 실험하기로 들어오면 장면 안 막대(기록 버튼)가 첫 화면 아래로 밀려 있을 수 있었다(공통 틀이 `enlarge()` 켜기/끄기 때만 스크롤을 맞추고, 단계 진입 자체에서는 안 맞춘다 — review-A2 L1과 같은 종류의 제약). `activateExp()`에 `S.Experiment.scrollIntoView(R.viewBox)` 한 줄을 추가했다(이미 보이면 아무 일도 안 한다, 공개 도우미라 공통 틀을 고치지 않고 앱에서만 해결). §3에서 전·후 수치로 확인했다.

### 1.4 궤적 보기 재설계(B2 핵심, 사용자: "지난 경로가 계속 남아 헷갈린다")
기록한 달을 전부 남기던 "👣 지난 경로: 보임/숨김"(`ghostsOn`, 기본 켜짐)을 없애고 두 버튼으로 바꿨다: **"🌤️ 이번 달만"(기본)** · **"📊 계절 대표 3개"**.

* "계절 대표 3개"는 **기록 여부와 무관하게** 3월(봄·가을 대표) · 6월(여름) · 12월(겨울) 값으로 **계산**해서 그린다:
  ```js
  var COMPARE3 = [
    { id: "springfall", label: "봄·가을", month: 3, color: "#2e8f9e" },
    { id: "summer", label: "여름", month: 6, color: SEASON.summer.color },
    { id: "winter", label: "겨울", month: 12, color: SEASON.winter.color },
  ];
  function pathList(current) {
    if (pathMode !== "compare3") return [];
    return COMPARE3.filter(function (c) { return c.month !== current; }); // 지금 보는 달과 겹치면 그 항목만 뺀다
  }
  ```
  `pathSamples(month, n)`(천문 계산, 기록 여부와 무관하게 항상 계산 가능)를 그대로 재사용하므로 미기록 달도 정확히 그려진다. "봄·가을"은 새 색(`#2e8f9e`, 기존 4계절 색과 겹치지 않는 청록)을 썼다 — 봄(초록)·가을(황토) 어느 한쪽 색을 쓰면 "그 계절만"이라는 오해를 줄 수 있어서다.
* **이름표는 3D/2D 장면 안에 더 이상 띄우지 않는다**(겹침이 audit.md가 지적한 원래 원인이었다 — "9월"·"4월"·"3월" 이름표 상자가 서로 맞닿음). 대신 값 패널 옆(`R.valuePanel` 안, `R.pathLegend`)에 **색 점 + 이름** 범례("🟢 봄·가을 🟢 여름 🔵 겨울" 형태)를 두고, "계절 대표 3개"일 때만 보인다. 이제까지 라벨 배치에 쓰던 `labelH()` 도우미 함수는 안 쓰게 돼 지웠다.
* 저장: 새 키 `pathMode`("current" | "compare3", 기본 "current")를 쓴다. 예전 `ghosts`(boolean) 키는 코드 어디서도 더 이상 읽지 않는다(무해하게 방치 — §4에서 실제로 안 쓰임을 확인).
* 12개월 필수 기록·측정값·조사 기간 표기 생략은 그대로다(값·조건은 바꾸지 않음).

### 1.5 직접 조작(태양 끌기)은 넣지 않음 — 생략 이유
B2 지침은 "하늘 경로 위의 해를 끌어 그날의 해 움직임을 살펴보기"를 예시로 들면서 "필요 없다고 판단하면 이유를 적고 생략 가능"이라고 열어 뒀다. 다음 이유로 이번엔 넣지 않았다:
1. **기록되는 값은 항상 남중 순간 값 하나뿐**이라(남중 고도·낮의 길이), 뜨고 지는 하루 전체를 손으로 훑어봐도 학습 목표에 새 정보가 없다 — 이미 "▶ 관찰하기" 애니메이션이 뜨고 지는 전 과정을 자동으로 보여준다.
2. 하늘 반구는 **카메라 자유 회전(드래그로 돌려 보기)이 이미 있는 자리**라, 태양을 끄는 제스처를 새로 얹으면 "장면 돌려보기"와 "태양 끌기"가 같은 손짓(드래그)으로 헷갈릴 위험이 있다(공통 틀의 `v.draggable()`은 카메라 회전을 잠시 멈추지만, 학생 입장에서는 "왜 이번엔 안 돌아가지" 혼란을 줄 수 있다).
3. 이 앱은 **달 고르기(탭 1번) → 재생(약 1.2초) → 측정하기 → 기록**이 12번 반복되는 짧고 촘촘한 흐름이라(개정 1 시간표 약 6:00~6:30), 새 조작을 끼워 넣을 여유가 크지 않다.
4. 달 바 버튼 고르기가 이미 탭 1번으로 충분히 "직접 만지는" 조작이라고 판단했다(§3.1 원칙 "버튼 선택은 항상 남긴다"와도 맞음 — 대안이 아니라 유일한 조작이 됨).

### 1.6 카메라 방향 유지(개정 3 확인 항목)
`v.moveTo`/`v.focus`/`v.setCameraPose` 같은 스크립트 카메라 이동이 이 앱 코드에 전혀 없다(자유 회전 드래그와 "🎥 처음 방향으로" 리셋뿐 — `v.resetView()`만 호출). 따라서 sci-6-2-1-5의 `closeUp()` 같은 "확대할 때 좌우가 뒤집히는" 위험 자체가 구조적으로 없다(코드 검색으로 확인, `grep -n "moveTo\|setCameraPose\|\.focus(" app.js` 결과 없음).

## 4. 끝까지 진행 · 저장 확인

헤드리스 자동화로 예상하기(답 작성) → 실험하기(12달 전부 재생+기록, 중간에 궤적 보기 전환도 시험) → 기록·분석하기(퀴즈 2문항 정답) → 정리하기(결론 제출 → 모범 답안 비교 → 궁금한 점 작성) → 학습 마치기까지 두 번(768×1024 크게 보기, 1024×768 기본 화면) 완주했다. 둘 다 **콘솔 오류·예외 0건**.

* 소요 시간(자동화 기준, 읽기 시간 없이 클릭·대기만): 약 31~35초. 이건 **학생의 실제 7분 기준과 비교할 수치가 아니다**(자동화는 문장을 안 읽는다) — 이번 변경은 §4.5(공통 spec)에 적힌 대로 측정 조건·문항 수를 안 바꿨으므로 기존에 승인된 시간표(개정 1, 약 6:00~6:30)가 그대로 유효하다고 보고 실측을 다시 하지 않았다. 스크롤 보정(§1.3)으로 오히려 막대를 찾는 시간이 준다.
* **저장 키**: `sci621sim3:v1`(안 바뀜). 12개월 기록 후 `sci621sim3:v1:records`에 12개 항목, `sci621sim3:v1:pathMode`에 `"current"`/`"compare3"`(문자열), 예전 `sci621sim3:v1:ghosts` 키는 **한 번도 만들어지지 않음**(코드로 검색해도 `store.set("ghosts"...)` 호출이 없음, 실행 로그로도 재확인).
* **`detail`/`detail.qa`**: `buildDetail()`·`recordRows()`·`predict.values()`·`conclude.values()`·`quiz.result()`·`curiosityText`는 이번에 코드를 손대지 않았다(값 패널·궤적 보기만 바꿈) — 완주한 두 번 모두 마치기 화면 요약("기록한 달: 12/12", "분석 질문: 2/2 맞힘")이 정확했고, `localStorage`의 `predict`/`conclude`/`records` 원자료가 기대한 모양 그대로였다(구조 자체는 서버 전송 전 단계라 직접 캡처하지 않았지만, 그 원자료를 만드는 함수를 하나도 안 고쳤으므로 모양이 그대로임을 코드로 보장한다).
* **재기록**: 이미 기록한 달(예: 3월)을 다시 눌러도 값 패널·기록 버튼이 정상 동작함을 12개월 순환 도중 확인(달 바의 `is-rec` 표시 정상).
* **새로고침 뒤 이어 하기**: `pathMode`를 "계절 대표 3개"로 바꾼 뒤 페이지를 새로고침(reload)했더니 실험하기 단계로 정확히 복원되고, 궤적 버튼도 "계절 대표 3개"가 눌린 채로, 범례도 그대로 보임(§6 스크립트로 확인) — `localStorage`가 아니라 실제 새로고침으로 검증했다.
* **체험 모드(비로그인)**: 완료 화면에 "체험 모드라서 결과는 저장되지 않았어요"가 정확히 뜸. Supabase로 나간 요청은 전 과정(예상~마치기)에서 `GET /rest/v1/site_settings?select=login_required&limit=1` **2건뿐**(로그인 잠금 확인용, 공개 읽기) — `app_progress`/`app_results`/`check-answer` 호출은 0건(체험 모드 규칙대로).

## 5. 공통 틀에 필요했던 것(고치지 않고 여기 적음)

* **812×375(가장 낮은 화면) + 학생이 직접 켠 크게 보기**에서 막대 일부가 아래 이동 막대에 살짝 깔리는 문제(§3의 표, §7) — `fit()`의 자동 재배치가 `wideLandscapeMq`(가로 900px 이상)에만 걸려 있어 이 폭에는 적용 안 됨. `max-height:480px` 구간의 `min-height:200px`을 조금 낮추거나, 이 폭 구간도 `fit()` 대상에 넣는 방향을 다음 공통 틀 손질 때 검토할 만하다. 이 앱만의 문제가 아니라(공통 CSS 규칙) 다른 앱도 이 폭에서 같은 현상이 있을 가능성이 있다 — 단계 D 등에서 여러 앱을 한 번에 확인할 때 같이 보면 좋겠다.
* **'더 탐구하고 싶은 점' 필수 검사가 이 앱의 안내 문구와 어긋남**(공통 틀 문제는 아니고, 발견 사실 공유): `scripts/templates/science-sim/lesson.js`는 `#ss-curiosity` 요소를 찾아 **비우면 마칠 수 없게** 막는다(주석 "이제 필수", CLAUDE.md 2026-09-23 결정과 일치). 그런데 이 앱은 `SciSim.Curiosity`를 안 쓰고 자체 입력칸을 직접 만들면서 같은 id(`ss-curiosity`)를 썼고, `data/lesson-config.js`의 안내 문구는 옛 기준 그대로 "**비워 두어도 마칠 수 있어요**"라고 적혀 있다 — 실제로는 안 비우면 못 마친다(자동화로 직접 확인: 비운 채 마치기를 누르면 "'더 탐구하고 싶은 점'을 한 줄이라도 적어야 마칠 수 있어요" 안내가 뜸). **이번 B2 범위(궤적 보기·전체 화면 보기)가 아니라 손대지 않았다** — 문구만 바꾸는 것은 `data/lesson-config.js` 안이라 파일 권한은 있지만, "예상·분석·정리 문항"을 바꾸지 않는다는 이번 단계 원칙에 걸릴 수 있어 보고만 한다. 안내 문구를 "적어야 마칠 수 있어요"로 고치는 간단한 수정을 Claude가 검토하면 좋겠다.

## 6. 테스트 방법

지침대로 자기 전용 headless Chrome(포트 9348, 프로필 `…/scratchpad/build-B/sci-6-2-1-3/profile/`)을 Node 24 전역 `WebSocket`으로 CDP 제어했다(Puppeteer 등 설치 없음). Chrome 실행 플래그: `--headless=new --use-angle=swiftshader --enable-unsafe-swiftshader --disable-web-security --host-resolver-rules="MAP *.supabase.co 127.0.0.1:9, MAP supabase.co 127.0.0.1:9"`. 모든 탭에서 첫 로드 전에 CDP `Fetch.enable(*supabase.co*)`로 가짜 응답을 걸었다(`site_settings` GET→`login_required:false`, 다른 GET→`[]`, POST/PATCH→201, OPTIONS→204) — 실제 Supabase·Gemini 요청은 0건(§4에 기록한 것 외에 새어 나간 요청 없음, 매 스크립트가 가로챈 요청을 로그로 남겨 확인).

localStorage는 `localStorage.clear()`를 쓰지 않고 이 앱 키(`sci621sim3` 접두사)와 `ssUiPref:` 접두사(화면 크기 스윕 시험 사이에 "켜짐 기억" 설정이 다음 시험으로 새는 것을 막으려고, 지침이 "자기 시험 전후에만" 허용한 범위)만 지웠다 — 처음에 `ssUiPref:`를 안 지워서 812×375가로 시험 하나가 이전 가로 시험의 "켜짐 기억"을 물려받아 결과가 왜곡됐던 것을 발견해 바로잡았다(§3 표는 바로잡은 뒤 결과). 다른 탭·프로세스·개발 서버(3000)는 건드리지 않았다(다른 B1/B3/B4 에이전트가 같이 쓰는 것을 확인하고 시작). 끝난 뒤 포트 9348 Chrome 프로세스를 모두 종료했다(재확인: `curl`이 연결 거부, 남은 프로세스 없음). 임시 파일 중 `chrome.log`는 지웠다 — **`profile/`(143MB, Chrome 사용자 데이터) 삭제는 `rm -rf` 권한이 거부되어 남아 있다**(fix-A-report.md·review-A2.md에 이미 기록된 것과 같은 제약). 저장소와 무관하니 그대로 둬도 된다. 스크린숏(26장)과 시험 스크립트(`cdp.mjs` + `test1~7-*.mjs`, 재현용으로 남겨 둠)는 `…/scratchpad/build-B/sci-6-2-1-3/shots/`·같은 폴더에 있다.

## 7. 확인하지 못한 것 · 남은 것

* **실제 iPad/태블릿**: 전부 headless Chrome(SwiftShader 소프트웨어 WebGL) + CDP 뷰포트 흉내로 확인했다. 손가락 드래그 감도(돌려 보기), 회전 때 전환, 실제 기기의 렌더링 성능은 확인 못 했다.
* **812×375(가장 낮은 화면)에서 학생이 직접 크게 보기를 켰을 때의 막대 겹침**(§3·§5) — 원인은 공통 틀에 있다고 보지만 코드는 고치지 않았다(범위 밖). 기본값(꺼짐)에서는 문제없다.
* **'더 탐구하고 싶은 점' 필수 안내 문구 불일치**(§5) — 발견만 하고 고치지 않았다.
* **실제 학생 소요 시간**: 이번 변경은 측정 조건·문항 수를 안 바꿔서 기존 승인 시간표(약 6:00~6:30)가 유효하다고 보고 다시 재지 않았다(자동화 소요 시간은 사람 기준과 무관해 참고용으로도 안 실었다).
* **소리·진동 등**: 이 앱에는 해당 요소가 없어 확인할 것이 없었다.
* **다른 3개 앱(B1·B3·B4)과의 동시 작업 영향**: 개발 서버(3000)와 파일을 공유했지만 내 파일(`sci-6-2-1-3/`)만 고쳤고 `git diff --stat`로 다른 앱 파일에 영향이 없음을 확인했다.
