## 4. Supabase 차단 기록

* 자기 전용 headless Chrome(포트 9351, 프로필 스크래치)에 `--host-resolver-rules="MAP *.supabase.co 127.0.0.1:9, MAP supabase.co 127.0.0.1:9"` + `--disable-web-security`, 모든 탭에서 첫 로드 전에 CDP `Fetch.enable(*supabase.co*)` → 가짜 응답만(`site_settings`→`login_required:false`, 가림막 시험 때만 `true`; `app_progress` GET→`[]`, POST/PATCH→201; `functions/v1/check-answer`→`{verdict:"ok"}`; `auth/v1/*` 가짜 사용자; OPTIONS→204).
* 요청마다 `Network.requestWillBeSent` ↔ 가로챈 요청을 맞춰 봄: **새어 나간 요청 0, 실패 0**(기록한 모든 실행). 마지막 점검(가짜 로그인 + 다음 단계 + 기록): site_settings 1, app_progress GET 1·POST 1·PATCH 3, check-answer 1 — 전부 가로챔. 실제 Gemini 요청 0. 가짜 세션은 localhost 출처 localStorage에만 넣었다(값은 문서에 적지 않음).
* `localStorage.clear()`는 쓰지 않았다(그 앱 `sci6…` 키와 `ssUiPref:` 키만 지움). 다른 탭·Chrome·개발 서버는 건드리지 않았다. 자기 정적 서버는 8781(바꾸기 전)·8782(시험 사본 + 작업 트리 사본)만 썼고 끝나면 종료했다.
