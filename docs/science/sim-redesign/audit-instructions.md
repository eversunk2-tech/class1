## 배경(사용자 요청 2026-09-25)
사용자가 실험 시뮬레이션 앱을 크게 손보려 한다. 그중 다음 문제를 앱마다 빠짐없이 찾아 달라는 것이 이 점검의 목적이다.
1. **글자가 다른 것을 가림**: 3D·2D 장면 안의 이름표·눈금·설명 글자·계기(HUD)가 측정값, 다른 이름표, 중요한 물체(그림자 끝, 눈금, 태양 등)를 가리거나 서로 겹치는 곳.
2. **동기화(싱크)가 맞지 않음**: 화면에 그린 것들이 서로 어긋나는 곳. 예) 2학기 1단원 탐구 2(`sci-6-2-1-2`)에서 "태양 그림과 태양빛 선이 맞지 않고, 태양과 지면이 줄로 연결된 것처럼 보인다", 각도기가 너무 크다. 태양 위치 ↔ 빛줄기 방향 ↔ 그림자 방향·길이 ↔ 표시된 측정값, 슬라이더 값 ↔ 장면 상태, 계기 숫자 ↔ 표·그래프 값이 서로 맞는지.
3. **답을 알려 줌**: 기록하기·측정 순간(또는 실험 중 안내 글·토스트·이름표)에 **결론이나 관계**("~할수록 ~해요", "그래서 ~이다", 정답 보기 문구와 같은 말)를 먼저 말해 주는 곳. 측정값·관찰 사실만 보여 주는 것은 괜찮다. 분석·정리하기 단계의 피드백(학생이 고른 뒤 맞고 틀림 알려 주기)과 정리하기 모범 답안 비교는 규칙상 허용이므로 **실험하기 단계와 기록 순간**을 중점으로 본다.
4. (참고로 함께) 2학기 1단원 탐구 3(`sci-6-2-1-3`)의 "월별 궤적이 계속 남아 헷갈림"처럼 화면이 복잡해지는 곳, 조작이 직접 하는 느낌이 약한 곳(값을 고르기만 하고 장면을 만지지 않는 곳)을 짧게 메모.

## 방법
* **코드 읽기**: 기록하기 처리·측정 안내·토스트·이름표 문구(`lesson-config.js`의 문구 포함)를 모두 읽어 "답을 알려 주는 문구"를 찾는다(파일:행과 문구 인용).
* **화면 보기**: 개발 서버가 이미 `http://localhost:3000/class1/apps/<앱>/`에서 돌고 있다(끄거나 다시 띄우지 않는다). **자기 전용 headless Chrome**(원격 디버깅 포트 **9344**, 사용자 데이터 폴더는 스크래치 안)으로 각 앱을 **체험 모드**(로그인 잠금 꺼짐 + 비로그인)로 열어 예상하기를 짧게 적고 실험하기로 들어간 뒤, 대표 조작(슬라이더·버튼·조건 바꾸기 2~3번)을 하며 **태블릿 세로 768×1024**와 **태블릿 가로 1024×768**에서 스크린숏을 찍는다. 3D 장면은 WebGL이 필요하다(headless에서 `--use-angle=swiftshader --enable-unsafe-swiftshader`로 켠다). 2D 대체 화면이 있는 앱은 2D도 한 번 본다.
* **실제 Supabase는 첫 로드부터 막는다**: Chrome 인자 `--host-resolver-rules="MAP *.supabase.co 127.0.0.1:9, MAP supabase.co 127.0.0.1:9"` + `--disable-web-security` + CDP `Fetch.enable`(패턴 `*supabase.co*`)로 가짜 응답만(`site_settings` → `login_required:false`, 나머지 GET → `[]`/`null`, POST → 201 `[]`, OPTIONS → 204). 로그인하지 않으므로 앱은 체험 모드로 동작한다. `Network.loadingFailed`로 새는 요청이 없었는지 기록. 실제 Gemini 호출 금지(체험 모드는 부르지 않음).
* `localStorage.clear()` 금지(그 앱의 `sci6…` 키만 지운다). 다른 탭·프로세스를 건드리지 않는다. 끝나면 Chrome 종료, 임시 파일 정리(스크린숏만 `/private/tmp/claude-501/-Users-sungchul-Desktop-classroom/7bf3a39e-3017-4189-b337-1b82aace66bb/scratchpad/sim-audit/`에 남김). 아무것도 내려받지 않는다. git commit/push 금지.
