## 할 일(모든 앱 공통)
1. **기록 뒤 자동 진행 없애기**(2026-09-26 사용자 규칙): 📝 기록하기 뒤에 앱이 **다음 조건을 스스로 고르거나(`exp.select` 등) 실행·재생하지 않는다** — 기록만 하고 지금 조건·장면 그대로. 다음 것을 **안내·강조**하는 것은 괜찮다(예: 알림 "✔ ○○을 기록했어요. 다음 조건을 골라 보세요." — 측정값·사실만, 아직 안 한 조건 버튼 강조는 움직임 줄이기를 지킴). 찾은 곳: `sci-6-2-2-1` `onRecorded`(`app.js:201-208`, 같은 가루의 다른 관찰 대상 자동 선택), `sci-6-2-2-4` `onRecorded`(`app.js:153-160`, 실험 1 기록 뒤 실험 2 자동 선택), `sci-6-2-3-2` `onRecorded`(`app.js:425-432`). 그 밖에도 기록 직후 조건을 바꾸거나 연출을 시작하는 코드를 모두 찾는다. 학생이 직접 한 일(표에서 기록 칸 누르기, 새로 고침 복원)로 조건이 골라지는 것은 그대로 둔다. **공통 틀도 2026-09-27부터 기록 뒤 다음 칸을 고르지 않는다**(사용자 "모든 실험 앱" — Claude가 정본 `experiment.js`를 고치고 20개 사본에 맞춤: 조건·장면 그대로, 크게 보기에서는 조건 고르기 카드가 보이게 조작 칸만 올림 — README "바뀐 동작(2026-09-27 단계 D)"). **'👉 다음' 같은 다음 칸 안내 표시는 두지 않는다**(사용자 2026-09-27: "'다음' 표시 없어도 교사의 활동 안내 후 학생들이 순서대로 선택해서 할 수 있을 것 같아" — 알림 글에도 넣지 않음, `suggestNext` 옵션도 없앰). 그러니 앱은 **앱 자신의** 자동 선택만 없애고, 틀을 우회하는 코드(기록 뒤 방금 칸 다시 고르기)나 다음 칸을 가리키는 표시·안내 글은 만들지 않는다.
2. **재생 연출**: 실행 연출이 있으면 **움직이는 동안에는 대상만 움직이고**, 측정 그림(선·호·표시)과 측정값 글은 **끝에 한 번만** 보인다(도중에 한 번 나타났다 끝에 다시 나타나는 식 금지). 교과서 절차의 측정 도구 자체가 움직이는 모습(예: 흐르는 초시계, 빨리 감기 바)은 측정 과정이라 괜찮다 — 판단을 보고서에.
3. **관찰 카드의 '본 모습' 글**(review-A L8): 관찰 카드(보기 바로 위)·캡션·이름표·HUD가 **바로 아래 보기와 같은 말(정답)**을 먼저 보여 주면, `sci-6-2-2-3` `chipNode()`처럼 중립 안내("장면에서 ○○을 살펴보세요")로 두고 **실제 상태 글은 맞는 보기로 확인한 뒤에만** 드러낸다(틀린 답으로 확인하면 계속 숨김). 장면 자체의 대체 설명(3D 장면 `aria-label`, 2D 그림 설명)은 장면을 "보는 것"과 같으므로 상태를 말해도 된다 — 시각 장애 학생이 관찰할 수 있어야 한다. **화면으로 볼 수 없는 현상을 알려 주는 표시**(예: `sci-6-2-2-2`의 '따뜻한 정도' — 사용자 결정 2026-09-27 "화면에서 그냥 알 수가 없으니 … 현재 그대로")는 관찰 수단이므로 그대로 둔다. 해당(확인된 것): `sci-6-2-2-1`(`app.js:231` `C.seen`), `sci-6-2-3-1`, `sci-6-2-3-2`. `sci-6-2-2-2`는 지금 글이 중립인지 확인.
4. **장면 속 글자·값 패널**: 바뀌는 값(시간·거리·개수·양 등)을 3D 이름표로 띄우고 있으면 DOM 값 패널로 옮기고, 크게 보기에 `scenePanel`로 넘긴다(장면 안 막대 윗줄). 값이 없는 관찰형 앱은 넘기지 않는다(까닭을 보고서에). 3D 이름표는 안 바뀌는 것만, **장면 가장자리에서 잘리거나** 토글(장면 왼쪽 위, 위에서 약 46~90px)·드래그 안내 줄·이동 화살표·장면 안 막대에 가리지 않게(카메라 맞춤 `frame`·이름표 자리 조정).
5. **직접 조작**(spec §3.3 자기 앱 줄): 조건을 **3D 장면의 물체를 눌러** 고를 수 있게 — 없는 것만 기존 `v.pickable`/`ctx.onPick` 패턴으로 더한다. 버튼은 그대로, **조작 단계·시간을 늘리지 않음**, 실행 중·아직 고를 수 없는 때의 탭은 무시(`sci-6-2-2-3` `app.js:280-282` 가드). 누를 수 있음을 알리는 짧은 말(드래그 안내 줄 등 — 이미 있으면 그대로). 끌기가 더 자연스러운 조작이 있으면 `v.draggable`(선택 — 필요 없다고 판단하면 까닭을 보고서에).
6. **시점 방향**: 앱의 모든 카메라 이동(`v.focus`·앱 트윈·시점 버튼·실행 연출)에서 전체 화면의 **좌우·물체 배치·빛이 오는 쪽이 뒤집히지 않는지** 전·후 스크린숏으로 확인하고, 뒤집히면 고친다.
7. **두 화면 모드**: 기본 화면(끔)은 지금 모습이 기준 — 이번에 고친 것 말고는 달라지지 않게. 크게 보기(켬 — 태블릿·PC 기본)에서: 조작 칸 첫 화면에 고르는 버튼, 장면 안 막대(측정값·실행·기록하기), 앱 HUD·배지·안내 글이 토글·막대·이동 화살표와 겹치지 않음, 페이지 스크롤 0. 앱이 장면 칼럼에 넣은 카드(시간 바 등)는 크게 보기에서 조작 칸으로(이미 한 앱: `sci-6-2-2-2`·`sci-6-2-2-3` — 그대로 동작하는지 확인).

  1. **관찰 질문을 두 회로 비교 질문으로**(사용자: "전지 1개일 때는 '어둡다'를 고르도록 하고 있어. 그런데 전구가 켜졌는데 어둡다는 개념이 이상할 수도 있어서(이건 전지 2개에 대한 상대적 개념이니)"). 지금은 부품 × 회로 6칸마다 "어둡다/밝다" 같은 **상대적인 말**을 고르게 한다(`lesson-config.js`의 `results`·`observeChoices`·`seen`). 이것을 **부품마다 한 번, 두 회로를 비교하는 질문**으로 바꾼다:
     * 전구: **"전구가 더 밝은 회로는 전지를 어떻게 연결했을 때인가요?"**
     * 전동기: **"전동기에 달린 날개가 더 빠르게 회전하는 회로는 전지를 어떻게 연결했을 때인가요?"**
     * 버저: **"버저에서 더 큰 소리가 나는 회로는 전지를 어떻게 연결했을 때인가요?"**
     * 보기(세 부품 모두): **"전지 1개 연결"**, **"전지 2개 직렬연결"**(사용자가 고름 — '직렬연결'은 전지 두 개 이상에만 쓰는 교과서 용어라 '1개 직렬 연결'은 쓰지 않는다). 정답은 "전지 2개 직렬연결".
