## 6. 사용자에게 물을 것

1. **(사진 `common-04`) 크게 보기 표의 칸이 틈 없이 붙은 모양**(칸 테두리로만 구분, 행 이름 두 줄)이 괜찮은지.
   - 1024×768에서 여섯 열을 44px 칸으로 넣으려면 틈을 없애야 했다(E1).
   - 같이 정할 것: L1(끝 열 고른 칸 테두리 오른쪽 잘림)을 이번에 고칠지, 다음 틀 작업 때 고칠지.
2. **(6-2-1-3) 선생님 '질문별 보기'**에서 이미 낸 결과의 궁금한 점("궁금한 점(선택)", 옛 문구)과 새 결과가 **두 질문으로 나뉘어** 보여도 괜찮은지. `sci-6-2-3-2` 때와 같은 방식이고, 학생별 보기는 둘 다 알맞게 보인다.
3. **(6-2-1-3) 칸 안내 예시** "예: 다른 지역에서도 낮의 길이가 똑같을까?"를 그대로 둘지.
   - 검토 의견: 답(남중 고도↔낮의 길이)을 알려 주지 않고 결론 제출 뒤에만 보여 괜찮다.
4. **(E2 물음 1) 조사판 `conclude.js`의 "제출한 글만 결과에"를 실험판에도 맞출지** — 검토 의견: **지금처럼 두기(옮기지 않기)를 권한다.**
   - 실험 앱은 모범 답안을 본 뒤 "빠진 내용이 있으면 위에서 고쳐 써도 좋아요"라고 안내한다. 옮기면 고친 글이 다시 제출하지 않는 한 선생님에게 가지 않아 학생이 헷갈린다.
   - 진행 기록 모양(`sent`)과 결과 글도 달라져 이번 단계의 '저장 모양 그대로' 원칙과 어긋난다.
   - 마칠 때 지금 칸의 글을 한 번 더 판정하므로 무의미한 글로 바꿔치기해 내는 길도 막혀 있다.
   - "처음 낸 글"과 "고친 글"을 선생님이 따로 보고 싶다면 나중에 새 기능으로 정할 일이다.
5. **(E2 물음 2) 조사 앱의 휴대폰 가로 머리말 줄이기** — 검토 의견: **사용자가 미뤄 둔 '휴대폰 화면 다듬기' 때 함께 하기를 권한다.**
   - 측정: 812×375에서 조사 앱은 머리말 161px + 아래 막대 69px로 본문이 약 145px뿐이라 다듬을 가치는 있다.
   - 다만 수업은 태블릿이라 급하지 않다. 넣으면 조사 앱 3개 화면 전체를 다시 확인해야 한다.

**배포해도 됨** — 높음·중간 발견이 없다. 기록·저장 모양·선생님 화면은 `sci-6-2-1-3` 궁금한 점 질문 글 두 곳 말고 모두 그대로다(실험 5·조사 3·6-2-1-3 저장 비교, 100설정 회귀 오류 0). 낮음 L1(끝 열 고른 칸 테두리 오른쪽 잘림)은 겉모양만이라 배포를 막지 않는다 — 사용자가 비교 사진(특히 `common-04` 칸 모양)을 보고 배포와 L1 처리 시점을 정하면 된다.
