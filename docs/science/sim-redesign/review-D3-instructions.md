## Build가 알린 판단거리(의견을 보고서에 — 사용자에게 물을지 Claude가 정한다)
* `sci-6-1-2-3`: "📸 찰칵!" 표시가 셔터 순간(5.0초)에 나타나고 자동차는 약 0.8초 더 달린다 — Build는 교과서 절차(사진 찍기 = 측정 과정, 흐르는 초시계와 같음)라 "측정 그림은 끝에 한 번" 규칙의 예외로 봤다. 맞는지, 학생이 헷갈릴 점이 있는지.
* `sci-6-1-2-5`: "▼ 앞부분" 표시가 실제 앞부분(122.0 cm 등)보다 약 3 cm 왼쪽을 가리키던 것을 고쳤다고 함 — 3D·관찰 카드 줄자 그림 모두 눈금과 정확히 맞는지(확대 사진으로, 과학 정확성). 학생이 값을 직접 적는 활동(값 읽기 → 계산기)은 이 차시 활동이라 그대로 — 타당한지.
* `sci-6-1-2-4`: 자동차 둘레 차선 바닥의 **보이지 않는** 누르기 자리 — 두 번 탭(처음 방향)·짧은 탭 ↔ 돌리기와 부딪히지 않는지, 옅게 보이게 할 필요가 있는지. 3D 처음 모습이 바뀜(장면 가운데로, 출발선·결승선 이름표를 앞쪽 한 줄로).
* `sci-6-1-2-1`: 문구 1곳 수정("고른 물체가 화면 안에 들어올 때까지 기다려요" → "사진 1을 찍기 좋은 때를 기다려요"), 고른 물체 표시 자리를 매 프레임 재는 부담(가능하면 프레임 시간), "누른 물체로 살짝 다가가기"를 넣지 않은 판단.
* `sci-6-1-2-2`: 꿀벌 위 3D 말풍선("1초", "2초"…)을 없애고 초 값은 DOM 표시로만 — 활동(초마다 위치 보기)에 지장이 없는지, 초 표시를 크게 보기 장면 안 막대로 옮길 필요가 있는지.
* 공통: 이미 고른 조건을 다시 누르면 관찰 카드가 닫히던 것을 앱마다 막음(6-1-2-1·-2·-4·-5) — 앱 사이 동작이 같은지. 휴대폰 크게 보기(기본 끔)에 남은 작은 겹침은 낮음으로.

## 확인할 것(앱마다, 수치로)
1. **기록 뒤 자동 진행 0·"다음" 표시 0**: 기록 → 고른 조건·장면 그대로, 조건 버튼·'기록한 칸 한눈에 보기' 표에 `.is-next`·👉 0개, 알림 글에 다음 칸 안내 없음, 학생이 직접 골라 모든 칸을 기록할 수 있음. 크게 보기에서 기록 직후 조작 칸의 조건 카드가 화면 안. 앱 코드에 남은 자동 선택·자동 재생이 없는지(`exp.select`·`setTimeout` 뒤 실행 등).
2. **재생 연출**: 자동차·꿀벌이 달리는 동안 대상만 움직이고(흐르는 초시계·빨리 감기 표시는 측정 과정이라 괜찮음), 다 달린 뒤의 측정 그림·값(거리 눈금·걸린 시간 등)이 도중에 먼저 나타났다 끝에 다시 나타나지 않는지.
3. **관찰 글**: 보기를 고르기 전 보기 바로 위 글·캡션·이름표·HUD에 정답과 같은 말이 없음(맞는 보기로 확인 → 드러남, 틀린 보기 → 계속 숨김). 장면 대체 설명(`aria-label`)은 상태를 말해도 됨.
4. **장면 속 글자·겹침**: 3D 이름표 잘림·가림 0(토글 "⛶ 전체 화면 보기"·장면 안 막대·드래그 안내 줄·이동 화살표·HUD·배지), 2D 그림의 글자. 바뀌는 값은 3D 이름표가 아니라 값 패널(크게 보기에서는 장면 안 막대 윗줄).
5. **직접 조작**: 새로 넣은 누르기(6-1-2-4 차선 바닥 등)와 원래 있던 누르기 — 버튼과 같은 결과, 실행 중·고를 수 없는 때 무시, 숨긴 물체 안 걸림, 짧은 탭 ↔ 돌리기 구분, "두 번 탭 = 처음 방향"과 부딪히는 경우.
6. **시점 방향**: 모든 카메라 이동(`v.focus`·다가가기·시점 버튼·실행 연출)에서 좌우·배치(출발선·결승선·차 순서) 유지, 연출 뒤 이동 화살표가 괜히 남지 않는지.
7. **두 화면 모드**: 기본 화면(끔)은 `2ddeeee`와 비교해 이번에 고친 것 말고 차이 0. 크게 보기 × 1024×768·1180×820·768×1024·810×1080·390×844·812×375, 어두움, 콘솔 오류 0, 페이지 스크롤 0.
8. **2D + 크게 보기**(`?no3d=1`): 칸 안에 맞음, 그림 속 누르는 칸이 처음부터 보임.
9. **답을 먼저 알려 주지 않음·과학 정확성**: 실험하기·기록 순간 글 전부(결론·관계 "~할수록"·"그래서"·원인 단정 금지). 측정값·단위·소수 첫째 자리 표기(135.0/122.0 cm, 4.2/5.8초, 24.4/23.8 cm/s, 교과서 값 27.0/17.2)가 전과 같은지, "모형" 표시, 학생 화면에 "지도서" 없음.
10. **저장 불변 + 선생님 화면 불변**(가장 중요): 앱마다 같은 입력으로 `2ddeeee` 판과 지금 판을 **가짜 로그인으로 끝까지** 해서 `app_results` POST 본문(`detail`·`detail.qa`)과 마지막 `app_progress` 본문이 시각·소요 시간 말고 **같아야 한다**. 그리고 두 판의 완료 `detail`을 `node_modules/jiti`로 `src/lib/app-responses.ts`의 `extractResponses`(와 `groupByStage`)에 넣어 결과(항목·질문·답·stage·extras)가 같은지(스크래치에서만 — `build-C-instructions.md` §3 방식). 예전 판 진행 기록(가짜 `app_progress` GET + localStorage) 이어받기, 로그아웃 때 충돌 창 없음.
11. **흐름**: 체험 모드와 가짜 로그인 둘 다 예상 → 실험(조건 전부) → 분석 → 정리 → '더 탐구하고 싶은 점'(6-1-2-1·-2는 따로 떨어진 단계 그대로) → 학습 마치기, 새로 고침 뒤 이어 하기, 단계 메뉴 칸 수.
12. **시간**: 앱 spec 시간표보다 늘지 않음(자동 선택이 없어져 조건마다 한 번 더 누르는 것은 약 1~2초 — 타당한지).
13. `node --check`(바뀐 JS), `git diff --check`, `diff -r scripts/templates/science-sim public/apps/<앱>/science-sim`(같아야 함), 임시 코드·`console.log`·`debugger` 없음, `src/`·응답 매핑·다른 앱 변경 없음.
