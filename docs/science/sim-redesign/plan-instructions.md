# 실험 앱 개편 계획(Plan) 지침 (2026-09-25)

당신은 **Plan** 담당이다. **코드는 고치지 않고** 계획서 `docs/science/sim-redesign/spec.md` 한 파일만 쓴다. 먼저 `CLAUDE.md` 전체(특히 "과학 차시 앱 규칙"), `docs/STATUS.md`, 공통 틀 `scripts/templates/science-sim/`(README.md, experiment.js, sim3d.js, stage-nav.js, lesson.js, persist.js, style-common.css), `scripts/templates/science-guide/`(조사 도우미), 관리자 응답 매핑 `src/data/app-responses/`(types.ts, helpers.ts, index.ts, sci-6-1-1-*.ts)와 `docs/admin/responses-spec.md`를 읽는다. 앱별로는 `public/apps/<앱>/spec.md`(끝 "개정" 절 우선)·`app.js`·`data/lesson-config.js`·`style.css`를 필요한 만큼 읽는다.

동시에 다른 에이전트가 20개 앱의 글자 겹침·싱크·답 알려 주기를 점검해 `docs/science/sim-redesign/audit.md`에 쓰고 있다. 그 결과는 Claude가 나중에 계획서에 합치므로, 당신은 **설계와 원칙, 앱별 변경 방향**에 집중한다(겹침·싱크 목록을 새로 만들 필요 없음 — 2학기 1단원은 예외로 직접 본다).

## 사용자 요청(2026-09-25, 원문 요지)
1. **1학기 1단원**(`sci-6-1-1-1~6`, 1~4 실험·5~6 조사)도 현재 앱 규칙(예상 질문 1개·정리 질문 1개·분석 보기 고르기 1~2개·7분·발전 질문 없음·조사 기록은 꼭 필요한 칸만)에 맞게 **질문 수를 줄이고 간략화**. 단 **학생 학습 결과 DB에 영향을 주면 하지 않는다.**
   * Claude의 1차 판단: `app_results`는 추가만 되는 기록이라 기존 결과는 그대로 남고, 관리자 "학생 응답"의 앱별 매핑은 `variants`(match 함수)로 예전·새 모양을 함께 보여 줄 수 있다 → **영향 없음**. 단 저장 구조가 바뀌면 저장 키 버전(`:vN`)을 올리므로 **진행 중이던 기록은 처음부터**(완료 결과는 무관). 이 판단을 코드로 다시 확인하고 계획서 §1에 근거(파일:행)와 함께 적는다. 영향이 있는 부분을 발견하면 그 앱은 "수정하지 않음"으로 계획한다.
2. **실험 화면 전체 폭**: 지금은 실험하기 화면이 좌우 반으로 나뉘어(왼쪽 3D 장면, 오른쪽 조작 카드) 있다(`style-common.css` `.ss-exp-layout` 342행 부근). 시뮬레이션 장면이 **화면 가로 전체**를 차지하게 하고, 실험 조작·기록하기 등은 **장면 안(겹쳐 놓는 조작 막대 등)에 넣을 수 있으면 넣고, 아니면 장면 바로 아래**에 둔다. **태블릿 세로 활동이 기본**(조작이 쉬움) — 가로·휴대폰에서도 망가지지 않게.
3. **직접 조작하는 느낌**: 학생이 장면의 물체를 직접 끌거나 누르는 느낌이 더 들게(예: 태양·손전등을 직접 끌기, 측정 도구를 대거나 눌러서 재기). **복잡해지면 안 되고 시간이 늘면 안 된다**(7분 원칙). 그리고 **기록할 때 답(결론·관계)을 알려 주지 않는다** — 측정값·관찰 사실만.
4. **2학기 1단원 재설계**(`sci-6-2-1-2~5`):
   * 탐구 2(`sci-6-2-1-2`, 하루 동안 태양 고도·그림자 길이·기온): 지금은 태양 그림과 지면이 줄로 이어진 느낌(빛줄기가 태양과 맞지 않음), 각도기가 너무 크고, 글자가 측정값을 가린다. **교과서 도구와 똑같을 필요 없다** — 태양이 있고, 사람·나무 같은 친근한 물체가 있고, **측정 방식만 과학적으로 맞으면 된다**. 학생이 흥미를 느낄 장면으로 새로 구성. (태양 고도 = 막대(물체) 끝과 그림자 끝을 이은 선이 지면과 이루는 각, 태양빛은 평행광, 그림자 길이·방향이 태양 위치와 항상 맞아야 함. 실험관찰 조건 9:30~15:30 7칸 + 시간 바, 8:30 제외는 유지 — 사용자 결정)
   * 탐구 3(`sci-6-2-1-3`, 월별 태양 고도·낮의 길이 등): 월별 궤적이 계속 남아 더 헷갈린다 → **선택한 달의 궤적만** 보이게. 다만 **봄·가을(같은 궤적), 여름, 겨울 대표 궤적 3개를 동시에 보는 옵션**을 준다(총 3개). 1~12월 21일 12칸 측정·조사 기간 표기 생략은 유지.
   * 탐구 4·5(`sci-6-2-1-4`, `-5`)도 글자 겹침·싱크 문제를 같은 기준으로 고친다(점검 결과 참고, 직접도 확인).

## 계획서 `docs/science/sim-redesign/spec.md` 구성(한국어)
0. **요약·범위·단계**: 무엇을 바꾸고 무엇을 안 바꾸는지. 앱 20개(실험)·3개(조사) 중 어디에 무엇이 적용되는지 표. **단계 나누기**(예: A 공통 틀 전체 폭 화면 + 답 알려 주기 제거 → B 2학기 1단원 재설계 → C 1학기 1단원 간략화 → D 나머지 앱 조작감·겹침 수정) — 한 번에 너무 많이 바꾸지 않게, 단계마다 Build·Review·사용자 확인이 가능하도록.
1. **1학기 1단원 간략화**: DB 영향 분석(근거), 앱별 "남길 질문 / 뺄 질문 / 바꿀 질문"(현재 문항을 인용), 측정 조건은 실험관찰 기준을 줄이지 않음(측정 규칙), 새 저장 키, `src/data/app-responses/sci-6-1-1-*.ts`에 새 변형(v2) 추가 방식, 7분 시간표. 이 앱들은 학생이 이미 사용했으므로 과학 내용·측정 조건은 바꾸지 않고 **질문 수·길이만** 줄이는 방향.
2. **공통 틀: 전체 폭 실험 화면**: 새 배치(세로 태블릿 768×1024 / 가로 1024×768 / 1180×820 / 휴대폰 375×812·812×375 각각 그림처럼 설명 — 장면 높이, 장면 안 조작 막대 위치, 장면 아래 패널, 기록하기 버튼 위치, 아래 이동 막대와 겹치지 않게), 공통 틀에 넣을 부품(장면 위 조작 막대·떠 있는 기록 버튼·접는 기록 표 등)과 **하위 호환**(20개 앱이 한꺼번에 깨지지 않게, 앱이 새 배치를 켜는 방식), 3D 장면 크기 변경 시 카메라·드래그·성능(태블릿 GPU) 고려, 2D 대체 화면 처리, 접근성(44px, 키보드, 움직임 줄이기).
3. **직접 조작 원칙과 답 알려 주기 금지 원칙**: 공통 원칙(장면 속 물체를 끌기·누르기, 측정 도구 애니메이션은 1초 안쪽, 조작 단계 추가 금지, 기록 문구는 "값·관찰"만), 앱별 조작 아이디어 표(20개, 한 줄씩, 시간 증가 없음 확인).
4. **2학기 1단원 재설계**(탐구 2·3·4·5 각각): 장면 구성(물체·배경·태양·빛 표현), 측정 방식과 과학적 근거(지도서·교과서 쪽수), 표시 규칙(이름표가 측정값·물체를 가리지 않는 배치 원칙 — 예: 이름표는 장면 가장자리 고정 칸, 각도 표시는 작은 호), 싱크 보장 방법(한 가지 상태 값에서 모든 그림을 계산), 탐구 3의 궤적 표시 방식(선택 달 1개 / 계절 대표 3개 보기 전환), 저장 키·기록 구조를 바꿀지(바꾸면 `:vN` 올리고 사용자에게 알림), 7분 시간표.
