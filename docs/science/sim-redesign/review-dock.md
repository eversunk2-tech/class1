### 항목 5 — 태블릿 실제 환경 걱정거리(코드 읽기 + 흉내): **조건부**(L2, 실기기 미확인)
* **`position: fixed` + 화면 키보드**: 키보드 대응 코드(`visualViewport`·focus 처리)는 없다 — 브라우저 기본 동작에 맡긴다. 조작 칸 안 `scroll-margin: 8px`(`style-common.css:504`)이라 칸 안 초점 이동은 정확하다. 흉내 결과(6-1-2-4 810×1080·768×1024·1180×820, 6-1-2-5 810×1080): **프로그램/Tab 초점 → 조작 칸만 스크롤되어 입력칸이 칸 안에 보이고 페이지 0**(칸 맨 위·맨 아래 어느 쪽에서든). 반쯤 가린 입력칸을 **누르면** 초점만 가고 칸은 안 움직인다(마우스 누름의 보통 동작 — 실제 기기는 키보드가 뜰 때 브라우저가 보이게 하는지에 달림). 세로 태블릿에서 관찰 카드가 나온 직후 숫자 칸은 조작 칸 아래 끝(810×1080 y 966~1,018, 칸은 1,003까지)이라 키보드(화면 아래 30~40%)에 가릴 위치 — iPad Safari가 화면을 밀어 보여 주는지 실기기 확인 필요. 창을 줄이는 키보드에서는 L2.
