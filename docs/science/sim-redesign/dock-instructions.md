# 크게 보기 개편 지침(dock) — "장면 + 옆 조작 칸" 한 화면 실험실 (2026-09-26, spec 개정 6)

먼저 읽기: `CLAUDE.md`(과학 차시 앱 규칙 — 방금 고친 "실험 화면 배치" 줄), `docs/science/sim-redesign/spec.md` 끝의 **개정 6**(최우선)과 개정 4·5, 공통 틀 README("추가 기능 2026-09-25" 절)와 `experiment.js`(`enlarge()`·`create()`·`showObserve`·`revealRecord`·`run`)·`style-common.css`(`.is-full` 규칙들), `fix-A-report.md`·`review-A2.md`(지금 크게 보기의 설계와 지난 문제들), `review-B2.md`.

## 사용자 요청(원문 요지)
크게 보기로 하면 조작 메뉴들이 전부 장면 아래로 내려가 위아래 스크롤을 해야 하고 학생들이 실험 방향을 잊을 수 있다. **크게 보기 화면에서는 실험 화면 안의 한쪽 부분에(실험 장면을 가리지 않으며) 조작 메뉴들이 나타나** 위아래 스크롤 없이 한눈에 조작할 수 있게.

## 설계(개정 6 — 이대로 구현)
1. **한 화면 실험실**: 크게 보기가 켜지면 `.ss-exp-layout.is-full`이 **머리말 아래 ~ 아래 이동 막대 위 화면 전체**를 채운다(권장: `position: fixed; top: calc(var(--ss-header-h) + 8px); bottom: calc(var(--ss-footer-h) + 8px)`; 좌우 8px + 안전 영역, 바탕은 페이지 바탕색, z-index는 머리말·아래 막대·알림보다 아래). 뒤 페이지는 스크롤되지 않게(예: `html:has([data-stage]:not([hidden]) .ss-exp-layout.is-full) { overflow: hidden }` — 실험하기 단계를 벗어나면 저절로 풀려야 한다). 머리말을 접으면 `--ss-header-h`를 따라 실험 영역이 커진다.
2. **조작 칸(dock)**: 기본 화면 오른쪽 패널(`.ss-exp-panel` — 진행 막대·조건 카드·빨리 감기·슬라이더 등 앱 카드·관찰 카드·기록 표)을 그대로 **장면 옆 칸**으로. **가로 화면은 오른쪽**(너비 대략 `clamp(300px, 32vw, 420px)`), **세로는 아래쪽**(장면 위 약 55~60%, 조작 칸 아래 — 둘 다 한 화면 안). 휴대폰도 같은 규칙(가로 = 오른쪽 약 280px, 세로 = 아래). 조작 칸은 `overflow-y: auto; overscroll-behavior: contain` — **길면 칸 안에서만** 스크롤. 장면은 남는 자리를 채우고(`flex: 1; min-height: 0`, 앱 `style.css`의 `.ss-exp-view` 높이 규칙보다 우선), 보기 도구 줄은 장면 아래에 작게.
3. **'실험 방법 알아 두기'(`R.intro`)와 안내 줄(`R.lead`)**: 크게 보기에서는 조작 칸 **맨 위**로 옮기고(접기 상태 유지), 끄면 원래 자리로(`homeOf`/`goHome` 재사용). 가려져서 못 읽는 일이 없게.
4. **장면 안 막대(실행·📝 기록하기·측정값)는 그대로**(개정 2-3). 3D 칸은 막대 위에서 끝나는 것(`.has-bar`)도 그대로.
5. **스크롤 동작 정리**: 크게 보기에서는 페이지가 움직이지 않는다 —
   * 관찰 카드는 조작 칸 안 **원래 순서**(조건 카드 다음)에 둔다(fix-A F4의 "관찰 카드를 패널 맨 앞으로"는 크게 보기에서 하지 않는다). 실행 뒤 `showObserve()`는 **조작 칸 안에서만** 관찰 카드가 보이게 스크롤(`scrollIntoView({ block: "nearest" })`이 조작 칸만 움직이는지 확인 — 페이지·고정 영역은 안 움직여야 한다).
   * `revealRecord()`: 기록 버튼이 장면 안 막대에 있으면(늘 보임) 아무것도 안 한다. 막대가 없는 앱(`sceneBar:false`·`factors:[]`)은 조작 칸 안에서만 보이게.
   * `run()`의 "장면이 보이게 스크롤"은 크게 보기에서 하지 않는다.
   * 지금 크게 보기 전용으로 있는 **페이지 맞춤 코드**(`fit()`의 `--ss-scene-h` 계산, 머리말·아래 막대·창 크기 변화 때 다시 맞추기, 토글 누를 때 `scrollIntoViewSafe(viewBox)`, 관찰 카드 숨길 때 조건 카드 자리 보정)는 새 배치에서 필요 없으면 **걷어 낸다**(기본 화면 동작에는 영향이 없게). README에서 `--ss-scene-h` 설명도 정리.
6. **2D 대체 화면**: 크게 보기에서 2D 그림이 장면 칸보다 크면 **장면 칸 안에서** 맞추거나(최대 높이) 스크롤 — 막대가 칸 밖으로 밀리지 않게. 앱 `style.css`에 전에 넣은 크게 보기 전용 2D 최대 높이 규칙(2-1-2·2-1-3·2-1-4·2-1-5, fix-B)은 새 배치에 맞게 정리.
7. **기본 화면(끔)은 지금 그대로**(픽셀 단위). 토글·기본값(태블릿 세로 켬, 막대에 넣을 것이 없는 앱은 끔)·방향별 기억·머리말 접기·`SciSim.Experiment.enlarge()` API(`sci-6-2-1-3`·`-4`가 씀)는 그대로 동작해야 한다.
8. 접근성: 조작 칸 `role="region"`·이름("실험 조작"), Tab 순서 = 토글 → 장면 안 막대 → 조작 칸, 움직임 줄이기면 애니메이션 없음. (선택) Esc로 기본 화면.

## 앱별 확인·정리(공통 틀을 바꾼 뒤)
* **20개 실험 앱 모두** 새 크게 보기에서 확인하고, 필요한 앱만 **그 앱 `style.css`·`app.js`를 최소로** 고친다(앱 HUD·확대 칸·이름표가 토글·막대와 겹침 등). 특히: `sci-6-2-1-5`(B4가 가로 크게 보기에서 관찰 카드를 앱 CSS로 숨김 → 새 배치에선 되돌리기, 확대 칸 자리), `sci-6-2-1-2`(시간 바 카드·옆에서 본 모습 칸·scenePanel), `sci-6-2-1-3`(범례·궤적 버튼·값 패널), `sci-6-2-1-4`(슬라이더 카드·손전등 끌기), 2D 최대 높이 규칙이 있는 앱.
* **`sci-6-1-1-1`~`-4`의 앱 파일(`app.js`·`style.css`·`index.html`·`data/`)은 고치지 않는다** — 단계 C 변경이 아직 커밋 전이다. 이 네 앱은 공통 틀 사본(`science-sim/`)만 동기화하고, 확인해서 필요한 앱 수정은 **보고서에 목록으로**(Claude가 C 커밋 뒤 처리). 조사 앱 3개(`science-guide`)는 해당 없음.
* 측정 조건·값·문항·저장 키·`detail` 모양·과학적 의미가 있는 색은 바꾸지 않는다.
