## 1. 공통 틀(정본 `scripts/templates/science-sim/`)만 고친다 → 끝나면 실험 앱 20개 사본에 복사
### 1-1. 전체 폭 실험 화면(옵트인, 하위 호환)
* `SciSim.Experiment.create(o)`에 옵션 추가(이름은 계획서 제안 `fullScene: true`, `scenePanel: node` — 더 나은 이름이면 바꿔도 되고 README에 적는다). **옵션을 안 준 앱은 지금과 픽셀 단위로 같게**(좌우 배치·높이·버튼 위치 그대로) — 이것이 가장 중요한 합격 기준.
* `fullScene: true`이면:
  * 실험하기 화면이 화면 폭과 무관하게 **1열**: 3D/2D 장면이 가로 전체, 그 아래에 조건 고르기 카드·관찰 카드·기록 표.
  * **장면 안 조작 막대**(장면 박스 안쪽 아래, 반투명 바탕): **[실행 버튼(R.run)] + [📝 기록하기(R.record, 값이 들어간 라벨 그대로)] + [측정값 패널(scenePanel, 앱이 넘긴 노드)]**. 사용자 결정: "실행·기록하기·측정값만 장면 안, 조건 고르기 버튼은 장면 바로 아래". 버튼은 원래 자리에서 **옮긴다**(복제 금지 — 이벤트·disabled 상태가 하나로 유지되게).
  * 좁은 화면(대략 폭 480px 미만)이나 장면이 낮은 가로 휴대폰에서는 막대에 버튼 두 개만 두고 측정값 패널은 장면 바로 아래 카드로(글자가 너무 작아지지 않게).
  * 2D 대체 화면(`.is-2d`, 높이 auto)에서는 막대를 장면 안에 겹치지 않고 장면 바로 아래에 둔다.
  * 장면 높이: 태블릿 세로(768×1024)에서 장면이 주인공이 되게(대략 45~55vh), 가로 태블릿(1024×768)·1180×820에서는 막대까지 한 화면에 들어오게(대략 40~48vh), 휴대폰 세로 약 35vh, 휴대폰 가로 최소 200px. 기록하기 버튼이 아래 이동 막대(`.ss-footer-nav`)에 가리지 않아야 한다(기존 `--ss-footer-h`·`revealRecord` 활용).
  * 앱이 `--ss-scene-h` 같은 변수 하나로 높이를 조정할 수 있게(선택).
  * 3D 카메라는 `sim3d.js`의 `ResizeObserver`/`computeFit()`이 새 크기에 맞춘다 — 넓고 낮은 장면에서 물체가 너무 작아지지 않는지 확인.
  * 접근성: 막대 안 버튼 44px 이상, 키보드 초점 표시, DOM 순서가 보이는 순서와 같게(보기 도구 → 막대(실행·기록·값) → 조건 카드 → 관찰 카드), `prefers-reduced-motion`에서 등장 애니메이션 없음.
### 1-2. 끌기 도우미 `sim3d.js`
* `v.draggable(obj, opts)`(순수 추가, 안 쓰는 앱에 영향 없음): 포인터다운으로 물체를 잡으면 카메라 회전(OrbitControls)을 잠시 멈추고, 포인터무브마다 **지정한 평면(또는 구면·곡선에 투영할 수 있게 레이 제공)**과의 교차점을 콜백으로 넘기고, 포인터업에 끝 콜백. 터치·마우스 모두, 잡는 영역은 물체보다 넉넉하게(44px 이상 느낌). 끌 수 있는 물체 위에서는 커서 `grab`. 사용 예를 README에 적는다(예: 태양을 하늘 반구 위로 끌기 → 가장 가까운 시각으로 바꾸기, 손전등을 호 위로 끌기 → 각도).
### 1-3. 알림(토스트)이 장면을 가리지 않게
* `lesson.js`의 `toast()`/`.ss-toast`(style-common.css 476행 부근): 실험 장면을 덮지 않는 위치(머리말 바로 아래 등)로. 점검: `sci-6-2-1-2`의 "🎉 7개 시각을 모두 기록했어요!"(3.8초)가 장면 전체를 덮었다. 모든 앱에 적용되는 겉모양 변경이므로 여러 앱에서 확인. `pointer-events:none` 유지.
### 1-4. README
* 새 옵션·도우미·배치 규칙, "바뀌는 값은 3D 이름표 대신 값 패널에"(계획서 §4.6 확장) 원칙, "기록 순간에 결론·관계를 말하지 않는다"(§3.2) 원칙을 README에 적는다.

## 4. 확인(반드시)
* **하위 호환**: 옵션을 안 준 앱 3개 이상(예: `sci-6-1-1-2`, `sci-6-2-2-2`, `sci-6-2-3-3`)의 실험하기 화면을 바꾸기 전·후 같은 크기(768×1024, 1024×768)로 찍어 비교 — 알림 위치 말고는 같아야 한다.
* **새 배치**: `sci-6-2-1-4`와 `sci-6-2-2-3` 두 앱에서 **작업 중에만 임시로** `fullScene: true`(+ 측정값 노드)를 켜 768×1024·1024×768·1180×820·375×812·812×375·어두움·2D(`?no3d=1`)에서 확인하고 스크린숏을 남긴 뒤 **원래대로 되돌린다**(보고서에 되돌렸음을 적기). 막대 안 실행·기록 버튼이 제대로 동작(기록이 표에 들어감)하는지, 아래 이동 막대와 겹치지 않는지.
* **끌기 도우미**: 임시 시험 코드로 한 앱에서 물체 끌기가 되는지(마우스·터치 이벤트 흉내) — 시험 코드는 되돌린다.
* **답 알려 주기 문구**: 5개 앱에서 바뀐 문구가 화면에 보이는지.
* 공통 틀 정본과 20개 실험 앱 사본 `diff -r` 일치(조사 도우미 3개 `science-guide`는 이번에 안 바뀜 — 그대로인지 확인). `npm run lint`.
* 테스트: 개발 서버가 이미 `http://localhost:3000/class1/apps/<앱>/index.html`에서 돈다(끄지 말 것). **자기 전용 headless Chrome**(포트 **9346**, 프로필은 스크래치 `/private/tmp/claude-501/-Users-sungchul-Desktop-classroom/7bf3a39e-3017-4189-b337-1b82aace66bb/scratchpad/build-A/`), WebGL은 `--use-angle=swiftshader --enable-unsafe-swiftshader`. **실제 Supabase는 첫 로드부터 차단**(`--host-resolver-rules="MAP *.supabase.co 127.0.0.1:9, MAP supabase.co 127.0.0.1:9"` + CDP Fetch 가짜 응답: `site_settings`→`login_required:false`, GET→`[]`/`null`, POST→201, OPTIONS→204). 체험 모드로 충분하다. `localStorage.clear()` 금지(그 앱 `sci6…` 키만), 다른 탭·프로세스 건드리지 않기, 끝나면 Chrome 종료·임시 파일 정리(스크린숏만 남김).
