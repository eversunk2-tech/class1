## 사용자가 정한 것(합격 기준의 근거)
1. **기본 화면은 지금 구조 그대로**(가로 901px 이상: 장면 왼쪽·조작 오른쪽 / 세로·좁은 화면: 위아래). 새로 생긴 버튼 2개와 알림 위치 말고는 전과 같아야 한다.
2. 장면 한쪽 **"⛶ 전체 화면 보기"** 토글(20개 실험 앱 모두, 앱 코드 없이) → **페이지 안에서 크게 보기**: 장면 가로 전체, **실행·기록하기·측정값은 장면 안 막대**, 조건 버튼은 장면 바로 아래. **가로 화면에서도 장면 전체와 막대(와 조건 줄)가 스크롤 없이** 보이게.
3. **태블릿 세로(세로 방향·폭 600px 이상)는 크게 보기가 기본**, 가로 태블릿·PC·휴대폰은 기본 끔. 학생이 누른 선택은 **방향별로 기억**.
4. **머리말 접기**(실험 20 + 조사 3): 계정 줄(로그인 중·로그아웃, 체험 모드 줄)과 단계 메뉴를 **함께** 접고 앱 제목 줄만 남긴다. 아래 이전/다음 버튼으로 이동 가능. 선택 기억.
5. 실험하기·기록하는 순간에는 **측정값·관찰 사실만**(결론·관계·원인 단정 금지), 알림은 장면을 가리지 않는 곳에.

## 확인할 것
1. **하위 호환(끔 상태 = 예전과 같음)**: 바꾸기 전 모습은 `git archive HEAD public/apps/<앱> public/fonts | tar -x -C <스크래치>/before`로 꺼내 자기 전용 정적 서버(포트 **8781**, `python3 -m http.server`로 `<스크래치>/before/public`을 서빙 → `http://localhost:8781/apps/<앱>/index.html`)에서 띄우고, 지금 모습은 개발 서버 `http://localhost:3000/class1/apps/<앱>/index.html`. 앱 최소 5개(`sci-6-1-1-2`, `sci-6-2-2-2`, `sci-6-2-3-3`, `sci-6-2-1-2`(값 패널을 matchMedia로 직접 옮김), `sci-6-2-2-3`(앱 style.css에 높이 규칙 6개)) × 1024×768·1366×768(기본 끔)과 768×1024(기본 켬 → 토글로 끈 상태): 실험하기 단계에서 장면·조작 패널·실행 버튼·조건 카드·관찰 카드의 위치·크기(getBoundingClientRect)와 스크린숏을 비교. 허용되는 차이는 **장면 위 토글 버튼, 머리말 접기 버튼, 알림 위치**뿐. 실행→관찰→기록 한 번씩(끔 상태)에서 기록하기 버튼의 활성/비활성 흐름이 예전과 같은지(공통 틀이 `R.record.disabled = true`를 몇 곳에 새로 넣었다 — 보기 고르기형·숫자형·확인하기(`check`)형·같은 조건 여러 번(`trials`) 앱에서 각각 확인).
2. **크게 보기(켬)**: 20개 실험 앱 전부를 1024×768과 768×1024에서 실험하기 단계까지 열어 콘솔 오류 0, 막대 안에 실행·기록하기(와 넘긴 경우 측정값)가 있고 조건 카드가 장면 바로 아래인지(스크린숏 목록). 그중 최소 8개 앱(보기형·숫자형·확인하기형·반복 측정형·시간 바/달 바가 있는 `sci-6-2-1-2`·`-3`·확대 카메라가 있는 `sci-6-2-1-5`·분류가 있는 1학기 1단원 앱)에서 **고르기→실행→관찰→기록→표에 들어감**을 두 모드에서, 그리고 **실행 뒤 기록 전에 토글을 바꿔도** 기록이 되고 버튼이 복제·유실되지 않는지, 막대 버튼이 비활성일 때 비활성으로 보이는지. 크게 보기에서 관찰 카드(보기 고르기)가 장면 아래에 있고 기록하기는 장면 안 막대에 있으므로, **실행→보기 고르기→기록하기 사이에 화면이 몇 번·얼마나 스크롤되는지**를 가로·세로에서 재고, 학생에게 헷갈리거나 번거로운지 판단해 개선안을 적는다(예: 크게 보기에서 관찰 카드를 조건 줄 위로, 또는 막대에 짧은 안내).
   * **측정값 노드(`scenePanel`) 시험**: 단계 A에서는 어느 앱도 넘기지 않으므로, **저장소를 고치지 말고** 스크래치에 지금 작업 트리의 `sci-6-2-1-4`(+ `public/fonts`)를 복사해 그 사본의 `app.js`만 값 패널을 `scenePanel`로 넘기게 바꾼 뒤 자기 정적 서버(포트 **8782**)로 띄운다. 1024×768(막대 안)·768×1024·375×812·812×375(좁은/낮은 화면 = 장면 아래 카드)에서 토글을 여러 번 오가며 값 패널이 **사라지거나 두 개가 되지 않는지**, 기본 화면으로 돌아오면 **원래 자리**에 있는지, 막대 안 순서(실행 → 기록하기 → 측정값)와 글자 크기·잘림.
3. **가로 화면 스크롤 없음 실측표**: 1024×768, 1180×820, 1280×800, 1366×768, 1920×1080에서 **토글 버튼을 눌러** 크게 보기를 켠 직후(버튼이 장면을 화면에 맞춰 스크롤한다) 앱 최소 5개(조건 카드가 많은 `sci-6-2-2-3`·`sci-6-1-1-4`, 장면 옆 카드가 있는 `sci-6-2-1-2`·`sci-6-2-1-3`, 표가 긴 `sci-6-2-3-3`)의 머리말 아래·장면 위·장면 아래·막대 아래 vs 아래 이동 막대 위, 장면 높이·폭(px). 합격: 장면 전체와 막대가 머리말과 아래 막대 사이에 다 들어가고 장면이 기본 화면보다 커야 한다(조건 줄은 스크롤해서 보는 것이 설계). 머리말 **펼침·접힘 두 상태 모두**(접으면 장면이 커지는지). 켠 상태로 새로 고침했을 때(토글을 누르지 않고 실험하기에 들어온 경우)의 첫 모습도 기록. 창 크기를 바꾸거나 3D↔2D를 바꾼 뒤에도 다시 맞는지, `ResizeObserver loop` 경고가 없는지. 장면 안 드래그 안내 문구(`.ss-view-tip`)가 3D 이름표·막대와 겹치는지도 본다.
4. **기본값·기억**: 768×1024·810×1080(켬), 1024×768·1366×768·1920×1080(끔), 375×812·390×844(세로지만 폭 600 미만 → 끔), 812×375(끔). 세로에서 끔으로 바꾸고 새로 고침 → 끔 유지, 가로로 바꾸면(창 크기 변경) 가로 기본값, 다시 세로 → 끔(기억) — 앱을 옮겨도 같은지. 저장 키가 `sci6`으로 시작하지 않는지(로그아웃 정리 대상 아님), localStorage 읽기·쓰기가 예외를 던지게 만든 상태(`Page.addScriptToEvaluateOnNewDocument`로 `Storage.prototype.getItem/setItem`이 throw)에서도 앱이 기본값으로 정상 동작하는지.
5. **머리말 접기(23개 앱 — 실험 20, 조사 3 `sci-6-1-1-5`·`sci-6-1-1-6`·`sci-6-1-2-6`)**: 제목 줄에 버튼, `aria-expanded`, 접으면 계정 줄(가짜 로그인 세션 상태의 "○○ 계정으로 로그인 중·로그아웃"과 체험 모드 줄 **둘 다** 확인)과 단계 메뉴가 사라지고 제목 줄(저장됨 표시 포함)만 남는지, `--ss-header-h`가 따라 바뀌어 장면 sticky 위치·알림 위치·`scroll-margin`이 맞는지, 아래 이전/다음으로 단계 이동이 되는지, 새로 고침·다른 앱에서도 기억되는지, 움직임 없이 바뀌는지, 휴대폰 가로(812×375)에서 제목 줄이 넘치지 않는지. **로그인 잠금 켜짐 + 비로그인**(로그인 안내 화면)에서 접기 버튼이 이상하게 동작하지 않는지. 단계 메뉴 칸 수가 앱의 단계 수와 같은지(Claude가 `stage-nav.js`·`style-common.css`에 `--ss-steps`를 더함 — 4단계 앱 오른쪽에 빈 칸이 남던 것, 5단계 앱은 그대로).
6. **알림 위치**: 기록할 때 뜨는 알림(예: `sci-6-2-1-2` 7개 모두 기록 알림, 일반 "기록했어요")을 기본 가로(장면이 머리말 바로 아래 sticky)·기본 세로·크게 보기 가로·세로에서 띄워 **장면과 겹치는 넓이**(px², 장면에서 차지하는 비율)와 무엇을 가리는지 기록. "장면을 가리지 않는다"를 만족하는지 판정하고, 아니면 대안(예: 가로 기본 화면에서는 조작 패널 칼럼 위, 머리말 위에 겹치기 등)을 적는다. `pointer-events:none`이 유지되는지.
7. **2D 대체 화면**(`?no3d=1`)과 3D↔2D 전환: 두 모드에서 막대가 장면과 겹치지 않고 바로 아래에 있는지, 크게 보기에서 3D↔2D를 10번 오가도 WebGL 컨텍스트·캔버스가 쌓이지 않는지(캔버스 수, 콘솔 경고), 토글을 20번 눌러도 이벤트 수신기·`ResizeObserver`가 늘지 않는지(가능한 범위에서 — 예: `getEventListeners`는 headless에서 쓸 수 없으면 코드 읽기로 판단).
8. **어두움·접근성**: 어두움 모드에서 막대(유리 바탕) 위 글자·버튼과 토글 버튼 대비 AA, `forced-colors`에서 보이는지. 크게 보기의 DOM 순서(보기 도구 → 막대(실행·기록·값) → 조건 카드 → 관찰 카드)가 보이는 순서·Tab 순서와 맞는지, 토글·접기 버튼 44px 이상·초점 표시, 막대 `role="group"` 이름.
9. **끌기 도우미 `v.draggable()`**(`sim3d.js`): 코드 읽기 — pointerdown/move/up/cancel·포인터 캡처·끌기 중 카메라 회전 멈춤과 **취소·캡처 잃음·3D↔2D 전환 때 원상 복구**, 잡는 영역, 커서, 여러 개 등록, 해제(dispose), 안 쓰는 앱에 영향 없음. 파일을 고치지 말고 CDP `Runtime.evaluate`로 한 앱의 3D 물체에 임시로 붙여 마우스·터치(`Input.dispatchTouchEvent`) 끌기 콜백과 카메라가 돌지 않는지 확인. README 사용 예가 실제 API와 맞는지.
10. **답 알려 주기 문구 5곳**(`sci-6-2-3-1` 회로 캡션, `sci-6-2-3-2` 병렬연결 팝업, `sci-6-2-2-3` 관찰 카드 캡션, `sci-6-2-1-5` 예상 힌트 1, `sci-6-1-2-4` 그래프 아래 문구): 화면에 바뀐 문구가 보이는지, 결론·관계·원인 단정이 남지 않았는지, 과학적으로 틀린 말이 없는지, **문구 말고 바뀐 것이 없는지**(저장 키·`detail`·보기·정답·측정값 — diff로). 같은 앱의 다른 기록 순간 문구(알림·관찰 안내·이름표)에 비슷한 문제가 더 있으면 목록으로.
11. **규칙·정리**: 정본 ↔ 사본 `diff -r`(실험 20개 `science-sim`, 조사 3개 `science-guide`), `npm run lint`, 임시 시험 코드가 남지 않았는지(앱·정본에서 `fullScene: true`, 시험용 `draggable` 호출, `console.log`, `debugger`), `localStorage.clear()` 없음, 새 외부 자원 없음, 앱 안 상대경로, README(두 정본)가 새 기능·규칙("바뀌는 값은 값 패널에", "기록 순간에 결론을 말하지 않는다")을 설명하는지. 학생 흐름에 새 필수 단계가 생기지 않았는지(7분 규칙).

## 테스트 규칙(반드시)
