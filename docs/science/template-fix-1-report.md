## 1. (가장 중요) 탭 전환·새로고침 뒤 뜨던 "기록이 두 가지예요" 가짜 충돌

### 원인
1. 탭이 숨겨지거나 페이지를 떠날 때 `persist.js`의 `flushNow()`가 스냅샷을 **keepalive**로 보낸다. 페이지가 사라지면 그 응답을 처리하지 못하므로 `syncedAt`은 옛 값이고 `dirty`는 true로 남는다.
2. 그런데 `sim3d.js`는 숨겨지면 남은 트윈을 즉시 끝내고(`setRunning` → `finishAll`), 그 뒤 `experiment.js`·앱 코드가 `scene` 같은 키를 **더 쓴다**. 즉 "보낸 뒤의 쓰기"가 생긴다.
3. 다시 열면 서버 `updated_at`(우리가 보낸 저장으로 바뀜) ≠ `syncedAt`이고 로컬도 `dirty`라서 "둘 다 바뀜"으로 판단하고, 내용까지 다르므로 충돌 창을 띄웠다.

### 고친 방법 — 방향 ②(가짜 충돌만 걸러내기), ①은 쓰지 않았다
`persist.js`의 `reconcileInner()`에서 충돌 창을 띄우기 **직전에** 두 가지를 본다(둘 다 `canon()` 기준, 데이터는 하나도 버리지 않는다).

| 위치 | 규칙 |
|---|---|
| `persist.js:825` | **ⓐ 서버 내용 = 이 기기가 마지막으로 보낸 내용**이면(메타의 `sentFp` 지문과 일치) 창 없이 로컬을 올린다. |
| `persist.js:826` | **ⓑ 서버 내용이 로컬 안에 그대로 들어 있으면**(키 단위로 값이 같고 로컬에 키가 더 있음 = 로컬이 서버의 확장) 창 없이 로컬을 올린다. |
| `persist.js:830` | 위 두 경우의 처리 `keepLocalOver()`: `syncedAt`을 서버 값으로 맞추고 `dirty`를 유지한 채 바로 저장한다(로컬이 서버를 덮어쓰되, 서버 내용은 이미 로컬에 들어 있으므로 잃는 것이 없다). |
| `persist.js:906`, `925` | 보내기 직전에 보낼 내용의 지문을 메타 `sentFp`에 **먼저 적고**(페이지가 사라져도 남는다), 응답을 받으면 지운다. |
| `persist.js:232`, `241` | 지문 `fpOf()`(FNV-1a, 길이+해시)와 포함 검사 `isExtensionOf()`. |

* ⓑ만으로는 부족하다. 두 번째 실험처럼 **이미 있던 키를 덮어쓰는** 경우에는 로컬이 서버의 확장이 아니기 때문이다. ⓐ가 그 경우를 덮는다.
* 방향 ①(숨김 상태에서 실험 진행·기록 중단)을 **쓰지 않은 까닭**: `sim3d.js`의 트윈을 멈춰 두면 `tween()`이 돌려주는 Promise가 숨겨진 동안 끝나지 않아, 그 Promise를 기다리는 앱 코드(17개 앱이 각각 다르게 쓴다)가 멈춘 채로 있게 된다. 하위 호환을 보장하기 어렵고, ②가 앱 코드와 상관없이(2D 연출·앱 자체 애니메이션 포함) 모든 경우를 덮는다. 진짜 충돌 판단은 그대로 남는다.
* 메타(`<storageKey>:__meta`)에 `sentFp` 필드가 하나 늘었다. 이는 **localStorage의 표시 키**이고 `app_progress.state`(스냅샷)에는 들어가지 않는다. 옛 메타에 이 필드가 없어도 그대로 동작한다.

### 재현 결과 (고치기 전 / 뒤)
같은 앱 사본 두 벌(`before-`는 위 두 줄만 뺀 것)으로, 떠날 때 보낸 keepalive 저장의 **응답만 사라지고 서버에는 반영되는** 상황을 만든 뒤 새로고침했다(= 실제 새로고침·탭 닫기 상황).

| 시나리오 | 고치기 전 | 고친 뒤 |
|---|---|---|
| 떠날 때 저장 → 그 뒤 앱이 `scene` 기록 → 새로고침 | **"⚠️ 기록이 두 가지예요" 창 뜸** (서버 4키 / 로컬 5키) | **창 없음.** 로컬 5키가 그대로 서버에 올라가고 `✅ 저장됨`, `dirty=false` |
| 진짜 충돌(서버 내용을 다른 기기가 다르게 바꾼 뒤 로컬도 다르게) | 창 뜸 | **창 뜸(정상 유지)** |

실제 앱 조작으로도 확인했다(아래 6절, 5개 앱): 실험 실행 중 탭 숨김 → 새로고침, 기록 직후 새로고침, 오프라인 뒤 복귀 — 모두 충돌 창 없음, 콘솔 오류 0.

## 3. 화면이 낮을 때(휴대폰 가로) 머리말이 화면을 거의 차지하던 문제

`style-common.css:106–122`에 `@media (max-height: 480px)` 규칙을 넣었다. 머리말 여백·글자, 단계 진행바(한 줄 유지, 높이 36px), 로그인 표시 줄(`.ss-who`, 버튼 30px), 아래 이동 막대를 함께 낮췄다. 차시 제목의 `small`(학년·단원)은 제목과 같은 줄에 붙여 한 줄을 줄였다.
`.ss-who`는 `persist.js`가 `<style>`로 넣으므로 `.ss-header .ss-who`처럼 앞을 붙여 우선순위를 이기게 했다.

| 화면 | 머리말 높이(고치기 전 → 뒤) |
|---|---|
| 812×375 (휴대폰 가로) | **165px(44%) → 116px(31%)** |
| 1024×768 · 768×1024 (태블릿) | 165px 그대로(규칙이 적용되지 않음 — 의도대로) |
| 375×812 (휴대폰 세로) | 248px 그대로(높이가 480px보다 커서 적용되지 않음) |

스크린숏: `scratchpad/shots/before2-sci-6-1-1-1-812x375-observe.png`(전), `after-sci-6-1-1-1-812x375-observe.png`(후).
**맞바꾼 것**: 낮은 화면에서만 단계 버튼이 48px → 36px, 로그아웃 버튼이 40px → 30px로 작아진다(터치 44px 권장보다 작다). 화면 높이가 375px일 때 본문을 쓰려면 피하기 어려웠다. 실제 태블릿(세로·가로)과 휴대폰 세로는 그대로다.

## 7. 확인하지 못한 것

* **실제 Supabase DB에서** 가짜 충돌이 사라지는지. 가짜 서버에서만 확인했다(실 DB 쓰기는 금지되어 있다).
* 실제 iPad·휴대폰 터치, 실제 GPU에서의 3D. headless Chrome(SwiftShader)로만 확인했다.
* 수치 입력형 실험(`sci-6-1-2-5`, `sci-6-2-1-2`의 측정값 입력)은 사람이 화면을 읽어야 해서 기록 단계까지 자동으로 진행하지 못했다. 로그인·복원·저장 키·콘솔 오류만 확인했다.
* `sci-6-2-2-3`은 '시간 바'를 끄는 앱 고유 조작이라 실험 실행을 자동으로 하지 못했다(가짜 충돌 재현 시험에는 이 앱을 썼다).
* 두 학생 계정을 번갈아 쓰는 흐름(주인 바뀜 삭제)은 이번 수정 범위 밖이라 다시 확인하지 않았다.

## 8. 남은 것(제안)

* `scripts/templates/science-guide/`(조사 도우미 틀)의 `persist.js`·`style-common.css`는 `science-sim`에서 복사한 것이라 **같은 문제(조사·머리말·여백)를 그대로 갖고 있다.** 이번 지침의 수정 범위가 `science-sim`과 그 사본이어서 건드리지 않았다. 조사용 앱 3개는 모두 "이전 기준·수정 금지"라 급하지 않지만, 다음에 조사 앱을 만들 때 같은 내용을 옮기는 것이 좋다.
