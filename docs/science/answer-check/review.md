### M1. 함수가 "로그인한 학생"인지 실제로 확인하지 않는다
Supabase의 **Verify JWT는 프로젝트 JWT 비밀키로 서명된 토큰이면 통과**시키는데, 각 앱 `config.js`에 공개로 들어 있는 **anon key 자체가 그런 토큰**이다. 즉 사이트를 연 사람이면 누구나 anon key만으로 `check-answer`를 부를 수 있고, 함수는 `Authorization` 헤더를 보지 않는다.
- 피해: 무료 등급 Gemini 하루 한도를 남이 소모할 수 있다(과금은 없음). 한도를 넘어도 설계대로 **차단이 풀릴 뿐 수업은 멈추지 않는다**. 응답이 고정 프롬프트의 200자 한국어 문구뿐이라 범용 AI 대리 호출로 쓰기도 어렵다.
- 권함(작은 수정): 함수 앞부분에서 `Authorization` 헤더의 JWT payload를 **검증 없이 읽어**(서명은 게이트웨이가 이미 봤다) `role === "authenticated"`이거나 `sub`가 있을 때만 진행하고, 아니면 `{ok:false, reason:"invalid"}`로 돌려보낸다. DB·service_role 없이 10줄 이내로 된다.
- 함께: `README.md`의 "로그인하지 않은 요청은 게이트웨이가 막습니다" 문장을 사실에 맞게 고치는 게 좋다(참고 I).

### L4. `verify_jwt` 설정이 저장소에 없다
`supabase/config.toml`이 없어 Verify JWT는 배포 명령·대시보드 설정에만 의존한다. README가 "`--no-verify-jwt`를 붙이지 말고 배포 뒤 확인"하라고 잘 적어 두었지만, `supabase/config.toml`에 `[functions.check-answer] verify_jwt = true`를 남겨 두면 실수로 꺼지는 일을 막을 수 있다.

### M2. 차단 카드가 떠 있는 동안 '다음 단계'가 아무 반응 없이 무시된다
차단 카드가 뜬 상태에서 학생이 **입력칸의 글을 고치고 '다음 단계 →'를 누르면 아무 일도 일어나지 않는다**(서버 호출 0, 메시지 없음, 카드 그대로). `stage-nav.js`의 `waiting` 때문에 `go()`가 조용히 `false`를 돌려주기 때문이다. 학생은 "버튼이 고장 났다"고 느낄 수 있다.
- 정리하기는 이 문제가 덜하다 — 제출 버튼이 **눈에 보이게 잠기기** 때문(`submit.disabled = true`).
- 권함: `showCard()`에서 입력칸(`o.focus`)의 `input` 이벤트를 듣고 카드를 `"again"`으로 닫아 주면, 글을 고치는 순간 카드가 사라지고 다음 누르기가 정상 재검사로 이어진다. (또는 카드가 떠 있는 동안 '다음 단계' 버튼을 시각적으로 잠그기.)

Build가 설계의 60%를 90%+길이 제한으로 좁힌 판단은 타당하다. 60%였다면 `산성화된 호수에 염기성 물질을 뿌리면 산성이 약해지기 때문입니다` 같은 **좋은 답이 막혔다**(재현 확인).

### L6. 짧은 답에서 '같은 글자 반복' 규칙이 셀 수 있다
`같은 글자 반복` 규칙은 공백 제외 4자 이상이고 글자 종류가 2가지 이하면 막는다. `길어길어`·`같다같다`·`네네네네` 같은 4자 답이 걸린다. 실제로는 **예상하기 `minLength`가 5 또는 10**이고 정리하기 `MIN`이 5여서 그 전에 걸러지므로, 23개 앱에서 이 경로로 새 오탐이 생길 여지는 사실상 없다(`sci-6-1-1-6`의 '조사 정리' 한 칸만 `minLength: 2`). 굳이 고친다면 이 규칙만 6자 이상으로 올리면 된다.

## 7. Edge Function 단위 점검(Node, 실제 호출 없음)

`typescript` 트랜스파일 + `Deno` 흉내로 순수 함수만 돌렸다. **50 passed / 0 failed.**

- `parseRequest` 18건: 정상 통과 / `appId` 경로 주입(`sci-6-1-2-3/../secret`) 거부 / 빈 `appId` / `stage` enum·줄바꿈 주입 거부 / 빈 답·타입 이상 거부 / `priorBlocks` 3·-1·1.5 거부, 2 통과 / 길이 자르기(답 500·질문 300·모범답안 600·힌트 300) / **줄바꿈 제거**
- `buildPrompt` 5건: 키 없음 / "block은 명백할 때만" 포함 / 학생 답이 한 줄로만 들어감 / predict는 "없음(예상하기 단계라 정답 없음)"
- `parseVerdict` 13건: ok는 메시지 비움 / 모르는 판정값·대문자·JSON 아님·빈 응답·`parts` 없음·`null`·안전필터(`blockReason`)·`verdict` 없음 → **전부 `null`(= 차단 안 함)** / 기본 문구 / 200자 제한 / 메시지 타입 이상
- `leaks` 6건: 모범 답안 그대로·12자 일부 → 차단, 무관 문구·`model` 없음 → 통과, **뜻만 바꿔 쓰면 통과(한계 L3 기록)**
- `clean` 3건, `geminiBody` 5건(enum 고정, `responseMimeType: application/json`, `temperature: 0`, `maxOutputTokens: 256`, 키 없음)

## 8. 완주 실측 (`sci-6-1-2-3`, 예상 → 실험 → 분석 → 정리 → 마치기)

정리하기에서 **차단 1회 → 되짚기 1회 → "그대로 제출"**로 마쳤을 때 저장된 결과:

```json
{ "stage": "conclude", "id": "conclusion", "label": "결론",
  "question": "내 실험 결과를 바탕으로, …", "kind": "text",
  "answer": "빨간 자동차가 더 멀리 갔으니까 더 빠르다고 생각해요",
  "submitted": true, "blockCount": 1, "nudged": true }
```
예상하기·기록·분석·궁금한 점 항목은 **예전과 완전히 동일**. 저장 키 `sci612sim3:v4` 그대로.

### L5. 호출 수는 설계 추정의 최대 2배
설계는 "학생당 2~3회, 반 50~75회"로 잡았지만, **구 기준 1학기 앱은 예상하기 2문항 + 정리하기 3문항(결론·발전 1·2)**이라 학생당 **최대 5회**, 25명이면 **125회/차시**가 된다(2학기 앱은 2회/50회). 하루 한도(RPD 500~1,500대) 안이지만, 하루에 여러 반이 같은 앱을 쓰면 한도에 닿을 수 있다. 닿아도 설계대로 차단이 풀릴 뿐이라 수업은 멈추지 않는다.

### 참고(I). 7분 기준에 주는 영향
검사 1회당 **정상 응답이면 1초 안팎, 최악(오프라인·시간 초과)이면 3.5초**가 더 걸린다(실측 3,533 ms). 2학기 앱은 제출이 2번이라 최악 7초, 구 기준 1학기 앱은 최대 5번이라 최악 17초가 늘 수 있다. 실제 수업 지연은 **실측하지 못했다**.

### 확인하지 못한 것
- **실제 Gemini 응답 품질** — 진짜 오탐·오차단 비율, 실제 판정 정확도, 실제 지연. 이번 시험은 전부 가짜 응답이다(지시대로 Google에 실제 호출을 하지 않았다). 키를 넣은 뒤 README 4절로 직접 확인해야 한다.
- **실제 Edge Function 실행** — 이 컴퓨터에 Deno가 없어 `Deno.serve` 핸들러 전체 흐름(CORS·상태 코드)은 코드 읽기로만 점검했다. 배포 뒤 Logs로 확인 필요.
- **Verify JWT의 실제 동작**(M1의 근거는 Supabase 게이트웨이의 알려진 동작과 함수 코드 읽기 — 실 프로젝트로 시험하지 않았다). 배포 뒤 "로그아웃 상태에서 anon key만으로 호출"을 한 번 해 보면 확실해진다.
- **실제 iPad 터치** — 버튼은 48px 이상이지만 실기기 확인 못 함.
- **실제 학생 소요 시간**(7분 기준에 미치는 영향)과 교실에서의 체감 좌절도.
- `npm run build` 재실행 — `src/`가 한 줄도 바뀌지 않았고(`git status src/` 0건) 바뀐 파일이 전부 `public/`·`scripts/`·`supabase/`라 영향이 없다고 보아 다시 돌리지 않았다(Build 단계에서 성공 확인됨).
- 두 학생 계정 전환·로그아웃 삭제 흐름 — 저장 구조를 바꾸지 않아 영향 없다고 보고 이번에 다시 보지 않았다.
