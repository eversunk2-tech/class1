git 명령·실 DB/Storage 쓰기·실제 Auth/Gemini 호출은 하지 않았다. 전용 포트(127.0.0.1:8891)에 내 스크래치 사본만 올려 내 탭에서 확인했고, `localStorage.clear()`는 쓰지 않았다(내 앱 키만 다뤘다). 서버는 끝내고 종료했다.

## 1. 무엇을 바꿨나

### (A) M1 — 체험 모드에서 좋은 답에도 되짚기 카드가 뜨던 문제

`answer-check.js`의 `verify()`는 서버(check-answer)에 물어본 결과가 없으면 `rethink`로 낮춰 카드를 한 번 띄운다. 그런데 체험 모드에서는 `ask()`가 **언제나** `null`이어서 좋은 답에도 카드가 떴다.

* 이제 서버에 묻는 단계(⑤) **앞에서** 체험 모드면 그대로 통과시킨다(`isTrial()` → `pass()`). 스피너("답을 다시 확인하고 있어요…")도 뜨지 않는다.
* **로컬 규칙(확실한 무의미)은 그대로 ①에서 돈다** — 체험 모드에서도 자모만·같은 글자 반복·숫자만·질문 그대로 복사·자판 뭉개기는 여전히 막는다.
* `ask()` 안의 체험 모드 검사도 보호용으로 남겼다(이제 그 지점까지 오지 않는다).

### (B) 마치기 조건

| 바꾼 것 | 어디 |
|---|---|
| '학습 마치기'를 누르면 `canFinish()` 뒤에 **정리하기 답 → 궁금한 점** 차례로 한 번 더 검사 | `lesson.js` `finish()` (클릭 처리를 `doFinish()`와 검사 단계로 나눔) |
| 정리하기 답 검사 등록(저장될 글 기준) | `conclude.js` → `AnswerCheck.registerFinish(root, fn)` |
| 마치기 검사 등록·실행, 느슨한 단계(`curiosity`), `settled()` | `answer-check.js` |
| '더 탐구하고 싶은 점' 필수 + 화면 문구 다듬기 + "제출" 안내 | `lesson.js` |
| `curiosity` 단계의 느슨한 기준(ok/block만) | `supabase/functions/check-answer/index.ts` |
| `.ss-submit-note`, `.ss-req-note` 스타일 | `style-common.css`(sim·guide 둘 다) |

세부 동작

1. **정리하기 답이 block이면 마칠 수 없다.**
   * 검사 대상은 **실제로 저장될 글**이다 — 실험 앱은 지금 칸에 있는 글(`st.text`), 조사 앱은 마지막으로 제출한 글(`st.sent`). 제출한 뒤 무의미한 글로 고쳐 놓고 마치는 구멍이 막혔다.
   * 카드는 **정리하기 화면**에서 보여 준다(`lesson.js`가 그 단계를 열어 주고, 통과하면 원래 단계로 되돌아온다). 5단계 앱(정리하기 ↔ 궁금한 점이 다른 화면)에서 실제로 확인했다.
   * `rethink`는 지금까지와 같다 — 질문당 한 번 권하고 "그대로 제출할게요"로 마칠 수 있다.
   * 같은 질문에서 **3번째 block부터 "🙋 선생님과 확인했어요 · 계속하기"** 버튼이 나오고, 누르면 마칠 수 있다(기존 규칙 그대로).
   * 결론이 최소 글자 수보다 짧아졌으면 카드 대신 "결론을 N글자 이상 적고 '고친 내용 다시 제출하기'를 눌러 주세요."라고 알린다.
   * **헛걸음 방지**: 이미 통과한 글·되짚어 준 글·선생님 확인을 받은 글이면 화면을 옮기지도, 서버를 부르지도 않는다(`AnswerCheck.settled()`).
2. **'더 탐구하고 싶은 점'은 필수.**
   * 비워 두면 "'더 탐구하고 싶은 점'을 한 줄이라도 적어야 마칠 수 있어요."라고 알리고 그 칸으로 보낸다.
   * 검사는 **느슨하게**(`stage: "curiosity"`): 로컬 규칙의 확실한 무의미와 **서버가 block이라고 한 경우만** 막는다. 서버가 `rethink`를 골라도 통과시키고, 서버를 못 쓰면(체험·오프라인·한도·오류·시간 초과) 그냥 통과시킨다. **내용이 아쉽다는 이유로는 절대 되짚지 않는다.**
   * 앱 파일(`app.js`·`data/lesson-config.js`)은 건드리지 않았다. 대신 `lesson.js`가 화면에 보이는 문구만 다듬는다: 배지 `선택` → `궁금한 점`, 라벨의 `(비워 두어도 마칠 수 있어요)`·`(선택)`·`(안 적어도 괜찮아요)` 제거, 그 아래 "한 줄이라도 적어야 '학습 마치기'를 할 수 있어요." 한 줄 추가.
   * **`detail.qa`의 궁금한 점 항목은 그대로다** — `label`("궁금한 점(선택)" 등)과 `question`(옛 문구 포함)을 바꾸지 않았다. 그래서 `src/data/app-responses/*`도 고칠 필요가 없다(확인함).
3. **"제출" 안내.**
   * '학습 마치기' 버튼 **바로 위**에 늘 보이는 카드: `제출` 꼬리표 + "'🎉 학습 마치기'를 눌러야 선생님에게 제출돼요."
   * 마친 뒤: `제출 완료` + "✅ 선생님에게 제출했어요…"(초록), 저장되지 않았으면 `제출 안 됨` + "⚠️ 아직 선생님에게 제출되지 않았어요…"(빨강). **색만이 아니라 꼬리표 글자로 구분**된다. 새로고침해도 상태가 복원된다(`meta.savedAt` 기준).

### (C) Edge Function `check-answer`

* `stage`에 `"curiosity"`를 추가(`STAGES`), 느슨한 단계 목록 `LENIENT_STAGES`.
* 느슨한 단계 전용 프롬프트(`buildLenientPrompt`): **"이 질문에는 정답이 없습니다. 내용이 맞는지 틀린지, 깊이가 있는지 없는지는 절대 따지지 마세요."** 를 명시하고 ok/block 두 가지만 고르게 한다(예시 포함).
* `geminiBody(prompt, verdicts)` — 느슨한 단계는 응답 스키마 `enum`이 `["ok","block"]`이라 모델이 rethink를 낼 수 없다. 그래도 rethink가 오면 `parseVerdict`에서 **ok로 본다**(막지 않는다).
* 로그 한 줄·개인정보 비수집·키 처리 등 나머지는 그대로다.

## 3. 사용자가 할 일

1. **`check-answer` Edge Function을 (다시) 배포해야 한다.** 아직 한 번도 배포하지 않았다면 이번에 처음 배포하면 된다.
   ```bash
   npx supabase functions deploy check-answer     # Verify JWT 켠 채로(--no-verify-jwt 붙이지 않기)
   ```
   배포하지 않아도 **학생이 막히지는 않는다** — 궁금한 점은 `400 invalid`가 되어 앱이 서버 판정 없이 통과시키고, 정리하기는 지금과 같이 동작한다. 다만 "완전히 딴 이야기"를 걸러 내지 못한다.
2. 배포 뒤 앱을 열어 궁금한 점에 평범한 한 줄을 적고 마쳐 보며, 대시보드 **Edge Functions → Logs**에 `{"appId":…,"stage":"curiosity","verdict":"ok",…}` 줄이 찍히는지 확인하면 좋다.
3. SQL 변경은 없다. 배포 순서 제약도 없다(정적 사이트 먼저 올려도 안전).

## 4. 확인하지 못한 것

* **실제 Gemini 판정** — 호출하지 않았다. 느슨한 프롬프트가 실제로 "집에 가고 싶다"만 block으로 고르는지는 수업 전에 몇 줄 넣어 보며 확인하는 것이 좋다.
* **실제 로그인·저장** — 가짜 세션/가짜 응답으로만 시험했다. `app_results` 실제 행 모양은 확인하지 못했다(코드상 인자는 그대로).
* **실제 iPad 터치** — 데스크톱 브라우저의 375px·768px 에뮬레이션으로만 봤다.
* **7분 기준** — 마치기 검사가 늘어나 최악의 경우 서버 대기가 두 번(정리하기 3.5초 + 궁금한 점 3.5초) 생길 수 있다. 다만 정리하기 답은 제출할 때 이미 검사해 두므로 보통은 궁금한 점 한 번(≤3.5초)만 기다린다. 대기 한도 값(`TIMEOUT_MS = 3500`)은 바꾸지 않았다.
* 나머지 18개 앱은 열어 보지 않았다(정본과 `diff -r`로 같음만 확인).
* 스크래치 사본은 삭제 권한이 없어 세션 스크래치 폴더(`…/scratchpad/fgate`)에 남아 있다. 저장소에는 영향이 없다.
