# 구현하면서 더한 문장 — 사용자 확인용 (2026-10-20)

> 처리방침 원문(`privacy-policy.md`)에는 없지만 화면이나 서버 안내로 보일 수 있는 문장을 구현 담당 보고서에서 **글자 그대로** 모았습니다. 대부분 **오류가 났을 때만** 보입니다. 원문 문장(사용자가 승인한 글)은 여기 없습니다.
> **사용자 승인(2026-10-20): "모두 그대로 쓰기"** — 나중에 고칠 문장이 보이면 그때 고친다. 같은 날 정한 것: 로그인 화면의 "계정은 관리자가 미리 발급합니다. 별도의 회원가입은 없습니다." → "학생 계정은 담임 선생님이 미리 만들어 줍니다.", 프로필 수정 창의 칸 이름 '이름' → '별명'(사진 주소 칸은 없앰), 처리방침의 '[내 정보]' → '[프로필 수정]'.

## 1. 로그인·확인 창·처리방침 화면 (모든 사람 — 묶음 3)

(모두 `src/lib/privacy.ts`의 `PRIVACY_EXTRA_TEXT` 한곳에 있다. ★ = 이번에 새로 쓴 문장)
1. `구글로 처음 오신 선생님은 교사 인증 코드가 필요해요.` — 로그인 화면 구글 단추 아래(spec 3.2의 문장, md에는 없음)
2. `개인정보 처리방침` · `친구들을 위한 쉬운 설명` — 바닥·로그인 화면 링크 이름(5·6절 제목에서)
3. `개인정보 처리방침을 준비하고 있어요` — 시행 전 `/privacy/`(md 5절 메모·9절 규칙)
4. `문의 이메일을 불러오지 못했어요.` · `다시 불러오기` — 문의 이메일이 없을 때(9절 규칙)
5. ★ `개인정보 처리방침을 불러오지 못했어요.` — `/privacy/`가 설정을 아예 읽지 못했을 때(+ [다시 불러오기])
6. ★ `개인정보 처리방침이 바뀌었어요. 화면을 새로 고쳐 주세요.` — 인증·확인 RPC가 `policy_changed`일 때(3-2 제목 + 4절 문장을 이음)
7. `구글 계정으로 로그인 중이에요.` — 프로필 수정 창(spec 4.4)
8. `회원` — 로그아웃 방문자에게 보이는 글쓴이(spec 4.10)
9. ★ `탈퇴했어요. 계정을 지웠어요.` — 회원 탈퇴를 마친 뒤 알림(4-1의 "가입하지 않았어요. 계정을 지웠어요."와 같은 모양)
10. `가입하지 않았어요. 계정을 지웠어요.` — [가입하지 않기] 뒤 알림. 원문 4-1절 끝의 `>` 메모 줄("지운 뒤 알림")에서 가져옴.

그 밖에 알아 둘 것
- 4절 `코드가 맞지 않아요. 다시 확인해 주세요. (남은 시도: {n}번)`는 서버가 남은 횟수를 주지 않으면 괄호 부분을 빼고 보인다(SQL ①은 늘 줌).
- 4절 `개인정보 안내를 읽고 확인해야 시작할 수 있어요.`는 다른 칸이 다 찼는데 체크만 안 했을 때 단추 아래 도움말로 보이고, 3-1·3-2(확인만 하는 창)에서도 같은 문장을 쓴다("시작할 수"가 어색하면 사용자 결정).
- 사용자 메뉴 항목 이름 `회원 탈퇴`는 8-6 제목. 창 닫기 단추의 화면 낭독용 "Close"는 기존 공용 Dialog 컴포넌트 그대로.
- 탈퇴·[가입하지 않기]가 서버에서 거부되면 Edge Function(묶음 2)이 보낸 한국어 `error` 문장을 그대로 보인다. 서버 연결 실패·알 수 없는 결과는 4절 `서버에 연결하지 못했어요. 잠시 뒤에 다시 해 주세요.`

표기 처리: 원문의 `**굵게**`는 굵게, `{자리}`는 채움, 문장 속 `[단추 이름]`은 그 단추가 그 자리에 없을 때 대괄호째 보인다("다시 [학급 정리하기]를 눌러 주세요."). 회원 추가 도움말의 [보호자 동의서 양식 내려받기(한글 파일)]만 그 자리의 링크라 대괄호 없이 링크로 그린다. 확인 창 문장을 감싼 원문의 따옴표·굵게는 문서 표기라 빼고 보통 글로 보인다. `{새 가입 / 이전 가입}` 자리는 상수에서 `{가입 종류}`로 이름만 바꿨다(채우는 값은 원문 두 낱말).

## 4. 관리자 화면에 그대로 보이는 DB 오류 (묶음 1)

원문(4절·8-7절) 그대로인 것: `숫자 6자리로 적어 주세요.` · `이메일 주소 모양이 아니에요.` · `별명을 적어 주세요.` · `별명은 2자 이상 20자 이하로 적어 주세요.` · `별명에는 이메일·인터넷 주소·줄바꿈을 쓸 수 없어요.` · `이 이름은 쓸 수 없어요. 다른 별명을 적어 주세요.`
기존 SQL 과 같은 문장: `관리자만 사용할 수 있습니다.` · `대상 회원을 찾을 수 없습니다.`
**새 문장**(관리자 화면이 오류를 그대로 보일 때만 보임):
- `총괄 관리자만 사용할 수 있습니다.`
- `잘못된 권한 범위입니다.`
- `자기 자신의 권한 범위는 바꿀 수 없습니다.`
- `교사 계정만 권한 범위를 바꿀 수 있습니다.`
- `총괄 관리자의 권한은 줄일 수 없습니다.`
- `이 학급의 담임 선생님(또는 총괄)만 볼 수 있습니다.`
- `학급을 찾을 수 없습니다.`
- `대상 학생을 찾을 수 없습니다.`
- `이 학생의 담임 선생님만 기록할 수 있습니다.`
- `탈퇴 처리된 학생은 기록할 수 없습니다.`
- `회원 명단에서 이 학생을 찾을 수 없습니다.`
- `이 학급의 담임 선생님만 기록할 수 있습니다.`
서비스 롤 함수의 영어 짧은 문구(`missing arguments`, `blocked` 등)는 Edge Function 이 한국어로 바꾼다(⑦과 같은 방식). 새 프로필 이름 값 `인증 전 회원`은 spec 3.2·4.4 의 값 그대로다.

## 5. 학생 아이디·별명 가리기 (묶음 5·6)

사용자 화면에 나올 수 있는 것: **`다른 학급 학생은 교사로 지정할 수 없어요.`**(spec 4.11 그대로 — `admin_set_role` 오류, 화면이 서버 문구를 그대로 보임). Edge Function은 새 문장 없음(가린 이름이 틀려도 기존 "이름이 맞지 않습니다. 학생 이름을 그대로 입력해 주세요.").

SQL Editor에서 사용자가 보는 것(새로 쓰거나 바꾼 것 — `%`는 값):
- ① `가린 글자 규칙(mask_label · privacy_name_source) 자체 시험이 설계와 다릅니다: %. 이 파일 전체를 되돌렸습니다 — 이 메시지를 알려 주세요.`
- ① `학급 정리 기한 날짜 계산(privacy_retention_window) 자체 시험이 설계와 다릅니다: %. 이 파일 전체를 되돌렸습니다 — 이 메시지를 알려 주세요.`
- ② `회원 명단 · 감사 기록의 읽기 정책이 설계(개정 4 — "…: 학생은 담임만 조회" 하나)와 다릅니다: %. 이 파일 전체를 되돌렸습니다 — 이 메시지를 알려 주세요.`
- ② `회원 명단 · 감사 기록에 옛 정책(can_manage_member · is_admin())이 남아 있습니다: %. 이 파일 전체를 되돌렸습니다 — 이 메시지를 알려 주세요.`
- ② 끝 알림에 더한 문장: `회원 명단·감사 기록의 학생 줄은 그 학생의 담임만 읽습니다(총괄은 다른 학급 학생을 첫 글자 + ***로 — 개정 4).`
- ③ 끝 알림 앞부분: `✔ ③ 프로필(이름·사진)은 이제 로그인한 회원만 읽습니다(학생 이름은 같은 학급·담임만 — 그 밖에는 첫 글자 + *** 로, 인증 전 구글 계정은 자기 것만, 비로그인 화면의 작성자는 "회원").`
- ② 되돌리기 `회원 명단 · 감사 기록의 읽기 정책이 옛 정의("…: 담임·총괄 조회" 하나)로 돌아가지 않은 표가 %개 있습니다. 이 파일 전체를 되돌렸습니다 — 이 메시지를 알려 주세요.` · 끝 알림 `✔ ②를 되돌렸습니다: 인증 전 계정 제한 · 학급 밖 권한 좁히기 · 학생 아이디 가리기(개정 4)가 풀리고(교사 누구나 · 총괄은 모든 회원 명단), 구글 새 가입은 ② 이전처럼 일반 회원으로 시작합니다. 가린 이메일·이름은 되돌리지 않았습니다. 인증을 마친 구글 선생님은 교사로 남습니다.`
- `test-queries.sql` 23): `✖ 총괄 흉내가 되지 않았습니다(지금 역할 %) — 통째로 Run 해 주세요(아무것도 바뀌지 않음).` · `✖ <학생C id> 는 총괄이 담임인 학생입니다 — 다른 학급 학생 id 로 바꿔 주세요(아무것도 바뀌지 않음).` · `% 다른 학급 학생 교사 지정: % — 시험이라 일부러 오류로 끝냅니다(아무것도 바뀌지 않음).`
