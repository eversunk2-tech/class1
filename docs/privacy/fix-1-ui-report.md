## 3. 새로 생긴·바뀐 화면 문장(글자 그대로)

- 프로필 수정 창 설명: **"댓글과 메뉴에 표시되는 별명입니다."** — 예전 "댓글과 메뉴에 표시되는 이름과 사진입니다."를 바꿨다. 사진 칸이 없어져 맞춘 것이라 원문에 없는 새 문장이다.
- 로그인 화면: "학생 계정은 담임 선생님이 미리 만들어 줍니다." — 사용자가 정한 문장.
- 프로필 창 칸 이름·도움말·오류 문장은 모두 원문이다(1·2·3-1절 칸 이름, 4절 별명 오류 4개).
- 없어진 문장: "이름을 입력하세요.", "이름은 50자 이하로 입력하세요.", "http:// 또는 https://로 시작하는 이미지 주소를 입력하세요.", "비워 두면 이름의 첫 글자가 표시됩니다.", 칸 이름 "프로필 사진 URL (선택)".
- 칭찬 문구 빈 목록은 기존 문장의 첫 문장만 보인다(새 글 없음).

## 5. 알릴 것·확인하지 못한 것

- 별명 규칙은 화면에서만 지킨다. 서버의 별명 검사 트리거(검토 R1 L13)는 사용자 결정을 기다리는 중이다. 지금 별명이 규칙에 맞지 않는 회원은 프로필 창에서 저장하려면 별명을 고쳐야 한다(한 글자 이름, `@`가 든 이름 등).
- `docs/privacy/review-ui.md`·`fix-1-ui-instructions.md`에도 `000000`이 인용으로 남아 있다(이번 범위 밖 문서 — 커밋 전에 메인 에이전트 판단).
- 실제 Supabase(SQL ② 뒤 `avatar_url` 수정 권한 거부와 실제 저장)는 확인하지 못했다. 실제 iPad Safari의 겹친 창 막·화면 키보드도 확인하지 못했다. 모두 가짜 응답과 headless로만 봤다.
