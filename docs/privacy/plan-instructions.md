## 0. 절대 원칙
- **교사 인증 코드의 실제 값은 어디에도 적지 않는다**(저장소가 공개다). 문서·예시·시험 값은 `000000`. 사용자가 채팅으로 알려 준 값은 이 지침에도 없다.
- 문의 이메일도 적지 않는다(총괄이 관리자 화면에서 넣고, 처리방침 화면이 서버에서 받아 보여 준다 — 자리표시 `{문의 이메일}`).
- 보안은 RLS·서버 함수로 보장한다(화면 가드는 안내용). 인증 전 구글 계정이 화면을 우회해 API로 쓰기를 해도 막혀야 한다.
- 처리방침에는 **사실만** 적는다. 코드·SQL·함수와 대조해서 쓰고, 불리한 사실(학생 답이 Gemini 무료 등급으로 가서 구글이 개선에 쓸 수 있음, 로그인 서비스에 구글 이메일이 남음, 게시글에 별명이 공개됨 등)도 사실대로. 확인하지 못한 것은 "확인 필요"로 표시하고 단정하지 않는다.
- 법에 관한 말은 공식 자료(국가법령정보센터 law.go.kr, 개인정보보호위원회 pipc.go.kr의 「개인정보 처리방침 작성지침」·「아동·청소년 개인정보 보호 가이드라인」 등)를 찾아 **출처와 날짜**를 적는다. "법적으로 문제없다"고 단정하지 않는다. law.go.kr이 열리지 않으면 그 사실과 대신 본 자료를 적는다.
- 아무것도 내려받거나 설치하지 않는다. git commit/push·실 DB 쓰기를 하지 않는다. 웹 문서 읽기(WebFetch/WebSearch)는 된다.

- 탈퇴: 아이디 계정은 `admin-delete-member` — auth 계정 삭제, 학습 기록은 "탈퇴한 학생"으로 **기한 없이** 남음. 구글 전용 계정은 `admin-purge-oauth-member` + SQL `admin_purge_oauth_member`(`20260928000000_oauth_purge.sql`) — 총괄만, 완전 삭제.
- 데이터 위치: Supabase 프로젝트 지역 **ap-northeast-2(서울)**(로컬 `supabase/.temp/pooler-url`로 확인). 사이트 전송: GitHub Pages(GitHub) + Vercel. 학생 답 판정: Edge Function `check-answer` → Google Gemini **무료 등급**(보내는 것: 답 글·질문·모범 답안, 이름·학번·id·이메일은 안 보냄 — 함수 코드로 확인할 것). 과학 앱 본문 글꼴은 jsDelivr CDN(`persist.js`), 사이트 글꼴은 자체 호스팅(`next/font`는 빌드 때 받음 — 확인할 것).
- 체험 모드(비로그인): 이 기기 브라우저에만 저장, 답 판정은 공개 키로 `check-answer`.
- 브라우저 저장: 로그인 세션, 과학 앱 `sci6…` 사본(로그아웃 때 삭제), 화면 설정 `ssUiPref:*`, 테마·사이드바.

## 2. 사용자 결정(2026-10-20 — 바꾸지 말 것)
1. **교사 인증 코드**(6자리, 값은 채팅으로만): 구글로 가입하는 선생님은 구글 계정을 고른 뒤 **개인정보 확인 창 + 교사 인증 코드**를 넣어야 가입된다. 학생 임의 가입은 불가.
2. **기존 구글 회원**: 사이트에 새로 들어오거나 새로 고칠 때마다(인증할 때까지) 같은 창이 뜬다. 당황하지 않게 **"인디스쿨의 게시글을 다시 확인하거나 메시지를 주세요"** 안내를 넣는다. '나중에 할게요'는 로그아웃만(계정은 남김, 다음 접속 때 다시). 기한을 두고 지우지 않는다.
3. **구글 계정에만** 확인 창과 코드. 관리자가 만든 아이디 계정(학생·교사)은 코드 없이 로그인. 총괄이 교사로 지정한 계정(role admin)도 코드 없이(Claude 판단 — 총괄 자신이 막히지 않게; 계획에서 위험을 적을 것).
4. **학생 확인 창은 만들지 않는다**(Claude 판단, 사용자 "법적으로 필요 없으면 만들지 말라"): 만 14세 미만은 보호자(법정대리인) 동의가 근거(개인정보 보호법 제22조의2 ①), 학생 클릭은 효력이 없음. 같은 조 ③(아동에게 알릴 때 쉬운 말) → 처리방침에 **학생용 쉬운 설명 절**, 사이트 바닥·로그인 화면에 처리방침 링크. 이 판단의 근거를 spec에 출처와 함께 적는다.
5. **보호자 동의 원칙**: 교사가 학생 계정을 만들 때 보호자 동의를 반드시 받는다(종이 동의서, 담임 보관). **동의서 양식(hwpx)**을 교사 대시보드에서만 내려받게(양식 파일은 Claude가 hwpx 스킬로 만든다 — 계획은 문안만). 회원 추가(한 명·엑셀)에서 학생 역할이면 **필수 체크 "보호자 동의서를 받았습니다(담임 보관)" + 누가 언제 체크했는지 `member_create_log`에 기록**(`admin-create-member` 수정 → 사용자 재배포).
6. **인증한 구글 선생님은 바로 교사 권한(role admin)** — 학급 개설·학생 계정·과제·선생님 글·자기 게시판·피드백. **단 "자기 학급 일만"**: 학습게임 전체 관리·신고 처리·블로그 글쓰기·함께 쓰는 칭찬 문구 고치기는 못 한다(총괄과 총괄이 만든 교사만). **총괄이 나중에 넓혀 줄 수 있다**(회원 관리에서).
7. **인증 안 한 새 구글 계정**: 창에서 '가입하지 않기' → 그 자리에서 계정을 **완전 삭제**(새 Edge Function — 본인 것만, 인증 전·구글 전용·role user·학급 없음·기존 회원 아님일 때만) 후 로그아웃. 창만 닫고 떠난 계정은 회원 관리에 **'인증 전'** 표시 → 총괄이 기존 '완전 삭제'로 지운다.
8. **문의 연락처**: 이메일, 총괄이 관리자 화면에서 넣는다(공개 읽기 — `site_settings`에 열을 더하거나 새 표), 처리방침 화면이 받아 보여 준다. 운영자 표시 이름은 사이트 바닥 문구와 같은 `PSC`.
9. **보관 기간 — 학년도 끝나면 지우기**: 담임(자기 학급)·총괄 화면에 **'학급 정리'**(그 학급 학생 계정과 학습 기록을 한꺼번에 완전 삭제, 강한 확인). 처리방침: 학생 계정·학습 기록은 학년도가 끝난 뒤 **다음 해 3월 31일까지** 지운다, 탈퇴한 학생의 기록도 이때 함께. (자동 삭제가 아니라 담임/총괄이 실행 — 사실대로 적는다. 늦어질 때 총괄이 볼 수 있는 표시가 필요한지 계획에서 제안.)
10. **구글 선생님 이름·사진**: 인증 창에서 **별명**(게시글에 보일 이름)을 정하고, 구글 프로필 사진은 저장하지 않는다(avatar_url 비움). 기존 구글 회원도 인증할 때.
11. **구글 선생님 스스로 탈퇴**: '내 정보'에서 회원 탈퇴 → 계정과 그 선생님의 글·기록 완전 삭제. **맡은 학급에 학생이 남아 있으면 막고** '학급 정리'를 먼저 하라고 안내.
12. **구글 아이디(이메일) 가리기**(사용자가 selectio-game처럼 원함): 사이트가 쓰는 표(member_directory·profiles 등)와 모든 화면(총괄 관리자 화면 포함)에 이메일 대신 **첫 글자 + `***`**(예 `k***`)와 별명만. 처리방침에는 사실대로: "사이트의 어느 화면에서도 운영자는 구글 이메일·이름을 볼 수 없다. 다만 구글 로그인을 처리하는 Supabase의 로그인 기록(서버 관리 화면)에는 로그인에 필요해 이메일·이름·사진 주소가 남는다" — 정확한 사실(무엇이, 어디에, 로그인할 때마다 다시 채워지는지)을 Supabase 문서·코드로 확인해 쓴다. 비밀번호: 구글 선생님은 이 사이트에 비밀번호가 없음(구글이 확인), 아이디 계정은 Supabase가 일방향 암호화.
13. **교사 인증 코드 관리**: 총괄이 관리자 화면에서 넣고 바꾼다(처음 값도 SQL 실행 뒤 총괄이 화면에서 — SQL 파일에 값 없음). 서버에는 되돌릴 수 없는 값(예: pgcrypto bcrypt)으로만, 틀린 시도 횟수 제한(계정당 — 계획에서 수치 제안).

## 3. spec.md에 쓸 것
1. 결정 요약(위 2절)과 법적 근거(출처·날짜).
2. **흐름**: 새 구글 가입(창 → 별명·확인 체크·코드 → 성공이면 교사 권한), 기존 구글 회원(같은 창 + 인디스쿨 안내 + 나중에), 가입하지 않기(완전 삭제), 창 닫고 떠남, 새로 고침, 다른 탭, 과학 앱을 바로 연 경우(공통 틀 `class1-record.js`가 인증 전 계정을 어떻게 다룰지 — 23개 사본 영향 포함), 로그인 잠금 스위치(`can_browse()`)와의 관계(인증 전 계정은 비로그인처럼).
3. **DB 설계**: 새 SQL 파일 하나(이름 제안), 표·열·함수·정책 전부. 인증 상태 판별 함수, 기존 회원/새 가입 구분(SQL 실행 시각 등), 코드 저장·검증·횟수 제한, 인증 RPC(성공 시 role admin + "자기 학급 일만" 표시 + 별명 + 사진 비우기 + member_directory 이메일 가리기 + 처리방침 판 번호·확인 시각), "자기 학급 일만" 판별(새 열 또는 표)과 그것으로 좁힐 **정책·함수 전부의 표**, 인증 전 구글 계정의 쓰기를 막는 방법(RESTRICTIVE 정책 등 — 표 목록), 문의 이메일·코드 관리 RPC(총괄만), 학급 정리 RPC(담임 자기 학급·총괄), 보호자 동의 기록 열(`member_create_log`), `sync_member_directory`가 구글 계정 이메일을 다시 채우지 않게. 실행 전·후 확인 쿼리.

7. **시험 계획**(가짜 세션·headless, 실제 Supabase 막기, 코드 `000000`), Review에서 볼 것.
