# 고침 2 지침 — SQL·함수 (검토 R1 재확인 N1·N3, 2026-10-21)

담당: 묶음 5 구현 담당(E). 규칙은 `build-common.md`·`build-5`·`fix-1` 지침 그대로(같은 파일 수정, 커밋·실 DB·내려받기 금지, `src/`는 메인 에이전트가 고침). 기준: `docs/privacy/review-sql.md` 6절. 보고서: `docs/privacy/fix-2-sql-report.md`(짧게).

## 메인 에이전트가 정한 방향
아이디 계정 판정은 **도메인 규칙(`@class1.local`) 하나로 둔다**(고침 1 그대로). 대신 이메일 모양 아이디를 **새로 만들지 못하게** 막고, 이미 있는 이메일 모양 아이디 계정은 **② 맨 앞 점검에서 멈춰** 사용자가 알리게 한다(있으면 그때 따로 고친다 — 아마 0개).

## 고칠 것
1. **N1 — 새 이메일 모양 아이디 막기**: `supabase/functions/admin-create-member/index.ts`에서 `@`가 들어간 아이디를 받지 않는다(이메일 갈래를 없애 기존 문구 "아이디에는 영문 소문자·숫자와 . _ - 만 쓸 수 있습니다(한글·공백 불가)."로 떨어지게 — 새 문장 없이). `scripts/import-users.mjs`(예비 스크립트)도 같은 규칙. 화면(`src/lib/member-import.ts`)은 메인이 이미 고침. README·주석의 "이메일 형식도 가능" 설명을 고친다.
2. **N1 — 이미 있는 이메일 모양 계정 점검**: ② 맨 앞 점검에, **`@class1.local`로 끝나지 않는데 이메일·비밀번호 로그인(provider/providers/identities에 `email`)이 있는 계정**이 하나라도 있으면 아무것도 바꾸지 않고 멈추는 점검을 더한다. 문구 예: "이메일 모양 아이디(또는 이메일로 스스로 가입한) 계정이 %개 있어 멈췄습니다. 이대로 ②를 실행하면 이 계정이 구글처럼 '인증 전'으로 묶여 기록 저장이 막힙니다. 이 메시지를 알려 주세요(아무것도 바뀌지 않았습니다)." ② 머리말의 "실행 전 확인"과 `test-queries.sql`에 같은 개수를 세는 읽기 쿼리(결과는 개수만)를 둔다.
3. **N3 — `선생님` 덮어쓰기**: ② 백필에서 이름을 `선생님`으로 바꾸는 조건에 "지금 이름이 구글이 준 이름(`raw_user_meta_data`의 `full_name`/`name`)과 같거나 비었을 때만"을 더해, 다시 실행해도 관리자가 고친 별명을 덮어쓰지 않게. 그리고 별명 예약어(SQL ①의 `privacy_nickname_error()` 목록)에 **`선생님`**을 더한다(화면 `RESERVED_NICKNAMES`에는 메인이 이미 더함 — 두 목록이 같은지 보고서에).
4. **N2**는 그대로 둔다(보고서에 한 줄).

## 시험
읽어서 대조, 고침 1의 자체 시험(가린 글자·날짜)이 그대로인지, `admin-create-member` 아이디 검사 경우(숫자·영문·`@` 거부), 스크립트 구문 검사(`node --check`). 끝나면 짧게 요약(새 문장은 글자 그대로).
