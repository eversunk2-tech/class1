# Plan 서브에이전트 지침: 프론트엔드 디자인 개편 (초등 6학년 대상)

## 목표
블로그 본체(Next.js)의 디자인 개편 계획을 세워 `docs/design/spec.md`에 작성한다. **구현하지 않는다.**

## 수정 범위
* 작성 가능: `docs/design/spec.md` 하나만.
* 그 외 모든 파일은 읽기만 한다.

## 사용자 요청 (원문 요약)
* 초등학교 6학년 학생 대상 사이트. 전체적으로 **깔끔하고 귀여운** 느낌.
* 학교, 과학 수업, 수학 수업 이미지가 귀여운 느낌으로 쓰이게 디자인.
* 접속하면 **왼쪽에 접었다 펼 수 있는 메뉴**.
* 메인 화면은 전체 활동을 보여 주는 **대시보드 형태**.
* 메뉴는 우선 `홈`, `학습게임활동`, `과학수업`, `수학수업`. 이후 계속 추가·수정할 예정 → **메뉴 추가가 쉬운 구조**여야 한다.

## 먼저 읽을 것
* `CLAUDE.md`, `AGENTS.md` — 이 Next.js(16.x)는 학습 데이터와 다를 수 있다. `next/font`, `next/link`, `usePathname`, 정적 export 관련은 `node_modules/next/dist/docs/`에서 확인하고 근거를 spec에 적는다.
* `docs/blog/spec.md` (기존 화면 설계), `next.config.ts`
* `src/app/layout.tsx`, `src/app/page.tsx`, `src/app/globals.css`
* `src/components/site-header.tsx`, `site-footer.tsx`, `post-list.tsx`, `post-card.tsx`, `tag-chip.tsx`, `states.tsx`, `apps/app-grid.tsx`, `apps/app-card.tsx`, `user-menu.tsx`, `theme-toggle.tsx`
* `src/app/search/search-view.tsx` (태그 필터 쿼리 방식), `src/data/apps.ts`, `src/lib/types.ts`
* `supabase/migrations/*.sql` (읽기 가능한 테이블/RLS 확인용)

## 확정된 전제 (메인 에이전트가 정한 방향 — 더 나은 안이 있으면 "열린 질문"에 대안으로 적는다)
* 정적 export + basePath(`/class1`) 제약 유지. 서버 기능 금지. Supabase 호출은 Client Component에서만.
* **스키마 변경 없이** 진행한다. `과학수업`/`수학수업` 메뉴는 `posts.tags`에 `과학`/`수학` 태그가 있는 발행 글 목록으로 구현한다. `학습게임활동`은 `src/data/apps.ts`의 웹앱 카드 목록이다.
* 새 라우트: `/games/`, `/science/`, `/math/` (정적 페이지, 동적 세그먼트 금지). 수업 페이지는 태그만 다른 공통 컴포넌트로 만든다.
* 메뉴 정의는 한 파일(예: `src/data/menu.ts`)에 배열로 둔다: id, 이름, 경로, 아이콘, 색상 테마, 설명. 사이드바와 대시보드가 모두 이 배열을 쓴다.
* 사이드바:
  * 데스크톱(≥ md): 왼쪽 고정. 펼침(아이콘+글자) ↔ 접힘(아이콘만 레일) 토글. 상태는 localStorage에 저장하고 첫 페인트 깜빡임을 최소화한다.
  * 모바일: 기본 숨김, 상단 바의 햄버거 버튼으로 여는 오버레이 드로어. 메뉴 선택/바깥 클릭/ESC로 닫힘.
  * 현재 경로 강조(`usePathname`, basePath·trailing slash 처리 주의), 키보드 접근성, `aria-expanded` 등.
  * 검색, 테마 토글, 사용자 메뉴(로그인/관리자)는 상단 바에 유지한다.
* 이미지: 외부 이미지/저작권 있는 소재를 쓰지 않는다. **직접 그린 인라인 SVG 일러스트**(학교 건물, 플라스크·행성·돋보기 등 과학, 자·도형·계산기·숫자 등 수학, 게임 컨트롤러 등)를 React 컴포넌트로 만든다. 다크모드에서도 어울려야 한다. 이모지는 보조로만.
* 디자인 톤: 파스텔 계열 컬러 팔레트(메뉴별 포인트 색: 예 홈=하늘, 게임=분홍/보라, 과학=민트/초록, 수학=노랑/주황), 큰 둥근 모서리, 부드러운 그림자, 둥근 한글 글꼴(제목용). 본문 가독성과 명도 대비(WCAG AA)는 지킨다. 과한 애니메이션 금지, `prefers-reduced-motion` 존중.
* 글꼴: `next/font/google`에서 한글 지원 둥근 글꼴 후보(예: Jua, Gaegu, Gowun Dodum, Nunito 등)를 비교해 추천한다. 한글 글꼴의 subsets/preload 옵션 제약을 문서에서 확인한다.
* 대시보드(홈) 구성 후보:
  * 환영 히어로(학교 일러스트 + 인사말)
  * 통계 타일: 전체 글 수, 과학 글 수, 수학 글 수, 학습게임 수 (Supabase `count` 쿼리: `select('id', { count: 'exact', head: true })`)
  * 메뉴 바로가기 카드(각 메뉴의 일러스트+설명)
  * 최근 과학 수업 / 최근 수학 수업 (각 3개)
  * 학습게임 미리보기(앱 카드 일부)
  * 인기 글(조회수 상위) — `views` 테이블로 가능한지 검토
  * 각 영역의 로딩(스켈레톤)·빈·오류 상태. 글/앱이 0개여도 허전하지 않게 귀여운 빈 상태 일러스트.
* 기존 화면(글 상세, 검색, 로그인, 관리자)은 기능을 바꾸지 않고 새 레이아웃·테마 토큰 안에서 자연스럽게 보이도록만 조정한다. 본문 폭(가독성)은 유지한다.
* 사이트 이름/문구를 초등학생 눈높이의 친근한 한국어로 다듬는다(사이트 이름 후보 제안).

## spec.md에 담을 내용
1. 디자인 컨셉 요약 (톤, 팔레트 — 라이트/다크 토큰 값을 oklch로 구체적으로, 글꼴, 모서리/그림자 규칙)
2. 레이아웃 구조 (사이드바 + 상단 바 + 본문, 브레이크포인트별 동작, 간단한 ASCII 와이어프레임)
3. 메뉴 데이터 구조와 메뉴 추가 방법
4. 화면별 설계: 홈 대시보드, 학습게임활동, 과학수업, 수학수업 — 구성 요소, Supabase 쿼리, 로딩/빈/오류 상태
5. SVG 일러스트 목록 (이름, 쓰이는 곳, 대략적 묘사, 색상 토큰 사용 방식)
6. 파일 구조: 새로 만들 파일 / 수정할 파일 / 건드리지 않을 파일
7. 기존 화면에 미치는 영향과 조정 사항
8. 접근성·성능 체크리스트
9. 구현 단계 분할 (Build 서브에이전트 단위; 파일 충돌 없이 나눌 것)
10. 검증 방법 (`npm run lint`, `npm run build`, 브라우저 데스크톱/모바일/다크모드 확인 항목)
11. 사용자 결정이 필요한 열린 질문 (추천안 포함, 5개 이내)

간결하게, 표와 목록 위주로 작성한다.
