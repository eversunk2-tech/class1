* **hover 뜨는 효과**: 코드를 직접 읽어 원인·수정이 정확함을 확인했다(Tailwind v4는 `hover:-translate-y-0.5`를 `transform`이 아니라 `translate` 속성으로 옮기므로 `transition-[transform,…]`으로는 애니메이션이 안 걸린다 — `transition-[translate,…]`로 고친 것이 맞다). 실제 hover 궤적을 초 단위로 표본 추출하는 내 스크립트는 마우스 좌표가 카드에 정확히 안 맞아 판정을 얻지 못했다(코드 근거로는 확실, 실측 재확인은 못함).
* **375 터치 영역**: 32px짜리 항목 6개(머리말 메뉴·검색·다크모드·유저·"메인으로" 등)가 있었지만 전부 **전역 머리말/사이드바**(1·2단계 산출물) 요소였고 이번 커밋(`git diff 8eb7a94~1 8eb7a94 --stat`)은 `topbar.tsx`/`sidebar.tsx`를 건드리지 않았다 — 이번 3·4단계가 만든 것이 아니다.

### 3.4 정적 export·basePath

* `rm -rf` 없이(권한 정책상 파괴적 명령 금지) `npm run build`로 직접 새로 빌드(24쪽, 통과) → `out/`을 내 서버로 `/class1` 경로에 서빙.
* 전체 라우트(관리자 6개 포함 15개) 200. 23개 앱 × 7개 핵심 파일(`index.html`·`config.js`·`style.css`·`style-common.css`·`persist.js`·`lesson.js`·`answer-check.js`) = **161개 전부 200**. 없는 경로로 확인차 요청해 404가 제대로 나는 것도 확인(서버가 무조건 200을 주는 게 아님을 검증).

### 3.5 접근성

* 대비: 위에 적은 값들(과학 앱·관리자) 전부 화면에 실제로 그려진 색을 캔버스로 다시 읽어 계산한 값이라 AA 기준(4.5:1, 큰 글자 3:1) 위반 0건.
* `prefers-reduced-motion`: 과학 앱·관리자 카드 hover 모두 코드에 대응 규칙이 있음을 확인. §2 표의 스피너 건 1개만 예외(기존 문제).
* 44px 터치 영역: 과학 앱 CSS는 크기 값이 이번 커밋에서 전혀 안 바뀌었음을 diff로 확인(색만 바뀜) — 새로 생긴 미달 없음. 관리자·학생 공용 버튼은 shadcn 기본 크기(44px 이상) 그대로.
* 키보드 초점: 관리자 25탭 전수, 과학 앱 `:focus-visible` 규칙(보라, 대비 5.3:1 밝음/10.6:1 어두움) 코드 확인.

## 4. 확인한 것 vs 확인하지 못한 것

**확인한 것**
* 과학 앱 공통 틀 변경 범위(코드 diff), SRI 해시(직접 계산), 23개 앱=정본(diff -r), 23개 앱 콘솔 오류 없음(전수), 글꼴 CDN 막힘/지연 시 첫 화면 안 막힘(실측), 되짚기 카드 실동작(4/5 앱), 5개 필수 앱의 5가지 화면·다크모드·3D 렌더링(WebGL 켜서 확인), 관리자 전체 화면·위험 버튼 색·회원 표 ⋮·관리자 색 미누출(빌드+실행 이중 확인)·대비 다수·탈퇴 이름 표시·키보드 초점, 정적 export 161개 리소스 200.
* 위 숫자들은 전부 이 리뷰가 **직접** 계산·측정한 값이며, build-3·4 보고서 값과 대조해 일치함을 확인하는 방식으로 교차검증했다(보고서를 그대로 베껴 적지 않음).

**확인하지 못한 것**
* 실제 iPad/Android 태블릿·실제 터치(3D 드래그, 슬라이더, 두 손가락 확대) — 전부 headless Chrome 에뮬레이션.
* 실제 로그인·실 Supabase 응답(전부 가짜 세션·가짜 응답).
* `sci-6-1-1-6`(조사)의 되짚기 카드 최종 확인 — 자동화 중 저장 충돌 안내가 떠서 끝까지 못 갔다(§3.1 참고, 코드상 다른 4개 앱과 완전히 같은 `answer-check.js`를 쓰므로 위험도는 낮게 본다).
* 정리하기·완료 화면·`app_results` 최종 제출까지 가는 전체 흐름(이번 검증은 1~2단계 진입까지 — 시간 제약으로 완주는 못 함). 저장 키·`detail.qa` 모양은 관련 JS 파일이 이번 커밋에서 전혀 안 바뀌었다는 사실로 대신 확인했다.
* 관리자 hover 뜨는 효과의 실측 확인(코드로는 확인, 스크린 좌표 문제로 자동 측정은 실패).
* "학생 응답" 화면의 일괄 칭찬 보내기 실제 클릭 흐름(화면 진입·버튼 존재는 확인, 끝까지 눌러보지 않음).
* 차단(3번째부터 "선생님과 확인했어요") 카드는 이번에 직접 3연속 차단을 재현해 보지 않았다(되짚기 카드까지만 확인).
