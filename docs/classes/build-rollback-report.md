## 3. 빠진 것 없음 — ③ ↔ 되돌리기 짝
③을 문장 단위로 읽어 뽑은 목록: create policy 16 · drop policy 33 · 함수 8 · 함수 권한 14 · do 2 · update 1 · notify 1(표 권한 문장 없음).
* ③이 만든 정책 16개 → 되돌리기가 모두 drop(새 이름 15 + 같은 이름 1은 drop 뒤 옛 정의로 create).
* ③이 지운 drop 33개 = ③ 이전에 있던 옛 정책 16개(→ 모두 옛 정의로 create) + 새 이름 재실행용 15개 + 방어용 2개(③ 이전에도 없음 → 만들지 않음).
* 되돌리기의 create policy 16개 = ③이 지운 옛 정책 16개(더 만드는 것 없음). drop 31개는 모두 ③의 새 이름 또는 다시 만들 옛 이름.
* 함수 8개·권한 문장: 함수마다 옛 파일의 "마지막 정의 뒤 권한 문장" 목록이 되돌리기와 순서까지 같다(7개 × revoke·grant, `assignment_submission_guard`는 0개). ③의 권한 문장도 옛 것과 글자가 같다(③은 함수 권한을 바꾸지 않았다).
* 함수 머리(인자 이름·타입·반환형)가 ③과 8개 모두 같다 → `create or replace`가 거부되지 않는다.

**상태 흉내**(13개 파일 → ① → ③ → ④ → 되돌리기 순서로 정책 전체·함수 전체·함수 실행 권한을 모형으로 적용해 비교):
* ①②③④ → 되돌리기 = ①②④(③ 없음) — 목표 상태와 같음
* ①②③ → 되돌리기 = ①②(③ 이전)
* 되돌리기 두 번 = 한 번(재실행 안전) · ③ 전에 잘못 실행해도 바뀌는 것 없음
* 되돌린 뒤 ③ 다시 실행 = ①②③④(다시 좁히기 가능)

## 5. 실행 방법 요약(사용자)
1. 문제가 생기면 먼저 `select count(*) from public.profiles where role = 'user' and class_id is null;` — 0이 아니면 되돌리기보다 학급 지정이 먼저.
2. 되돌려야 하면: Supabase SQL Editor > New query에 `docs/classes/rollback-classes-rls.sql` 전체를 붙여넣고 Run(drop 확인 창이 뜨면 Run). 끝에 "✔ ③ 이전 상태로 되돌렸습니다" 알림이 나오면 성공, 오류면 아무것도 바뀌지 않았고 메시지를 Claude에게 전달.
3. 머리말 확인 쿼리 1)~5)로 확인(1은 16행, 2는 0행, 3은 8행 모두 옛_판단 true·학급_판단 false).
4. 되돌린 동안: 교사 누구나 전체 학생 기록을 볼 수 있다(③ 이전과 같음 — 지금 교사가 총괄 1명이면 달라 보이는 것이 거의 없음). **담임 지정·해제는 하지 않는다**(옛 `admin_set_role`은 학생 소속 비우기·빈 학급 보관·총괄 표시 끄기를 안 함). 회원 추가·초기화·탈퇴(Edge Function)는 ①의 표를 직접 읽어 학급 규칙 그대로다.
5. 원인을 고친 뒤 다시 좁히려면 ③ 파일 전체를 다시 Run.

## 6. 한계(확인하지 못한 것)
* 기준: ①·③·④는 커밋 `e7487ce` 판으로 대조했다. ③을 고치거나 ③ 앞에 들어가는 새 마이그레이션이 생기면 이 파일도 다시 대조해야 한다(스크래치 `verify.mjs`를 다시 돌리면 된다 — 저장소 밖이라 지워졌으면 다시 만들어야 함).
* 실제 Postgres에서 실행하지 않았다(로컬 DB 없음). 문장 나누기·모형 적용·글자 대조는 스크립트, 의미(이름 자르기 규칙, `create or replace` 조건, `::name` 비교, `to_regprocedure`)는 읽어서 검토했다.
* SQL Editor가 붙여 넣은 전체를 한 트랜잭션으로 돌린다는 가정은 ③·기존 파일과 같다(Review §7에도 미확인으로 적힘). 만약 문장마다 따로 적용되더라도 되돌리기 자체는 적용되고, 끝 점검 오류는 "무엇이 덜 됐는지"를 알려 준다.
* 모형은 저장소 파일 기준이다. 대시보드에서 직접 만든 정책·함수가 있다면 모른다(끝 점검 (3)은 11개 표에서 학급 판별을 쓰는 정책은 이름과 상관없이 잡는다).
* 끝 점검의 함수 확인은 본문 글자 검색(`is_admin()` 있음, 학급 판별 함수 없음)이다. 본문 전체가 옛 것과 같은지는 이 파일의 글자 대조(위 표)로 보장한다.
* 되돌린 동안 옛 함수·정책의 동작(교사 누구나 전체 보기, 잠금 스위치·담임 지정 RPC는 교사 누구나)은 ③ 이전 그대로라 새로 시험하지 않았다. 관리자 화면에서 학급으로 거르지 않는 목록(앱별 결과 등)과 개요 숫자는 전체 기준이 된다.
